# Организация репозитория

Читатель начинает с карточки источника, затем переходит к датированным обзорам и данным. Хронология работы чата не определяет структуру каталога.

Семантический контракт описан в [единой модели](data-model.md). Все 83 карточки нормализованы, legacy-список пуст. `catalog/entities.json` хранит явные связи; `structure.json` отвечает за физические пути и совместимость. `studies/` сохраняет исходную аналитику, `catalog/studies/` и `projects/` — генерируемые представления. Их не редактируют вручную.

| Каталог | Содержимое | Правило имени |
| --- | --- | --- |
| `studies/` | Одна карточка на источник | `<source>.md` |
| `reviews/` | Обзоры и проверки одного источника | `<source>/YYYY-MM-DD[-scope].md` |
| `portfolio/` | Сводки нескольких работ и project-fit | `<period>/review.md`, `project-fit.md` или предметное имя |
| `collections/` | Реестры подборок и их provenance | `<collection>/` |
| `data/results/` | Машинные результаты проверок | `<source>/YYYY-MM-DD[-scope].json` |
| `data/project-fit/` | Решения о применимости | `<source>/YYYY-MM-DD[-scope].json` |
| `experiments/` | Скрипты и fixtures | Новые: `<source>/<purpose>.<ext>` |
| `archive/dsh/` | Неизменяемые исторические копии | Исходные пути и байты |
| `catalog/` | Структура и соответствие адресов | `structure.json` |
| `scripts/` | Генерация навигации и проверки | Имя операции |
| `reports/` | Совместимость старых адресов | Генерируется; вручную не редактировать |

`source` — устойчивое имя: `hyra-2` или `vercel-agent-desktop`. Telegram BK остаётся идентификатором происхождения в реестре и тексте. Дата имени — дата записи; диапазон в `portfolio/` — период подборки, а не дата публикации paper.

Заголовок называет предмет: «REA — проверка PE layout». В нём нет запроса из чата, «нового follow-up» или объявления о завершённости всей проверки. Доказательный статус и ограничения указываются в тексте.

## История и совместимость

[Перенос 05.11.2026](migration.md) меняет расположение, заголовки и ссылки. Выводы, результаты, статусы и scope не пересматриваются. [Прежний индекс](history/2026-11-05-study-index.md) сохранён как исторический документ; его старые статусы не заменяют актуальные карточки. Прежние версии доступны в Git history.

Старые Markdown-адреса в `reports/` содержат переходы и anchors разделов. GitHub не выполняет автоматический redirect Markdown: читатель переходит по видимой ссылке. Старые JSON-адреса содержат генерируемую копию канонического JSON для машинного чтения. Это слой совместимости, а не второй редактируемый источник. Pinned ссылки на прежние коммиты остаются историческими снимками.

Архив DSH не перемещается и не форматируется; ограничения его относительных ссылок описаны в [manifest](../archive/dsh/ARCHIVE_MANIFEST.md). Экспериментальные скрипты при переносе документов не меняются и не запускаются.

## Добавление материала

1. Найти источник в [каталоге](../studies/INDEX.md), сверить URL/DOI и прочитать [протокол](../RESEARCH_POLICY.md).
2. Дополнить карточку. Новый вывод оформить датированной записью в `reviews/`; сводку — в `portfolio/`. Связать с предыдущими проверками.
3. Добавить путь в `catalog/structure.json`. Для нового материала без старого адреса указать `from: null`, `date: YYYY-MM-DD`; legacy-адрес не создавать.
4. Выполнить `node scripts/build-catalog.mjs`, затем `node scripts/check.mjs` и `git diff --check`.

Главная страница содержит устойчивые входы. Полные списки генерируются из каталога, а не дописываются вручную в нескольких местах. Генератор не определяет scientific status и не считает карточку подтверждением метода.
