# Единая модель — пилот v1

Миграция выполняется по [опубликованному сценарию](migration-runbook.md); состояние партий — в [журнале](migration-progress.md).

Модель отделяет источник, нашу проверку и применимость к проекту. Данные хранятся в `catalog/entities.json`; исполняемый контракт — `scripts/entity-model.mjs`. Markdown остаётся текстом анализа. Эта схема пока применена к пяти источникам, а не ко всему архиву.

## Сущности и обязательные поля

| Сущность | Поля |
| --- | --- |
| Study | `id`, `title`, `kind`, `card`, `primary_url`, `current_review_id`, `fit_coverage` |
| Version | `id`, `study_id`, `ref`, `url`, `unknown_reason` при неизвестной версии |
| Review | `id`, `study_ids[]`, `version_ids[]`, `date`, `document`, `source_coverage`, `limitations`, `supersedes` |
| Experiment | `id`, `study_ids[]`, `review_id`, `environment`, `result`, `scope`, `limitations`, `artifacts[]` |
| Project | `id`, `title`, `registry_revision`, `registry_card_url` |
| Assessment | `id`, `study_id`, `project_id`, `review_id`, `date`, `decision`, `evidence`, `reason`, `limitations`, `next_test` или `next_test_reason`, `project_revision`, `project_card_sha256`, `source_matrix`, `supersedes` |
| Current assessment | `study_id`, `project_id`, `assessment_id` — единственная актуальная оценка пары |
| Study relation | `id`, `from`, `to`, `type`, `reason`, `review_id` |

ID не зависит от пути и даты. Один обзор может рассматривать несколько источников. Общий обзор не превращает две работы в один источник. Ссылка на другую работу в тексте сама по себе не создаёт Study relation.

Статус доступа/разбора источника, результат опыта, project-fit и разрешение внедрения не подменяют друг друга. `NO_CONFIRMED_FIT` — отсутствие подтверждённого соответствия. `NOT_MIGRATED` — оценки ещё не перенесены в модель; прежние материалы остаются доступны в карточке. Это не NO_FIT, не NOT_RUN и не отсутствие анализа.

Для неизвестной версии обязателен `unknown_reason`. Отсутствующий отдельный тест имеет явную причину в `next_test_reason`, а не выдуманную команду. В пилоте licences/third-party terms остаются в первичных карточках и обзорах; модель не является license audit.

## Актуальность и происхождение

Обзоры и оценки имеют собственные ID. `supersedes` задаёт историю, `current_review_id` и `current_assessments` задают текущий выбор явно. По имени файла или максимальной дате актуальность не выводится. Замена оценки возможна только для той же пары источник–проект. Циклы запрещены.

В пилоте 90 оценок REA перенесены из двух исторических матриц: 45 первоначальных и 45 последующих. Валидатор сравнивает решение, evidence, rationale, ревизию и hash карточки с указанной исходной матрицей. Это проверка сохранности импорта, не новое подтверждение научной или проектной пользы.

## Представления

- [Структурированные источники](../catalog/studies/README.md): версия, текущий обзор, история, применимость и экспериментальные артефакты.
- [Проекты](../projects/README.md): обратная проекция тех же current assessments. Список не редактируется вручную.
- [Полный старый каталог](../studies/INDEX.md): все 81 карточка; только пять уже используют явные review relations. Для остальных пока работает прежняя навигация.

Реестр проектов остаётся приватным источником истины. В публичную проекцию перенесены только уже опубликованные ID и pinned ссылки, без приватных описаний и кода. 45 страниц проектов не означают перенос всех исследовательских связей.

## Наполнение и проверки

1. Создать или найти Study по первоисточнику. Не создавать второй Study ради новой версии или оценки.
2. Зарегистрировать Version и Review, сохранить ограничения. При нескольких источниках перечислить все ID и их версии.
3. Добавить Experiment только с заявленным scope и существующими артефактами. Старые raw результаты не переписывать.
4. Переносить project fit только из проверенного основания; неизвестные связи оставить немигрированными. Обновить current pointer, не удаляя историю.
5. Запустить `node scripts/build-catalog.mjs`, `node scripts/check.mjs`, `node --test scripts/check.test.mjs scripts/entity-model.test.mjs`, `git diff --check`.

Генерация валидирует модель до записи файлов. Проверка охватывает внешние ключи, версии обзора, первоисточник, обязательные поля, существование документов, provenance импорта, актуальность и циклы. Она не доказывает истинность утверждений в prose и не проверяет доступность внешних сайтов.

## Границы пилота и следующий шаг

Пять случаев: BenchShield (статья), REA (engineering и повторная оценка), Unreal Agent (недоступное видео), RRSI и Harness² (общий обзор двух работ). В структурированный Experiment пока перенесён только PE layout опыт REA; отсутствие остальных записей не меняет ранее опубликованных результатов.

После проверки этих случаев можно мигрировать остальные карточки и связи партиями. Неоднозначные упоминания должны проходить редакционную сверку. Старые адреса, архив, исходные матрицы и исследовательские статусы сохраняются.
