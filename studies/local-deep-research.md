# Local Deep Research — автономный поиск, RAG и отчёты с цитированием

[Структурированная запись и связи](../catalog/studies/local-deep-research.md)

**Тип:** open-source engineering source, не рецензированное исследование. **Первичный источник:** [LearningCircuit/local-deep-research](https://github.com/LearningCircuit/local-deep-research), pinned [`32b50c96f316e9025341fbf569c9381b8c9f351b`](https://github.com/LearningCircuit/local-deep-research/tree/32b50c96f316e9025341fbf569c9381b8c9f351b), commit 2026-11-23, snapshot review 23.11.2026. [MIT License](https://github.com/LearningCircuit/local-deep-research/blob/32b50c96f316e9025341fbf569c9381b8c9f351b/LICENSE); app version [`2.0.3`](https://github.com/LearningCircuit/local-deep-research/blob/32b50c96f316e9025341fbf569c9381b8c9f351b/src/local_deep_research/__version__.py).

**VERIFIED — не просто prompt-обвязка:** Python ≥3.12, FastAPI/Socket.IO backend, web frontend, configurable pipeline strategies и `langgraph-agent` с поисковыми tool calls и ограничением итераций; поисковые engines для публичного web и академических источников (включая arXiv, PubMed, Semantic Scholar), локальной библиотеки и внешних document stores. PDF/HTML ingest, дедупликация ссылок, SQLCipher per-user DB, документы/collections, embeddings и RAG, API/MCP, экспорт отчётов. Привязка citations к sources реализована в `SearchResultsCollector` и citation handlers; **не** доказана автоматическая семантическая истинность каждого процитированного утверждения.

**Критическая поправка к «всё локально»:** локальная программа и SQLCipher не означают отсутствия интернет-передачи. Выбранный облачный LLM/embedding API, публичные search providers и даже локальный SearXNG, отправляющий запросы во внешние движки, создают egress. Режимы `Adaptive / Public only / Private only / Strict` и SSRF/egress policy реализованы, но upstream [SECURITY.md](https://github.com/LearningCircuit/local-deep-research/blob/32b50c96f316e9025341fbf569c9381b8c9f351b/SECURITY.md) прямо называет их **best-effort**, не OS network sandbox. Только внешнее network namespace/firewall ограничение даёт реальную границу. PDF/library storage может включать filesystem, а не только encrypted DB — конфигурация имеет значение.

**BENCHMARK — AUTHOR_REPORTED, конфигурационно зависим:** [README](https://github.com/LearningCircuit/local-deep-research/blob/32b50c96f316e9025341fbf569c9381b8c9f351b/README.md) заявляет ~95% SimpleQA и 77% xbench-DeepSearch для Qwen3.6-27B. Таблица в pinned README конкретизирует **95.7% = 287/300** и **77/100**, стратегия `langgraph-agent`, локальная модель Ollama + **облачный поисковик Serper**. В шапке одновременно написано `n=500` — знаменатель headline **не совпадает** с 300 в таблице, требуются исходные артефакты для reconcile. Другие модели: Qwen3.5-9B 182/200, gpt-oss-20B 295/346. Grader-LLM шумит, вероятна benchmark contamination, независимого A/B на выбранных задачах не было. Нет причин переносить 95.7% на медицинские рекомендации, PostgreSQL RCA или собственное оборудование.

**Применимость:** как самостоятельный **candidate search-and-collect stage** для `dsh-paper2agent`, отдельный public-literature explorer для `TrinMedicalBot`, документальный comparator для `Wiki_PG` (синтетические/публичные технические материалы). Не подменять независимую оценку источников, clinical/DBA gating или текущие фактические provenance, не загружать реальные медицинские/производственные данные.
