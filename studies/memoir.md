# Memoir — Git-like branch-aware память AI-агентов

[Структурированная запись и связи](../catalog/studies/memoir.md)

**Тип:** open-source engineering project, не peer-reviewed performance study. **Pinned source:** [`zhangfengcdt/memoir@7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d`](https://github.com/zhangfengcdt/memoir/tree/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d), commit 2026-10-27; [Apache-2.0](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/LICENSE); [Python package `memoir-ai` 0.2.9](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/__init__.py), Alpha.

**Верно:** [ProllyTree VersionedKvStore](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/prolly_adapter.py), branches/checkout/merge/commit/diff/blame и Merkle-style `generate_proof`/`verify_proof`, семантические иерархические пути, LLM или шаблонная классификация, CLI/SDK/MCP, официальные плагины Claude Code, Codex, Hermes. Branch-aware память может уменьшить загрязнение контекста при переключении Git-веток, но это **пока исследовательская гипотеза**, не доказанная точность recall в этом портфеле.

**Оговорки к маркетингу:**
- «**Криптографически защищено**» относится к *целостности и верифицируемости*, не шифрованию at rest, authentication, RBAC, privacy или независимому доверенному корню. [`_encode_value`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/prolly_adapter.py#L568-L577) сохраняет plain JSON/UTF-8; [CryptoService](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/crypto_service.py) делегирует proof хранилищу. Сравнение с доверенной *внешне закреплённой* root hash и устойчивость к adversarial rewrite не продемонстрированы.
- «**Заменяет векторную БД**» справедливо для **путевого/ключевого сценария**, но в собственном проекте есть [`VectorService`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/vector_service.py) с ProllyTree `NamespacedKvStore.text_index_search` и MiniLM embedding (~90 MB download first run); path lookup и vector semantic recall — разные операции.
- «**O(log n)**» — не строгая общая сложность: [docs/theory/search.md](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/docs/theory/search.md#L502-L508) называет это «shape claim», при этом `summarize` группирует k ключей за O(k), LLM path pick добавляет токены и задержку. [`all_keys()`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/prolly_adapter.py#L524-L537) использует восстановление всего снимка из истории из-за лимита ProllyTree `list_keys()` 1024 записей. Предыдущие latency и 1M-scale claims **не воспроизведены**.
- Git-history `forget` означает логическое удаление текущего ключа, но сохранение прежней версии в коммитах может удерживать приватные сведения. Для *физического стирания* нужен независимый retention/rewrite/GC/remote deletion протокол. В дополнение [`git_safety.py`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/git_safety.py) отключает auto-GC ради защиты dangling ProllyTree nodes: принудительный `git gc --prune=now` способен их уничтожить; операционные backup/recovery и disk growth требуют теста.
- [`hooks/stop.sh`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/plugins/claude-code/hooks/stop.sh) автоматически извлекает факты из транскрипта/изменений кода, а Codex/Hermes hooks имеют аналогичные точки захвата. LLM-провайдеры и opt-in `memoir-cloud` sync создают явный egress и retention/privacy scope, требующие согласования. Безопасное чтение через ручной `memoir get` и запись с явным `-p` может работать без LLM, но автоматическая классификация/semantic search не обязательно offline.

**Риск использования:** не подключать auto-capture к репозиториям с production AKUZ данными, credentials, приватными инструкциями или медицинскими транскриптами; не считать branch namespace полноценным tenant ACL; не включать cloud sync по умолчанию.

**Registry applicability:** 45 карточек [`Artemedi/project-registry@91a0ca742a3225f6c4683b51031e8bbb595fdab8`](https://github.com/Artemedi/project-registry/tree/91a0ca742a3225f6c4683b51031e8bbb595fdab8) просмотрены, 4 **DOCUMENTED_CANDIDATE** по архитектуре: `TencentDB-Agent-Memory` (comparator history vs shared memory), `dsh-team-context` (versioned skills/learnings with governance), `HermesAgent` (реальный upstream provider plugin, но live settings вне допуска), `dsh-runtime` (tenant/branch-aware agent memory experiment). Другие 41 — `DEFERRED_SCREENING`, не `NO_FIT`. Ни одна интеграция или performance benefit не подтверждены.
