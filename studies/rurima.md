# Rurima — image/rootfs utility и частичный Linux container runner

[Структурированная запись и связи](../catalog/studies/rurima.md)

**Тип:** open-source engineering tool, не исследовательская публикация. **Первичный источник:** [RuriOSS/rurima](https://github.com/RuriOSS/rurima), pinned [`30a0637331a95b05377e3ea2e36d52b13d1a94f7`](https://github.com/RuriOSS/rurima/tree/30a0637331a95b05377e3ea2e36d52b13d1a94f7), commit 2026-09-07, review 2026-11-23; [MIT license](https://github.com/RuriOSS/rurima/blob/30a0637331a95b05377e3ea2e36d52b13d1a94f7/LICENSE). Written in C, submodules pinned at ruri `711673a7b2a1e3c5d2a77a6085f2e082e8fd5d56`, catsh `300103abc54a07fff1be7d0add7d136a966d45db`, ssfx `4c79538755661de75aaa912c9fd8e4dc90c6bbca`.

**Проверенная суть:** [README](https://github.com/RuriOSS/rurima/blob/30a0637331a95b05377e3ea2e36d52b13d1a94f7/README.md) описывает загрузку rootfs из Docker Registry и LXC mirror, распаковку, восстановление, резервирование tar и запуск встроенного `ruri`. Не требует *установки Docker Engine или LXC*, но **не OCI compliant** и не является их полной заменой; проекты `Rurima` (fetch/unpack/manage) и `Ruri` (runtimes chroot/unshare/rootless) различаются.

**Критическая поправка к описанию «без зависимостей»:** [`src/checkdep.c`](https://github.com/RuriOSS/rurima/blob/30a0637331a95b05377e3ea2e36d52b13d1a94f7/src/checkdep.c) проверяет доступность `tar`, `curl`, `file`, `gzip`, `xz`. Для JSON registry/meta используется `jq`; для проверки Docker layer hash — `sha256sum` при доступности; без root для извлечения rootfs нужен `proot` (README), а полноценный `ruri --rootless` требует user namespaces и `uidmap` по [документации закреплённого субмодуля Ruri](https://github.com/RuriOSS/ruri/blob/711673a7b2a1e3c5d2a77a6085f2e082e8fd5d56/doc/USAGE.md). Статический бинарник Rurima **не** означает, что внешние utilities не нужны. Сборка через CMake требует libcap и libseccomp.

**Граница безопасности:** без cgroups/namespaces работа сводится к более слабым chroot/PRoot сценариям, не доказывающим network/filesystem/process/resource isolation. [FAQ](https://github.com/RuriOSS/rurima/blob/30a0637331a95b05377e3ea2e36d52b13d1a94f7/doc/FAQ.md) говорит, что Rurima не реализует сетевую изоляцию; pinned Ruri отдельно допускает unshare и `-x`, но NET/USER namespaces у него ограничены. Нельзя подменять OCI rootless Podman в экспериментальном sandbox.

**Проверяемый риск образов и поставки:** [`src/dockerhub.c:632–650`](https://github.com/RuriOSS/rurima/blob/30a0637331a95b05377e3ea2e36d52b13d1a94f7/src/dockerhub.c#L632-L650) проверяет SHA-256 Docker layers **лишь при `!fallback` и наличии `sha256sum`**; fallback, автоматически применяемый для некоторых registries, оставляет этот путь без сверки слоя. [`src/subcommand.c:698–793`](https://github.com/RuriOSS/rurima/blob/30a0637331a95b05377e3ea2e36d52b13d1a94f7/src/subcommand.c#L698-L793) OTA загружает tar из latest release и заменяет исполняемый файл, без видимой в этой функции сверки хэша/подписи скачанного tar. Не использовать `rurima ota`, `. <(curl ...)` из README или непроверенные внешние rootfs на хосте.

**Применимость:** Bazzite уже имеет rootless Podman; преимущества Rurima возможны в Termux/minimal Linux и как read-only referential comparator по разбору OCI layer и rootfs, а не как замена производственной изоляции. По документам `dsh-paper2agent` использует Podman для изолированных опытов; `Harness` имеет deployment и integration probes — оба пригодны *только* для исследовательского сопоставления архитектурных tradeoffs и инвентаризации требований. Никаких доказанных потребностей в замене рантайма и готовых extension points не обнаружено.

**Вердикт:** `BOUNDED_CODE_REVIEW / DOCUMENTED_CANDIDATE / NEEDS_EVIDENCE / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED`. Ни binary, ни образ, ни контейнер, ни updater в ходе аудита не запускались.
