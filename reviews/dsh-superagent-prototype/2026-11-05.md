## Что действительно ограничивает полномочия

`VERIFIED` по [src/policy.ts:167](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/policy.ts#L167): отправитель, receiving scope и admission table определяют explicit/inferred запрос. Бот не получает explicit strength; авто-принятие inferred требует `auto` и включённых правил. Режим по умолчанию — `observe` (:84). [assessmentOutcome:40](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/policy.ts#L40) проверяет покрытие правил, направление и наличие intent evidence. Семантическая истинность model-written evidence этим не доказана.

Work item — Ticket с неизменяемым Mandate, содержащим основание, actor, policy version и scope. [Evals](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/core/evals.ts) не создаёт второй Ticket из уже принятого Trigger и отклоняет решение по старой policy version. Follow-up, которым владеет worker, нельзя принять повторно до handback. Подписка доставляет контекст, но не должна расширять Mandate. Проверка соответствия текста исходному scope частично остаётся задачей модели; строка scope не является OS capability.

[Tickets.wake:252](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/core/tickets.ts#L252) перепроверяет Mandate перед возобновлением завершённой задачи. Human stop не даёт ей возобновиться; бот/CI и context-only поток не возобновляют завершённую задачу. Важное исключение: [settingsPolicy.revalidate:213](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/policy.ts#L213) сохраняет explicit follow-up Mandate при сохранённом source scope. Изменение policy для уже работающего Ticket даёт Input, а не немедленно убивает процесс. Нельзя описывать удаление отправителя из списка как универсальный мгновенный отзыв всех действий.

## Permission и sandbox: разные уровни

Обе управляемые роли получают [`danger-full-access` в src/app/sessions.ts:152](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/sessions.ts#L152). [workOnly:289](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/sessions.ts#L289) ограничивает набор инструментов и запрещает новые tool calls после завершения Ticket; shell при этом остаётся полномочным инструментом. Отдельная Session и рабочая директория разделяют состояние работы, но не пользователя ОС, файловые права или сеть.

[src/infra/environment.ts:45](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/infra/environment.ts#L45) убирает ambient GitHub token/identity overrides и настраивает отдельный git config; [:79](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/infra/environment.ts#L79) создаёт PATH wrappers для agent account и запрещённых имён. `gh`, `git`, `lark-cli` нельзя запретить этим списком. Абсолютный путь обходит PATH shim. [:149](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/infra/environment.ts#L149) проверяет локальные git credential/extraheader настройки, но не все возможные каналы чтения секретов и исполнения. Сам [deployment guide:19](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/006-deployment.md#L19) предупреждает о доступе к home оператора.

Prepare — настроенная оператором shell-команда с timeout, [executor/dsh.ts:247](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/executor/dsh.ts#L247). Данные Trigger не могут штатным settings tool менять prepare/account CLI: [settings.ts](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/settings.ts) проверяет origin для этих полей. Но [main tools:249](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/tools/main.ts#L249) разрешают сохранять policy/eval по инструкции «только по explicit human request»; schema не содержит независимо проверяемого approval token. Management API имеет panel origin. Shell и API под тем же OS user не превращаются в недоступные модели capabilities. Это архитектурное ограничение, **не воспроизведённая эксплуатация prompt injection**.

## Privacy и внешние действия

[HTTP:75,230](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/http.ts#L75) требует bind на 127.0.0.1, ожидаемый Host, custom header и совпадающий Origin, если он задан. Это защита от части browser cross-origin запросов, не аутентификация локального процесса: Origin может отсутствовать, а локальный процесс может сформировать header. Реального HTTP exploit-теста не было.

[Store:51](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/store.ts#L51) сохраняет Triggers, Decisions, Tickets, настройки, outbox и effects в SQLite/WAL; исходный код задаёт chmod 0600 для DB и 0700 при создании каталога. Это не шифрование и не доказательство аналогичной ACL-семантики Windows. [resources.ts](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/resources.ts) ограничивает чтение worker его Ticket/Threads на уровне resource API; OS filesystem этим не ограничен. Сообщения и результаты могут уходить настроенному model provider и в каналы. Перед применением нужны отдельные data-retention, model-egress и least-privilege решения; реальные пользовательские данные не использовались.

Авто-слияние регулируется delivery prompt и GitHub branch protection, а не merge-specific host gate ([docs/003-execution.md](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/003-execution.md)). Наличие approvals в тексте инструкций не доказывает server-side enforcement.

## Lifecycle, восстановление и доставка

Ядро разделяет Ticket, Assignment, доставленный Input и прочитанный Input. Pause не останавливает текущий turn. Human stop и завершение Ticket переводят assignment в ended и вызывают Executor.stop. [executor/dsh.ts](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/executor/dsh.ts) резервирует worker slots, оставляет дополнительный слот человеческому follow-up и ограничивает retries. Это не общий лимит потребления CPU/RAM/денег всех процессов.

[Effects](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/effects.ts) хранит очередь до действия, использует generation против удаления нового payload старой попыткой и retry/backoff. [Outbox:39](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/app/outbox.ts#L39) фиксирует sent после ответа источника. [GitHub channel:18](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/sources/github-channel.ts#L18) ищет свой marker перед POST; [Feishu channel:19](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/src/sources/feishu-channel.ts#L19) передаёт idempotency key. По коду это механизмы снижения дублей, не доказательство exactly-once внешних операций. Сбой после внешнего эффекта до локальной записи и согласованность внешнего read-back требуют отдельного fault-injection теста.

## Выполненный ограниченный эксперимент

Объект: оригинальные `src/core/*.ts`, без переписывания алгоритма. Среда: Windows, Node v24.19.0, built-in TypeScript transform, Node permission model с разрешённым чтением только исходника и fixture; запись, child processes, workers и addons не разрешены. Сетевых модулей в исполняемом core/fixture нет; отдельный OS network namespace не создавался. Node permission model сам по себе не заявляется OS sandbox. Ни живого агента, ни GitHub/Feishu CLI, ни LLM, ни секретов.

Предикаты oracle — assertions независимого fixture по сохранённым Ticket/Decision, числу fake launches/stops и сообщениям fake outbox. Policy, Executor и Outbox подставные. **settingsPolicy и реальный enforcement не тестировались**. Положительные и отрицательные пары: human/bot resume, valid/revoked mandate, own/context thread, current/stale policy, original/duplicate event. 15/15 в исходном коде; повторный запуск с heap limit 128 MiB тоже 15/15. Это детерминированная функциональная проверка, не статистический benchmark latency или эффективности.

Mutation control: в отдельной локальной копии core удалено только `if (!policy.revalidate(ticket.mandate)) { this.refuse(ticket); return }` из Tickets.wake. Тот же fixture завершился ненулевым кодом на `revoked mandate cannot resume completed ticket`: задача ошибочно ожила. Положительный baseline и отрицательный mutant различены; upstream checkout не менялся. Для воспроизведения скопировать `src/core` в отдельное дерево и выполнить указанную однострочную мутацию. Не запускать mutant как сервис.

```powershell
# В корне research-hub; $source — отдельный checkout указанного SHA.
$source = (Resolve-Path ../bk060-source).Path
$fixture = (Resolve-Path experiments/2026-11-05-bk060-core-offline.mjs).Path
node --experimental-transform-types --permission --max-old-space-size=128 "--allow-fs-read=$source" "--allow-fs-read=$fixture" $fixture $source
```

Перед воспроизведением проверить `git rev-parse HEAD` и чистоту core. SHA в JSON обозначает проверенный исходный снимок, а не runtime-верификатор произвольного переданного каталога. CPU — один короткий процесс; heap cap 128 MiB не равен измеренному RSS, GPU/VRAM не используются, сетевые/платные вызовы отсутствуют. Полезность проекта, model cost и p95 не измерены.

Upstream tests/typecheck/build: `BLOCKED_ENV / NOT_RUN`. При попытке typecheck pnpm начал разрешать отсутствующие зависимости; загрузки получили EACCES, downloaded/added=0, процесс остановлен. Новые зависимости и install scripts не запускались. Повторной сетевой установки не было. Отдельного lint script в package.json нет. Публикуемый fixture проверяется `node --check`; полный `pnpm check` не считается успешным.

## Следующий gate и исторический статус

Для каждого кандидата заморозить baseline SHA, fixture, oracle и план до изменения кода. Предлагаемый A/B: 100 искусственных traces, по 3 одинаковых replay на arm; ошибки разрешений/повторных внешних действий/orphan processes — 0, state oracle совпадает в каждом шаге; сравнивать только при одинаковых входах. Считать wall time, peak RSS, IO, requests/tokens/cost и false accept/reject. Предел: один disposable worker, 60 секунд на trace, 512 MiB целевого бюджета; отдельный OS account/container без пользовательских home/credentials, fake network endpoints. Это **план**, не выполненное измерение. Rollback — удалить только disposable среду; рабочие проекты не меняются. До baseline `BLOCKED: MEASUREMENT_MISSING`.

Исторический BK-060 получает **«разобран»**, а не «проверен экспериментально» всей системы: основной результат — source review и узкий тест core, реальный security/runtime gate отсутствует. `LAB_VERIFIED` допустим только с квалификатором original in-memory core 15 checks; для проектов остаётся `NEEDS_EVIDENCE`, `PRODUCTION_APPROVED` отсутствует. BK-025/034/041/063/064 этим отчётом не продвигаются.
