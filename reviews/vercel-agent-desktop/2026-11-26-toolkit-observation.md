# Agent Desktop — чтение дерева Qt и Electron

26 ноября 2026 года

Закреплённая версия Agent Desktop распознала поле и кнопку в **шести из шести** снимков синтетических окон. В каждом снимке имена совпали, поле имело роль `textfield`, кнопка — `button`, у элементов были ссылки. Контроль с заведомо отсутствующим именем прошёл во всех шести снимках. Второй запуск воспроизвёл все наблюдения. [Протокол](../../experiments/vercel-agent-desktop/2026-11-26-toolkit-observation-protocol.md) · [Результат](../../data/results/vercel-agent-desktop/2026-11-26-toolkit-observation.json) · [Предыдущий прогон GTK](2026-11-05-wayland.md)

| Стенд | Поле и кнопка | Отсутствующий элемент |
| --- | ---: | ---: |
| Qt 5, отдельный X11-дисплей | 3/3 | 3/3 |
| Electron 44.7.0 с принудительно включённой доступностью Chromium, отдельный X11-дисплей | 3/3 | 3/3 |

Наблюдение шло через настоящий CLI и приватную шину AT-SPI. Временный контейнер работал без сети. В исходной попытке стенд ждал запуска Xvfb. Добавили контейнерный init, после чего дисплей и шина стартовали. Xvfb сообщал, что непривилегированный пользователь не создаёт каталог сокетов, а Electron сообщал об отсутствии системной D-Bus. Оба приложения были видны на отдельной шине сессии. [Версия Agent Desktop](https://github.com/vercel-labs/agent-desktop/tree/b43ac4f6e892ef608f8851428613c4009f0e84c7)

Для **psqlqa** результат обосновывает проверку стандартных элементов Qt на синтетическом плане запроса. Для **concept-loom-desktop** он подтверждает чтение именованных элементов HTML при указанной настройке Electron. Деревья реальных приложений, доставка ввода, отображение графа или плана и поведение на Windows остаются непроверенными. Перед оценкой пользы нужно сверить дерево доступности отдельного тестового окна целевого проекта с его эталоном.
