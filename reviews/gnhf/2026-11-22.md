## 2. Что это значит для безопасной автономности

| Авторский тезис | Проверенный механизм | Граница |
| --- | --- | --- |
| «Каждая итерация делает небольшой чистый коммит» | Агент получает instruction выбрать один маленький шаг; есть commit + notes | Содержание, размер diff и test-pass не контролируются независимым gate |
| «Ошибки откатываются» | `reset --hard` + `clean -fd` | Только Git worktree; внешние side effects не откатываются; untracked файлы удаляются |
| «Можно безопасно оставить на ночь» | Лимиты, stop, resume, backoff, worktree | По умолчанию unlimited iterations/tokens/runtime и bypass permissions; безопасность зависит от внешней изоляции |
| «Журнал всех изменений» | Локальные notes/JSONL и Git history | Не равнозначно независимому audit ledger, опубликованным критериям и фактическому качеству |

## 3. Обобщённая гипотеза и независимый эксперимент

**H1:** дополнительный bounded orchestration loop с маленькими committable единицами и отдельным review может повысить долю завершённых **проверенно корректных** задач за фиксированный бюджет по сравнению с ручным однократным агентным запуском; после включения обязательных независимых safety gates. **H0:** прирост отсутствует или компенсируется непроверенными коммитами, стоимостью, регрессиями, опасными side effects.

**A/B/C — предрегистрируемый план, НЕ выполнен:**
- **A:** один агент без внешнего overnight loop, но с одинаковыми входными задачами и бюджетом;
- **B:** базовый собственный bounded orchestrator (скрипт изолированного Git worktree, deterministic tests/rollback);
- **C:** pinned gnhf с явно выставленными лимитами/закрытым агентным исполнителем и отдельным host-controlled validation gate. **Без контроля исполнения внешних команд C не допустим**.
- Использовать 10–20 искусственных Git-задач с fixture-only проектом; заранее замороженные requirements/test oracle, отдельная копия repo/кэш/домашний каталог; независимые tests, `git diff`, approved path allowlist, build, lint, выходные хеши, остановка по budget. Adversarial cases: `success=true` при no-op, failing tests, timeout, invalid JSON output, rate-limit, unauthorized file edit, fail commit, untracked sentinel rollback, prompt injection в файле. Каждая variant получает одинаковую модель, ограничения и условия.
- Измерять `accepted_valid_commits` (не `commitCount`), долю прошедших независимую проверку, false success, нарушенные границы, destructive side effects, end-to-end время, токены/стоимость, число повторных попыток, размер diff, recoverability. Неправильный коммит считается провалом независимо от ответа агента.
- **Непересекаемые полномочия:** rootless Podman `--network=none` с filesystem read-only за пределами отдельного sandbox и ограниченными томами; fake agent без credentials/host access. Никаких реальных SSH, DB, GitHub push, секретов или медицинских данных. Отдельный человеческий gate для любых живых агентов.
- **Success gate:** ноль выходов за allowlist и побочных эффектов, 100% независимое прохождение для принятых коммитов, stop/rollback без повреждения пользовательского дерева, C по accepted-valid-work/budget не хуже B и A. Нулевой результат или риск достаточны для отказа. Результат одного synthetic fixture не даёт production approval.
