## 1. Verified boundary of the available sources

- **Only 20 tracked files in upstream repo:** 9 Markdown (README and skills/commands), 9 JSON (Claude plugin marketplace, per-project config), PNG demo and gitignore. There is **no** Rust/Tauri/React Desktop implementation, dependency lockfile for Desktop, runtime test suite, security/authorization code or Desktop CI workflow in this Git tree. `README.md` itself says **Proprietary. All rights reserved**, and `LICENSE` / `LICENSE.md` are absent. Analysis and independent reimplementation of *ideas* are possible, but copying/translating private implementation, treating plugin repo as source availability or asserting security-reviewed Desktop is not. Separate [Lanes Link](https://github.com/lanes-sh/link) claims open-source status for a **different product**, which cannot license Desktop.
- **macOS-only vendor-support claim:** [`README.md`](https://github.com/lanes-sh/app/blob/7b9cb385d1100ded8a74986f81472f8856840578/README.md), [`install-lanes-desktop/SKILL.md`](https://github.com/lanes-sh/app/blob/7b9cb385d1100ded8a74986f81472f8856840578/plugins/lanes-desktop/skills/install-lanes-desktop/SKILL.md) and [Quickstart](https://lanes.sh/docs/desktop/quick-start) require macOS Ventura+ / `uname -s == Darwin`, supported installer Homebrew cask. A Linux/Bazzite application, Flatpak, AppImage, Windows package or source build is **not established** by those official materials. For Bazzite, do not install unsupported package or claim parity on Linux.
- **Product model described, not independently observed:** README says Tauri 2, React 19, Rust, SQLite; product docs [Sessions](https://lanes.sh/docs/desktop/sessions) and [Worktrees](https://lanes.sh/docs/desktop/worktrees) describe PTY-backed Claude Code/Codex sessions and arbitrary shell CLI (not first-class resume/metrics for all), issue board, per-issue branch/worktree, diff and Git actions, SQLite browser and Monaco. Static repo proves documentation and plugin instructions, **not** the underlying crash, write-lock, PTY, model detection, Git or SQLite implementation.
- **Native local MCP is a privileged orchestration surface:** [`lanes-sessions/SKILL.md`](https://github.com/lanes-sh/app/blob/7b9cb385d1100ded8a74986f81472f8856840578/plugins/lanes-desktop/skills/lanes-sessions/SKILL.md) documents `lanes_create_issue`, `lanes_start_session`, `lanes_read_terminal`, `lanes_get_issue_changes`, `lanes_delete_worktree` and more; [local MCP docs](https://lanes.sh/docs/desktop/local-mcp) show optional SSE endpoint `http://localhost:5353/sse`, default off. It can read prompt and terminal content and spawn CLI processes with user-supplied flags/env/worktrees. No Desktop source => cannot verify endpoint bind/auth/ACL/origin checks, approval granularity, session-scope access, race conditions or log redaction. Design requirements: loopback bound, authorization, write actions gated by human, never expose externally.
- **Race/idempotence hazard documented by authors:** the [`lanes-sessions` skill](https://github.com/lanes-sh/app/blob/7b9cb385d1100ded8a74986f81472f8856840578/plugins/lanes-desktop/skills/lanes-sessions/SKILL.md) explicitly says `lanes_start_session` **always adds** a new session; launches are asynchronous; unconfirmed start and temporarily empty status are not failure and must not be retried blindly. `lanes_resume_session` is Claude-only. For high fan-out in DSH use idempotency keys, durable issue/attempt IDs, at-most-once attempt creation, heartbeat/state reconciliation, concurrency caps and cancellation evidence.
- **Worktree is not isolation boundary:** [Worktrees docs](https://lanes.sh/docs/desktop/worktrees) say every issue gets a branch and working folder in a shared Git repo. Git worktrees share object storage, history and usual user privileges; by default share `$HOME`, environment, Git credentials, filesystem mounts, network and hardware. Worktree reduces local code-edit collisions but neither prevents agents writing other worktrees nor running privileged commands. Subsequent merges can conflict, and preview of each separate diff is not integration testing. Use isolated UID/rootless Podman/VM for untrusted code and explicit paths/quotas, not GUI folder separation.
- **Public examples can authorize dangerous operations:** [`.lanes/quick-actions.json`](https://github.com/lanes-sh/app/blob/7b9cb385d1100ded8a74986f81472f8856840578/.lanes/quick-actions.json) includes terminal shell `git merge` and AI instructions to commit/push/release/merge; `.lanes/cli-flags.json` includes `--enable-auto-mode`; [GitHub bridge skill](https://github.com/lanes-sh/app/blob/7b9cb385d1100ded8a74986f81472f8856840578/plugins/lanes-bridges/skills/github-lanes-bridge/SKILL.md) illustrates fan-out with `dangerously-skip-permissions`. These are **documentary caution examples, not demonstrated Desktop exploits**. Do not ship default unattended `push`, `merge`, wildcard chmod or bypass-permissions flags. Use draft PR after independent test and explicit owner gate, and no writes to protected production branches.
- **Provider credential boundary needs careful language:** [Gateway docs](https://lanes.sh/docs/desktop/gateway) say profile auth is given to the CLI process as environment, not terminal text/args/`ps`. Environment **is still accessible to the child process and can be inherited by its children**; that is not a security boundary from the agent executable. [Settings](https://lanes.sh/docs/desktop/settings) warn `env=VALUE` in repo-saved `.lanes/cli-flags.json` command prefixes can appear in scrollback and process args. Login shell may override configured gateway. Lanes docs say Codex reads `~/.codex/config.toml` and cannot always be configured by Gateway env like Claude. Secrets, model routing and remote endpoints need dedicated per-agent immutable policy and redacted audit, not guessed provider compatibility.
- **Remote and crash-report claims not source-verified:** README claims local-first SQLite, opt-in remote team workspaces, GitHub/Linear OAuth, and crash reporting **enabled by default**. Product privacy policy and nonpublic implementation need independent checks for telemetry payloads, sync encryption, data deletion, prompt/terminal capture and token storage before sensitive projects. Lanes Link's permissions/audit guarantees apply to the separate Link component only, **not** as blanket proof of Desktop security.
- **Loops offer useful safeguards but no universal guarantee:** [Lanes Loops guide](https://lanes.sh/docs/desktop/loops) recommends maker/checker separation, diff inspection and actual test execution, wall-clock timeout, attempt cap, context budget and human review for blocked input. It includes a sample loop protocol, not an independently validated scheduling engine with durable at-most-once semantics or proven correctness under crash. No pinned repo performance benchmarks for tasks/hour, accepted PR per agent-hour, token spend, CPU/RSS/IO, worktree cleanup or review quality are available.

## 3. A/B design without installing Lanes

**H1:** on controlled synthetic TypeScript/Python repository fixtures, independent task-bound worktrees + durable attempt states + independent verification reduce duplicate agent starts, unfinished hidden sessions, cross-task accidental edits and time to *accepted* test-backed PR, without raising review and runtime overhead excessively. **H0:** current Git-worktree/CLI/issue discipline is sufficient; an extra board duplicates state and slows incident/research work.

- **A baseline:** existing Linux Git worktrees, DSH/Claude/Codex agent orchestration and GitHub draft PR workflow; record task IDs, one worker per issue, manual check/test/diff/approval; no new dependencies.
- **B bounded conceptual test (YAGNI):** a **paper protocol / no-code fixture** assigning `task_id`, `attempt_id`, `branch`, `worktree`, `agent_model`, `owner`, `state`, `deadline`, `max_attempts`, `review_verdict` from existing tools. Independent worker/reviewer tasks on inert source files; no Lanes code or macOS binary; no auto push/merge. Run the same synthetic issue set, 5+ repetitions if owner authorizes.
- **C Lanes Desktop live comparison:** **NOT_AVAILABLE** on Bazzite Linux under vendor support; would require separate macOS host, proprietary software trust and explicit owner decision. Not a prerequisite for an architectural A/B.
- **Metrics:** issue-to-accepted-PR latency p50/p95, review failure and correction rate, hidden/duplicate sessions, abandoned attempts, context drift, stale status, tests and diff compliance, cross-worktree writes (required zero), branch-merge conflicts, CPU/RAM/IO/disk worktree pressure, peak concurrent sessions, API tokens/$ billed, owner minutes and total operational complexity.
- **Hard gates:** no overwriting unreviewed worktree, no automatic merge/push or permission bypass, no uncontrolled loops, mandatory cancellation/timeout/max retries and independent tests, no production AKUZ/DBA credentials or live agent config mutation. Human approval for any real implementation.

**Decision:** `DOCUMENTARY_REFERENCE_ONLY / MACOS_ONLY / PROPRIETARY / DESKTOP_SOURCE_UNAVAILABLE / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED`. Static repo and docs cannot establish security or operational quality of the proprietary Desktop runtime.
