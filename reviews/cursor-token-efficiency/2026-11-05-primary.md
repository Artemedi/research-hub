## Метод и заявленные результаты

Cursor измеряет производственные запросы и A/B сравнения harness-политик. Зафиксированы пять отдельных изменений: сокращение system prompt примерно на 66%, динамическое подключение tool schemas (без скрытия высокочастотных read/search/edit/shell инструментов), явные cache breakpoints после стабильных слоёв контекста, уменьшение line numbering до каждой десятой строки, ограничение ненужного делегирования subagents и выбора моделей.

Авторы заявляют **7%** снижения совокупной токенной стоимости после комплекса изменений без измеримого ухудшения eval/product-качества. Ранее внедрённая динамическая выдача MCP tools уменьшила **общее количество токенов на 46,9% в сессиях, вызывавших хотя бы один MCP-инструмент** — не в общем потоке запросов. Унос редко используемых встроенных tools сократил tokens в статическом блоке описания на **60%**, но не весь inference cost. Изменения cache-prefix снизили **cold cache misses на 20%**. Прореживание номеров строк уменьшило **cache-read tokens на 1,6%**, а не все входные токены.

## Ограничения и возможный ущерб

Представлены внутренние продуктовые A/B, не доступны raw anonymized traces, счета, параметры сравнения и статистические интервалы; причинность отдельной меры в рамках полного эффекта не установлена. Сдвиг границ caching/provider-specific API может сломать перенос. Отложенная загрузка tool schemas не должна заменять проверку авторизации: невидимый инструмент ≠ запрещённый. Прореживание line numbers может ухудшить ссылочную точность и debugging на файлах с большим количеством строк. Subagent isolation снижает контекст, но может увеличить повторную работу, tokens и latency.
