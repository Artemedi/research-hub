# Cursor Token Efficiency — цена поиска инструмента

26 ноября 2026 года

На девяти синтетических каталогах оба локальных токенизатора показали один переход: дополнительный поиск редкого инструмента увеличивал вход при **4 схемах** и уменьшал при **12 и 24**. Эффект зависит от размера схем и повторяемого контекста. Два запуска дали одинаковые отчёты. [Протокол](../../experiments/cursor-token-efficiency/2026-11-26-token-budget-protocol.md) · [Результат](../../data/results/cursor-token-efficiency/2026-11-26-token-budget.json) · [Ранее проверенный первоисточник](2026-11-05-primary.md)

| Английские схемы | Полный каталог, cl100k / o200k | Редкий инструмент с поиском, cl100k / o200k |
| --- | ---: | ---: |
| 4 | 312 / 323 | 577 / 597 |
| 12 | 856 / 883 | 577 / 597 |
| 24 | 1 672 / 1 723 | 577 / 597 |

Для каталога из 24 схем оценка DSH превышала подсчёт `cl100k_base` на 585 токенов с английским описанием и на 189 с русским. Для китайского описания она была ниже на 99. При `o200k_base` оценка превышала подсчёт для всех девяти каталогов. Изменение порядка при неизменном наборе оставило 13 одинаковых начальных токенов для `cl100k_base` и 14 для `o200k_base`. Восстановление порядка вернуло одинаковый JSON.

Для **DSH Runtime** это обосновывает раздельный учёт размера каталога и запроса поиска. В исходнике DSH сравнение заголовков учитывает порядок инструментов. Можно проверить стабильность порядка на фиксированных запросах, прежде чем измерять кэш. В этой работе запускалась штатная функция оценки размера. Модели, кэш провайдера, счета и внедрение в **DSH Runtime** или **HermesAgent** остались вне прогона. [Статья Cursor](https://cursor.com/blog/improved-token-efficiency)
