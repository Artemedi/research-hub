## Полный первоисточник и версии

Оригинал: [Jediah Katz, Connor O'Keefe, Calvin Yee, *Improved token efficiency for longer agent runs*, Cursor Research, 23 сентября 2026](https://cursor.com/blog/improved-token-efficiency). Полная публичная HTML-страница проверена 7 ноября 2026, SHA-256 raw HTML `8dd43830988dfd560cc8e40f9f72e1768c503abc263ed55cf89d51c273df7526`, извлечённого текста `5f67fe27a2a817f9d06fe8b11616310732d7a4de07c6f12f784b0bb8f187a55f`. Это **первичная инженерная статья**, а не peer-reviewed работа или опубликованный raw A/B dataset.

Cursor сообщает об **уменьшении суммарной стоимости токенов на 7%** при совокупном изменении harness без измеренной автором потери качества. Метрики **не складываются**: −66% приблизительно от размера system prompt; −46,9% *всех токенов лишь в сессиях, вызывавших MCP*; −60% *статических описаний встроенных tools*; −20% *частоты cold-cache misses*; −1,6% *cached-read tokens* после разрежения номеров строк. Публичная статья не содержит исходных логов/выборок достаточных для независимой репликации производственных цифр. Авторы отдельно отмечают coordination tax сабагентов.

## Два независимых трека на общей фиксированной задаче

Перед запуском совета GPT-6 отдельно зафиксировал исходный документ, дизайн синтетического эксперимента, измерения, два отрицательных mutation test и десять проверочных критериев. Совет **не видел** этот контрольный документ до своего вердикта.

**Фикстура:** 12 полностью фиктивных инструментов (4 частых, 8 редких), 52 шаблона задач и 5 seed-перестановок **тех же** шаблонов. Сравнение трёх схем: `static` — 12 полных описаний постоянно доступны; `oracle` — 4 частых + правильные редкие, выбранные заранее независимым gold (идеальный верхний предел); `keyword` — 4 частых + описания редких по буквальному совпадению. Обязательные инструменты проверяются независимым списком `required`. Никаких реальных LLM tool calls, MSSQL/PostgreSQL команд, файловых правок, опасных инструментов или сетевых действий в симуляторе **нет**. Объём текста считается **в символах**, не tiktoken и не в фактических provider tokens. Сравнение не feature-equal: oracle знает ground truth, keyword — нет.

| 5×52 проверки | Static | Oracle dynamic | Naive keyword |
| --- | ---: | ---: | ---: |
| Доступность требуемых инструментов | **260/260** | **260/260** | **220/260** |
| Пропущено обязательных tools | 0 | 0 | **40** |
| Общий контекст, символов | 1 085 775 | 538 875 | 532 305 |

Негативные кейсы: «do not send_notice», «never publish_report», «do not rotate_fixture_key», «never rollback_release». Буквальный router раскрывает соответствующее описание несмотря на отрицание: **4 уникальных примера ×5 перестановок = 20**. Это ошибка выбора *доступного описания*, **не исполнение запрещённого инструмента**. Синонимы «point-in-time copy», «notify a colleague», «revert deployment», «visualize metrics», «inspect kernel events» приводят к пропуску редких инструментов. На 80 редких кейсах 40 промахов. Аудит собственных строк/агрегатов выполнен во всех 15 прогонах; две намеренные подделки результата отвергнуты.

## Как работал совет ZCode

Четыре последовательные роли на **одной** `glm-5.3-flash` через неофициальный ZCode Start Plan: (1) source analyst, (2) экспериментатор, (3) skeptic, (4) председатель. Для членов разрешены только `get_article(section)`, `run_fixture(policy,seed,subset)`, `audit_fixture(...)`. За вызовом стоит host-валидация типов и независимый инвариант по фикстуре; нет shell, GitHub write, личных файлов, браузерной навигации, частных исходников и пользовательских учётных данных в запросах модели. Текущая сессия ZCode используется wrapper'ом в памяти. Локальный HTTP API не запускался.

| --- | ---: | ---: | ---: | ---: |
| Источниковед | 3 | 8 | 64,62 | 7 385 / 2 244 |
| Экспериментатор | 3 | 10 | 123,33 | 7 939 / 5 139 |
| Скептик | 3 | 9 | 97,96 | 7 149 / 3 657 |
| Первый председатель, **неуспешный** | 3 | остановлен лимитом | 80,69 | 7 366 / 2 822 |
| Исправленный председатель | 2 | 1 независимый `verify_all` | 72,39 | 11 986 / 2 916 |
| **Всего, включая переделку** | **14** | — | **438,99** | **41 825 / 16 778** |

Без неудачного первого председателя путь занял **358,30 с**, **34 459 input / 13 956 output**. Это *фактическая ZCode usage-telemetry*, не выставленная стоимость/списание конкретного Start Plan bucket. Рой выполнялся **последовательно**, поэтому нельзя обещать ускорение от параллельных 10 агентов: предшествующий pilot concurrent ZCode был нестабилен. Все четыре роли — **одна модельная семья**, а не независимые поставщики/модели.

У первого председателя модель запрашивала слишком много проверок, цикл достиг ограничителя `tool_call_budget` и **не вынес вердикт**. Старый orchestration loop к тому же возвращал лишь первые пять `tool_use` результатов одного ответа, не подтверждая остальные IDs; у экспериментатора обнаружено как минимум **5 таких пропусков**. Это **дефект управляющего harness**, а не доказательство дефекта модели. Исправленный председатель прошёл двухэтапный протокол: **один** принудительный и отдельно проверенный `verify_all` (с отрицательными mutant controls), все его tool IDs подтверждены; затем отдельный ответ **без предоставления инструментов**. Полный архив первого цикла сохранён в локальном временном каталоге Bazzite, не публикуется вместе с сессионными следами.

## Независимая критическая оценка GPT-6 после вердикта

**Совпало:** председатель подтвердил реальные 260/260, 260/260, 220/260, −50,37/−50,97% по символам, верно не приравнял эти числа к авторским 7%, отказал в production rollout и потребовал проверки семантической маршрутизации с fallback. Совет сам заметил ошибку источниковеда: тот воспринял «20%» как редкую частоту вызовов инструментов, тогда как официальный текст говорит об уменьшении частоты **cold-cache misses**. Один участник видел лишь 2 из 7 разделов, поэтому не мог проверить 1,6% cached-read.

**Материальная ошибка самого совета:** инструмент `audit_fixture` возвращал полные суммы, но список примеров `negative_false_exposure` **обрезался до первых шести элементов**. Председатель и специалисты превратили длину этого превью в «6 ложных экспозиций». Независимый GPT-6 проверил полный набор отрицательных строк и обнаружил **20**, т.е. **4 уникальных отрицательных шаблона ×5 seeds**. Аудит строк агрегатов проверял `missing`/`context_chars`, но **не проверял целостность агрегата отрицательных экспозиций, который председатель вывел из усечённого массива**. В результате «прошёл mutation audit» нельзя считать сертификатом истинности *всех* чисел доклада.

По заранее определённым десяти критериям заключение председателя прошло **9/10** (явно не упомянуто −66% длины system prompt), но **дополнительно содержит существенную численную ошибку, не охваченную этими десятью критериями**. Эта оценка — инженерный чеклист, не научная оценка intelligence или A/B качества.

**Сравнение затрат честно ограничено:** GPT-6 зафиксировал независимый аналитический вывод и исполнил локальный проверяющий Python-цикл за около **6 мс CPU/wall**, но это *только машинное время симулятора*, **не** время/токены размышления GPT-6 и не сравнимо с 439 секундами платёжных вызовов ZCode. Аналогичный model-token trace GPT-6 в этом чате недоступен. Следовательно, утверждать «рой быстрее» или «рой дешевле одного GPT-6» **нельзя**. Влияние реальной координации измерено только на стороне ZCode; для fair model A/B нужен один и тот же runtime/совместимые инструменты и 30–50 независимых сложных задач.

## Проектное решение

| Target ID | Решение | Next gate |
| --- | --- | --- |
| `dsh-runtime` | `DOCUMENTED_CANDIDATE / NO_CODE_ADOPTION` | На копии конкретного source@SHA: измерить настоящие tool_schema tokens, cache hit/miss, recall/precision выбора, tool failures, task correctness, запрещённые tool calls и p95 cost; shadow-mode dynamic + fallback |
| `HermesAgent` | `DOCUMENTED_CANDIDATE / NO_CODE_ADOPTION` | То же в отдельном профиле с неисполняемыми разрешениями и read-only oracle; сначала короткий набор поведенческих A/B без расширения scope |

**Итог BK-021:** `разобран + BOUNDED_PROXY_EXPERIMENT_AND_COUNCIL_EVAL`. Подтверждён потенциал снижения текста контекста и риск ошибочной маршрутизации на синтетике. Проверена реальная связка GLM-5.3-Flash → bounded tools → independent chair; выявлен координационный изъян и конкретная численная ошибка совета. Никаких гарантий переноса авторского Cursor A/B, ускорения роем, экономии реального тарифа, корректной авторизации или production эффективности не получено. **Не внедрять до отдельного controlled held-out model A/B.**
