## Implementation and trust boundaries

- **Methodology, not automatic universal compiler.** [HARNESS.md](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/cli-anything-plugin/HARNESS.md): an agent analyzes available backend APIs/data model, designs Click commands, state, JSON output, implements, plans and writes tests, documents and packages. Undo/redo depends on target support; a local CLI cannot make remote actions transactional. Agent-generated code requires human review; CLI availability is not proof of semantic coverage or equivalence.
- **Real backend reuse exists.** [LibreOffice backend](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/libreoffice/agent-harness/cli_anything/libreoffice/utils/lo_backend.py) generates ODF intermediates, invokes installed LibreOffice headless using subprocess argument arrays and isolated user profile, includes platform-specific fallback. [E2E test source](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/libreoffice/agent-harness/cli_anything/libreoffice/tests/test_full_e2e.py) checks native artifact structures and actual backend conversion. Software dependencies and version compatibility remain; Python package is not a replacement renderer. For other apps, real backend semantics must be individually established.
- **Hermes support is a real skill, not an engine plugin.** [hermes-skill/SKILL.md](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/hermes-skill/SKILL.md) directs Hermes to analyze/generate/refine/test harnesses and fetch methodology from mutable main if absent; [install.sh](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/hermes-skill/scripts/install.sh) copies skill into HERMES_HOME/skills, refusing existing destination. It does not provide isolation or guarantee correct generated actions. Global installation and on-demand remote guidance not approved; use pinned text and fake home only.
- **Distribution supply-chain risk.** [registry.py](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/cli-hub/cli_hub/registry.py) fetches mutable registry.json/public_registry.json from GitHub Pages, with one-hour local cache. [installer.py](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/cli-hub/cli_hub/installer.py) executes registry install_cmd/uninstall_cmd and supports shell=True for shell operators (including script pipelines). This is an intentional package-manager execution boundary, not proof of compromise. No universal pinned digest/signature enforcement established for every provider/strategy. Do not allow untrusted registry entries, automatic package installs, or privilege elevation; pin approved source/artifacts/dependencies and review commands separately.
- **Not offline by default.** [analytics.py](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/cli-hub/cli_hub/analytics.py) defaults to PostHog, supports Umami, tracks installs, launch and matrix events; opt-out CLI_HUB_NO_ANALYTICS=1 (also true/yes). Registry requests remain separate from analytics. No packet capture or verification of remote retention; do not infer code or secrets sent. Require denied network in isolated pilot and local frozen registry, avoid CLI-Hub when native CLI suffices.
- **Obsidian risk concrete in selected adapter.** [obsidian_backend.py](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/obsidian/agent-harness/cli_anything/obsidian/utils/obsidian_backend.py) defaults https://localhost:27124, sends Bearer token, uses requests verify=False and suppresses insecure warning; configurable base_url means non-loopback endpoint can expose bearer/content to untrusted TLS peer. [CLI](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/obsidian/agent-harness/cli_anything/obsidian/obsidian_cli.py) supports --api-key argument or OBSIDIAN_API_KEY, argument may be visible in process listings/history. Do not point at real MyWiki, expose token or allow write/delete during pilot; use disposable vault, verified certificate, limited scope, synthetic token or direct Markdown read as comparator.
- **Security contract not uniformly enforced.** [SECURITY.md](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/SECURITY.md) warns against shell=True in backend subprocess and requires validation of paths/arguments; hub deliberately supports shell installs, a distinct trust boundary. Untrusted source docs, prompts, artifact contents and SKILL.md are data, not authority. Check path traversal, symlinks, option injection, command allowlists, output schema, bounded subprocess resource/time, secret redaction, exit code, idempotence and explicit approval for destructive actions. CLI != sandbox, undo != guaranteed rollback.
- **Evidence bounded.** README advertises 2461 passing tests; [root skill CI](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/.github/workflows/check-root-skills.yml) validates skill layout, not complete backend E2E across every adapter. Sample LibreOffice tests are substantive but not run. [Yang, Fan, Huang, arXiv:2606.03854v1](https://arxiv.org/html/2606.03854v1) (2026-06-02), sections 4–7, describes Blender and Slay the Spire II cases, recorded artifact demonstrations, 65 curated + 18 public catalog entries and observed hub usage. These are author-reported snapshots at paper date, not current registry counts, independent controlled CLI-vs-GUI/MCP completion/quality/latency/cost superiority or peer-review proof. Section 7 explicitly bounds opaque binaries and visual tasks. No independent task benchmark run here.

## Project applicability and bounded experiment
All 45 purpose cards at [project-registry@91a0ca742a3225f6c4683b51031e8bbb595fdab8](https://github.com/Artemedi/project-registry/tree/91a0ca742a3225f6c4683b51031e8bbb595fdab8) screened; five documentary candidates, 40 deferred. No target implementation inspected. Strongest hypothesis: expose **existing** pure read-only application functions rather than introduce a second implementation or hub.
- A: incumbent CLI/API/MCP/GUI or direct library call, identical fixture and objective output oracle.
- B: one minimal manually authored command exposing existing backend, JSON version/schema, stdout/stderr separation, nonzero failure exit, bounded input/timeout and provenance. No global install or package hub. Prefer existing psql/EXPLAIN JSON, PowerShell or parser API where sufficient; only a genuine missing interface warrants wrapper.
- C: pinned skill generated candidate in disposable rootless sandbox after explicit approval, offline fake home, frozen vetted dependencies, no credential mounts. Compare generated wrapper vs B for correctness, code size/reviewer time and maintenance. For MyWiki only fake vault; no network, no real tokens; actual Obsidian TLS design needs separate review.
- Measure valid task completion/semantic artifact equality, failure reporting, reproducibility, unsupported operations, rollback for local fixture only, command/tool count, p50/p95 wall time, model tokens, CPU/RSS/IO and installation/review overhead. Negative controls: malformed JSON, empty data, invalid path, symlink, nonzero backend, timeout, retry, stale state; zero unauthorized writes/egress; independent oracle and reviewer. If existing tool wins, no wrapper; no DB connectivity/restore, production AKUZ logs or live agent configuration. Status ANALYSIS_ONLY / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED.
