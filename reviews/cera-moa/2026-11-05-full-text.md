## Метод, результаты и издержки

Авторы совместно обучают маршрутизатор и политики экспертов: средние hidden states питают familiarity estimator; cumulative-threshold routing активирует небольшой набор экспертов; exploration используется при обучении, но выключается на inference. В базовом эксперименте четыре LoRA-адаптера разделяют Qwen3-4B, в heterogeneous pool используются три разные открытые модели. Это не маршрутизатор поверх закрытых HTTP API.

По авторской OOD-таблице для Qwen3-4B средняя оценка CERA-MoA 72,8 против 71,5 у сильнейшего указанного AT-GRPO; для heterogeneous pool 71,8 против 69,1. Авторы измеряют router latency 11,87 мс на H200. Учебная среда: четыре H200 с 141 ГБ VRAM каждая и около 500 ГБ host RAM; примерно один H200-GPU-day на 1000 шагов в заявленной постановке. Эти значения **не** производственные нормативы и **не** локальные измерения.

## Ограничения и project-fit

В статье маршрутизатор учитывает прежде всего исходный prompt: изменение потребностей по ходу многотурового agent loop не испытано. Для code generation итог часто берётся у одного эксперта, а не объединяется из нескольких; inference архитектура зависит от доступа к hidden states, обучению LoRA и большому GPU-бюджету. Лицензию и полноту авторского training code отдельно не проверяли.
