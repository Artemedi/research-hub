# LAGO × DSH Runtime — проверка и повторное использование вариантов

27 ноября 2026 года

Проверка по контракту решила **72 из 72** синтетических задач при библиотеке из **24 вариантов**. Допуск по одному примеру оставил 48 вариантов и решил только 24 задачи. Полная проверка и объединение сократили библиотеку до 24, но выбор только по имени решил 48 задач. Три повтора дали одинаковые счётчики. [Протокол](../../experiments/lago/2026-11-27-option-admission-protocol.md) · [Данные](../../data/results/lago/2026-11-27-option-admission.json)

| Ветка | Вариантов в библиотеке | Решено из 72 | Выбран вариант с другим контрактом |
| --- | ---: | ---: | ---: |
| Фиксированная библиотека | 12 | 48 | 36 |
| Допуск по одному примеру, выбор по имени | 48 | 24 | 36 |
| Полная проверка и объединение, выбор по имени | 24 | 48 | 36 |
| Та же проверка и объединение, выбор по контракту | 24 | 72 | 0 |

Штатный реестр DSH выбирал один одноимённый вариант по приоритету в проверенном слое. Ветка с одним положительным примером допускала вариант, который обнулял отрицательные значения. Ветка с полной проверкой отклонила 24 варианта и объединила 12 совпадений, но при выборе по имени продолжала скрывать вариант для другого контракта. Этот вариант использовался после явной передачи контракта в отбор. [LAGO, раздел 3.4](https://arxiv.org/html/2610.19843v1#S3.SS4) · [Матрица применимости](../../portfolio/2026-10-12--2026-10-19/project-fit.md)

Совпадение проверено на трёх входах из ограниченного набора. Для произвольных программ такая проверка не устанавливает равенство поведения. Авторский планировщик, реальные навыки, хранение библиотеки и расходы на выполнение за пределами стенда.
