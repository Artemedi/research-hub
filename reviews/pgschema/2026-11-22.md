SSL mode по умолчанию `prefer`, а не `verify-full`.
- **VERIFIED — drift guard:** [`cmd/apply/apply.go:175–189,463–484`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/cmd/apply/apply.go#L175-L189) проверяет source fingerprint **если он есть в JSON-плане**; [`377–401`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/cmd/apply/apply.go#L377-L401) проверяет версию инструмента и формат. План без fingerprint не получает этот guard. Fingerprint не покрывает объём таблиц, данные, WAL, долгие транзакции и состояние реплик; между проверкой и DDL нет доказанной полной сериализации с конкурентным DDL.
- **VERIFIED — транзакционные группы:** [`internal/plan/plan.go:147–234`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/internal/plan/plan.go#L147-L234) группирует транзакционные и изолированные DDL; [`cmd/apply/apply.go:486–568`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/cmd/apply/apply.go#L486-L568) исполняет группы последовательно. Поздний сбой **не откатывает** предыдущие успешно выполненные группы; это не одна атомарная миграция.
- **VERIFIED — online-oriented strategies:** [`internal/plan/rewrite.go:134–160,230–269,272–458`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/internal/plan/rewrite.go#L134-L160) реализует `CREATE INDEX CONCURRENTLY`, `ADD ... NOT VALID` / самостоятельный `VALIDATE`. Для partitioned parent стандартный `CREATE INDEX` остаётся fallback. На PG18 — native NOT NULL constraint с NOT VALID + validate, на PG14–17 — CHECK NOT VALID → VALIDATE → SET NOT NULL → DROP CHECK. «Online» здесь не означает lock-free и не гарантирует отсутствие WAL lag.
- **VERIFIED — lock retries:** [`cmd/apply/apply.go:571–628`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/cmd/apply/apply.go#L571-L628) повторяет SQLSTATE 55P03 с backoff при заданном `lock_timeout`, исключая concurrent index batches из повторов из-за возможности invalid index. Без lock-timeout ожидание acquisition может быть неопределённым; lock-timeout не ограничивает *длительность исполнения* после получения блокировки.
- **VERIFIED — неполный объектный охват:** [`docs/syntax/unsupported.mdx`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/docs/syntax/unsupported.mdx) не поддерживает `RENAME`, ownership, role/database/extension, subscription/publication и ряд других команд. Переименование может породить destructive DROP+CREATE в diff; это кандидат на негативный тест, не утверждение о каждом возможном плане.
- **CI evidence, не runtime evidence:** [`.github/workflows/ci-test.yml`](https://github.com/pgplex/pgschema/blob/1b7eaf2827c84bb3e20679c6bab0c1116bf4e962/.github/workflows/ci-test.yml) запускает `go test -v ./...` на Ubuntu / Go 1.24; README даёт интеграционные тесты с контейнерами. Здесь upstream tests **NOT_RUN**.

## 2. Риски PostgreSQL 15/18 на крупных OLTP

| Операция | Риск | Необходимое доказательство |
| --- | --- | --- |
| `ADD COLUMN ... NOT NULL` на непустой таблице | Показанный в README DDL без DEFAULT/backfill может завершиться ошибкой на заполненных строках | Отдельный синтетический fixture с данными; staged backfill и constraint-validation |
| `ALTER COLUMN TYPE` / другие table rewrite | Длительная сильная блокировка, место под переписанную таблицу, IO/WAL и деградация реплик | Реальный DDL-класс, размер relation/TOAST, WAL bytes, lock graph, скоуп rollback |
| `CREATE INDEX CONCURRENTLY` | Несколько сканирований, ожидание старых snapshot, инвалидный индекс при сбое | `pg_stat_progress_create_index`, `pg_index.indisvalid`, disk/WAL, старые транзакции |
| `ADD ... NOT VALID` и `VALIDATE` | Длинный scan, standby replay conflicts, разделённые commit points | Фиксировать версии PG, длительность lock, standby replay delay, конфликтные запросы |
| `DROP TABLE/COLUMN`, rename | Потеря данных или нарушенный контракт приложения; rename unsupported | Фильтр destructive DDL, owner approval, exact semantic oracle, restore drill |
| Несколько транзакционных групп | Частично применённая миграция, повышенная сложность восстановления | After-step checks, frozen plan, сценарий recover/resume |
| Fingerprint и конкурирующие изменения | Проверка схемы происходит до DDL, не гарантирует эксклюзивное владение всем планом | TOCTOU negative test, контроль параллельных миграций |
| PG physical/logical replication | WAL lag/retention, long queries on hot standby, replication slots | `pg_stat_replication`, WAL rate, slots, conflicts, `pg_stat_wal_receiver` |
| Embedded PG для desired schema | Недоступные third-party extensions, роль/locale/version mismatch | Disposable PG15/18 с pinned extension set и безопасными правами |

PostgreSQL reference: [ALTER TABLE](https://www.postgresql.org/docs/18/sql-altertable.html), [CREATE INDEX](https://www.postgresql.org/docs/18/sql-createindex.html), [locking](https://www.postgresql.org/docs/18/explicit-locking.html), [WAL](https://www.postgresql.org/docs/18/runtime-config-wal.html). Риски — технические свойства выполнения DDL, **не** измеренные локальные инциденты pgschema.

## 3. Проверяемая методология и A/B/C

**H1:** отдельная генерация декларативного плана с независимой DBA-оценкой повышает точность и снижает цену разработки миграций при неизменных правилах безопасности относительно ручных migration scripts. **H0:** автоматический diff не экономит DBA-время или вносит слишком много неочевидных destructive/lock-sensitive действий.

- **A:** вручную подготовленный, версионированный SQL с DBA review и валидированным ожидаемым состоянием.
- **B:** `pgschema plan` в синтетической локальной PG15/18 лаборатории, ручной SQL/JSON review **без apply**. Сравнить с A обязательные/лишние DDL, риски и review effort.
- **C:** тот же pinned generated plan на disposable PG15/18 с synthetic data, специально подготовленным lock contention, WAL и dummy standby. Выполнять только после изолированного security review и отдельного human gate; **не выполнялось**.
- **Oracle:** независимый PostgreSQL catalog diff, точный набор объектов/constraints/indexes/grants, data checksums, ошибки SQLSTATE, отсутствие незапрошенных drops, time bound/recoverability. Не считать `exit 0` достаточной проверкой.
- **Метрики:** precision/recall DDL, incident/false-positive destructive actions, accepted DBA plans, время review, access-exclusive lock duration, elapsed, p50/p95, IO/WAL, peak disk, replay lag/conflicts, cost.
- **Изоляция:** rootless Podman без сети и host PG socket, synthetic fixtures, фиксированные source/input hashes и лимиты CPU/RAM/IO/time, no external credentials. Никаких `apply` к production и реальным AKUZ репликам.
- **Predeclared acceptance:** не допустить незаявленные destructive changes, 100% точного каталога/data oracle для принятых тестов, отсутствие неоправданных блокировок относительно A, доказанная экономия review effort; при провале — `NO_BENEFIT / NOT_APPLICABLE`, не подменять эффект авторскими примерами.
