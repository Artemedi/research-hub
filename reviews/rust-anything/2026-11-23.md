# rust-anything — bounded engineering review: агентный Rust-port и границы доказательства

**Дата:** 2026-11-23. **Pinned source:** [`erkamyaman/rust-anything@50d3810b622fdc6cb3aee965fe4c9d4b4f29205b`](https://github.com/erkamyaman/rust-anything/tree/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b), [MIT LICENSE](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/LICENSE). **Scope:** `BOUNDED_CODE_REVIEW`, не external audit, не автоматический translator qualification, не независимый benchmark. Пользовательский тезис: «переносим любое приложение на Rust; 10–20× быстрее».

## 1. Что действительно реализовано

Изучены pinned README, Cargo.toml, LICENSE, `DECISIONS.md`, `docs/{how-it-works,whole-apps,real-world}.md`, `src/{go,bridge,recording,gate,effects,profile,harness,setup,enable,app,front_door,lift}.rs`, language adapters и CI. Просмотрены исходники и тесты как текст; никакой сторонний Rust executable, agent loop, setup, бенчмарк или real app rewrite не запускались.

- **VERIFIED — не translator:** [README](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/README.md) прямо указывает, что Rust пишет **Claude/Codex/человек**, а не сам rust-anything. Алгоритм: `profile → bridge → record → agent port → diff → gate → bench → enable`; whole-app дополнительно требует front-door, wire/lift, fallback и отдельные интеграционные тесты. `go --agent` ускоряет именно этот workflow.
- **VERIFIED — source-language wrappers:** language adapters TS/JS (napi/wasm), Python (PyO3), C (C ABI), Go (cgo), Ruby, Java/Kotlin (JNI), PHP (FFI), C# (P/Invoke) различаются семантикой, FFI/allocator cost, поддерживаемыми типами; [`src/bridge.rs`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/src/bridge.rs), [`DECISIONS.md`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/DECISIONS.md) ограничивают не-portable объекты: структуры с указателями, GUI/event-loop, async/deferred object lifetimes, dynamic semantics нельзя считать автоматически переписываемыми. PHP/C# support ограничен static/top-level units, не всем .NET/PHP окружением.
- **VERIFIED — gate ограничен корпусом:** [`src/gate.rs:222–351`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/src/gate.rs#L222-L351) проверяет fmt/clippy/cargo test, build, stubs, API и recorded diff, stale fingerprint; но coverage записывается с `passed:true` как информационный пункт, не как минимальный threshold. [`docs/how-it-works.md:176–211`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/docs/how-it-works.md#L176-L211) прямо признаёт: проход равен совпадению на записанных входах, **не** доказательству эквивалентности всех программных состояний.
- **VERIFIED — слабые места oracle:** nondeterministic output может быть masked (время/ID) и reordered; при разном количестве строк wildcard `...` может сравнивать широкие варианты. [`src/recording.rs:361–432`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/src/recording.rs#L361-L432) позволяет объяснённые `known-diffs` принимать как passed, это policy exception; обязательны reject/owner review, иначе 100% `gate` не даёт 100% byte-equivalence вне разрешённых отклонений. Исключения ошибок могут сравниваться по типу, не полному сообщению.
- **VERIFIED — side effects/record risk:** [README warning](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/README.md) сообщает, что `record` и `app record` многократно **выполняют исходный код**; `diff`, `gate`, replay тоже запускают код. Если приложение обращается к БД, файлам или сети, операции повторяются. [`src/effects.rs`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/src/effects.rs) реализует опциональные HTTP/SMTP sinks; [`docs/whole-apps.md`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/docs/whole-apps.md) — `--db-reset`/`--db-dump`, но message queues, local sockets, signals и внешние секреты **не** становятся автоматически наблюдаемыми. Side-effect contracts необходимо задавать явно и запускать без production credentials.
- **VERIFIED — агентные полномочия:** [`src/go.rs:213–237`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/src/go.rs#L213-L237) создаёт headless Claude `acceptEdits` с разрешёнными Bash(cargo/rust-anything) и Codex `exec --full-auto`. Это не гарантированный bounded sandbox/allowlist на уровне ОС; одевая wrapper через agents, нельзя передавать доступ к AKUZ production.
- **VERIFIED — speed vs correctness:** [`src/go.rs:444–469`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/src/go.rs#L444-L469) вызывает `bench` после gate и не разрешает `go` автоматически включить заведомо медленный порт (`speedup < 1`). Отдельный `gate` не проверяет достижение performance SLO.
- **AUTHOR_REPORTED benchmarks:** [README](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/README.md) и [`docs/real-world.md`](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/docs/real-world.md): Prettier CLI JS/TS 2360 files 128.6→6.9s (~19×), Fuse.js search 50k 91.2→2.8ms (~32×); `vercel/ms` per-call 0.56×, batch parse 100k=18× excluding bridge setup but 3.4× including crossing; `format` 0.8×. `libavutil` from C roughly C speed, 16 benchmarks slower by 3–40%. Prettier full Rust coverage **15,861 of 17,224 cases**, rest fallback to original; aggregate byte equality does not mean entirely Rust. Prettier/CLI performance on Apple M4 with two repetitions, not independent deployment-qualified confidence interval or cross-platform performance.
- **VERIFIED — release/test controls:** [CI](https://github.com/erkamyaman/rust-anything/blob/50d3810b622fdc6cb3aee965fe4c9d4b4f29205b/.github/workflows/ci.yml) runs cargo fmt/clippy/test plus Mac/Windows bridge lanes, demos. `setup` changes installed agent MCP/skill configuration and makes `.rust-anything.bak` backups; **не** запускать globally without consent and reviewing diff. Rust/native toolchain and source-language runtime are required. Windows kernel/desktop OS migration, unsafe drivers, hardware-facing C and privileged APIs remain **OUT_OF_SCOPE**.

## 2. Производственная релевантность и tradeoffs

| Область | Возможная польза | Стоимость/опасность | Отрицательный тест |
| --- | --- | --- | --- |
| CPU-bound parsing/classify/normalize | Небольшой Rust hot loop может уменьшить CPU на повторяемом большом наборе | PyO3 conversion + GIL/marshalling, platform wheels, memory copies, source-compatibility, cache/release overhead | малые payload; unicode/cyrillic; regex, invalid UTF-8, huge multiline events; numbers/locales |
| Python I/O/SQLite | Rust не ускоряет network/SMB/SSH, индексы SQLite или задержку storage | FFI/Bundling increases complexity without speed benefit | A/B full pipeline wall with same disk/cache and SSH disabled |
| Native ABI | Возможность не переносить весь процесс | бинарные подписи/PyO3 ABI, Windows portable packaging, architecture, toolchain, build reproducibility | portable Windows startup/smoke and strict fallback |
| Recorded equivalence | regression coverage for observed cases | input coverage holes, masking/known diffs, errors/non-stdout effects | property/metamorphic tests independent from original, mutation testing, no silent wildcard |
| Semantic data integrity | byte/field-level parity can be checked | PHI/PII, dedup, double writes, transaction retries, operator side effects not all captured | untouched source, no prod credentials, synthetic fixtures, DB exactly-once and exception classes |
| Whole-app rewrite | potential lower memory/startup | migration of all integrations, UI, protocol/security, unmaintained native library | reject unless quantified benefit + full integration and platform conformance |

## 3. A/B/C protocol — NOT RUN

**H1:** исходно подтверждённый CPU-dominant Python hot path (а не любое приложение) может быть перенесён на Rust через PyO3 и уменьшить CPU/wall при exact result equivalence и сопоставимом RSS/IO. **H0:** FFI/batching/packaging overhead и семантический drift не дают надежного полного выигрыша.

- **A (baseline):** pinned `akuzlogparser` Python code with existing performance instrumentation; isolated synthetic fixture and frozen CPU profile/CPU flame graph. Сначала *доказать* что именно Python loop dominates wall time, а не SSH/download, JSON serialization, SQLite, I/O.
- **B (manual controlled):** тот же выбранный hot path rewritten by human/agent without rust-anything, only on disposable branch, independent fixtures and wrapper parity; сравнить effort и artifacts.
- **C (tool-assisted):** `rust-anything analyze/profile/bridge` plus agent in **offline rootless Podman** with network=none / isolated HOME, read-only target snapshot and writable scratch, pinned Rust/Cargo + Python, synthetic fixtures only. Use `record/diff/fuzz/gate/bench`, but **do not** allow `setup` global configs, `enable` original product code or push. Host-independent comparison checks all event/raw/bytes/field hashes, exceptions, errors and no side-effects. Build Windows artifact only in separate explicit pilot after C.
- **Fixture:** 100k/1M events, 1MiB+ lines, Windows/Linux newline, Cyrillic/non-ASCII, malformed/partial and timestamp-crossing, duplicate/out-of-order, exceptions nested, env effects, negative and time-bound cases. Predeclared test generator, fixed seeds and independent property oracle before agent runs, same host/CPU affinity, warmups, >=5 repetitions and blinded acceptance.
- **Metrics:** whole-pipeline p50/p95 wall, CPU seconds, RSS max and allocation, input/output hash and event count, FFI crossings per event, throughput MB/s, IO and disk footprint, build/setup size, platform portability, maintenance cost and review minutes. Per-function headline speedup is insufficient.
- **Gate:** 100% exact existing/golden synthetic event bytes on approved cases; no unknown wildcards or accepted known diffs in safety-sensitive fields; no writes/network/remote access; total pipeline improvement beyond noise and operational complexity justified; otherwise `NO_BENEFIT/NOT_APPLICABLE`. Baseline owner approval before any actual Rust execution or edits of a source repo.

**Decision:** `DOCUMENTED_CANDIDATE / NEEDS_EVIDENCE / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED`. Test first for correctness and CPU impact, stop if profile shows IO dominance.
