# Agent Error Dataset — парный повтор запросов Wiki_PG

В 24 синтетических сценариях исходный повтор каждый раз возвращал прежнюю ошибку. Когда задача однозначно называла нужный порт или регион, запрос с одним исправленным полем вернул точный ответ в 8 из 8 случаев. В остальных 16 сценариях стенд воздержался от коррекции. Python API и штатный MCP stdio дали одинаковую сводку, которую подтвердил повтор всей серии.

## Метод и результат

Парное сравнение из Agent Error Dataset сохраняет общий исходный снимок и меняет только действие. Здесь такой снимок — временная публикация SQLite, построенная штатным сборщиком Wiki_PG из трёх искусственных JSON. [Статья v2, §3.2](https://arxiv.org/html/2609.40111v2#S3.SS2) · [Предыдущий локальный опыт](2026-11-08-checkpoint-replay-ab.md)

Штатный `SystemQueries.state` в `Wiki_PG@d55721bb99bff25fae352341cfd630c048693d6b` требует порт для запроса уровня экземпляра. При одинаковом имени хоста в разных регионах он требует регион. Стенд связывал ошибку с ID вызова и брал единственное явно указанное значение из контекста этого вызова. Диагноз, правило выбора и типы контекста заранее заданы протоколом. [Проверка входа и выбор области](https://github.com/Artemedi/Wiki_PG/blob/d55721bb99bff25fae352341cfd630c048693d6b/Wiki_PG/ingestion/system_queries.py#L239-L292) · [Разрешение имени хоста](https://github.com/Artemedi/Wiki_PG/blob/d55721bb99bff25fae352341cfd630c048693d6b/Wiki_PG/ingestion/system_queries.py#L51-L63)

| Проверка | Результат для каждого интерфейса за прогон |
| --- | --- |
| Исходный повтор подтвердил ту же ошибку | 24/24 |
| Коррекция явно указанного порта | 4/4 |
| Коррекция явно указанного региона | 4/4 |
| Воздержание при пропуске, конфликте или подсказке для другого действия | 16/16 |
| Допустимый, но неверный порт или регион обнаружен оракулом | 8/8 |
| SQLite и исходные файлы после всех вызовов | SHA-256 совпали |

Оракул читал исходные JSON независимо от парсера Wiki_PG и сверял версию, порт, регион, время и хеш источника. Неверный селектор тоже возвращал штатный ответ `ok`. Проверка происхождения факта обнаружила все восемь таких ответов.

MCP вернул общий код `invalid_request`, сохранив конкретную причину в структурированном сообщении. ID каждого JSON-RPC ответа совпал с ID вызова. Правило коррекции всё ещё зависит от точного текста ошибки. Одного общего кода для выбора поля недостаточно. Сервер работал отдельным stdio-процессом, читал временную публикацию и получал только путь к ней и параметры локальной среды.

Для повтора запустите `python -B experiments/agent-error-dataset/wiki-pg-paired-replay.py ПУТЬ_К_WIKI_PG` в Linux или WSL. Серия записана на Python 3.12.16 с закреплёнными в Wiki_PG пакетами `mcp==1.28.1`, `PyYAML==6.0.3` и `requests==2.34.2`.
