# BenchShield — как Paper2Project различает исход опыта и полноту доказательств

25 ноября 2026 года штатные JSON- и Markdown-отчёты Paper2Project совпали с ожидаемыми решениями в **28 из 28 сценариев**. При этом отсутствие сохранённых фактов и числовое расхождение получили одинаковое решение `EXPERIMENT_FAILED`. Причину первого случая можно увидеть в JSON. Markdown её не показывает.

## Проверка

В BenchShield исход задачи и вывод о достаточности инфраструктурных доказательств имеют разные вердикты. Например, неполные сведения оставляют вывод о целостности открытым. Более ранний [локальный replay](2026-11-04.md) проверял эту идею на самостоятельной модели, без чтения кода Paper2Project. [BenchShield, §4.5](https://arxiv.org/html/2609.11028v1#S4.SS5)

В текущем тесте использованы `dsh-paper2agent@c3bbe09bddf54b0efdcc0da1f17e1446dd35a4fd` и штатные пути `App.report` и `execution.runs`. Идентичность опыта и факты сравнения читаются из объектов с проверяемым хешем. Стенд зарегистрировал семь семейств по четыре варианта. Эталон вычислял сумму из отдельного файла с числами. Ни один исполняемый опыт не запускался. [Датированный протокол](../../experiments/benchshield/2026-11-25-paper2project-protocol.md) · [Сценарий](../../experiments/benchshield/paper2project-report-replay.py)

| Наблюдение | Результат за прогон |
| --- | --- |
| Совпадение JSON и Markdown с эталоном статусов и решений | 28/28 |
| Совпадение значений и флагов проверок в завершённых числовых сценариях | 8/8 |
| Одинаковое решение и объяснение у отсутствующих фактов и числового расхождения | 8/8 |
| Наличие причины в JSON у неполной записи, прерванного или заблокированного опыта и старого формата | 16/16 |
| Та же строка причины в Markdown для этих 16 записей | 0/16 |
