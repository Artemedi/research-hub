# Harness² — выбор финального результата при ошибке

26 ноября 2026 года

Штатные функции Harness² прошли **8 сценариев × 3 повтора** на Python 3.12.16. При ошибке выбора в режиме готовых финальных вариантов сохранялся первый доступный по имени вариант. Запись указывала, что выбор завершился с ошибкой. При корректном идентификаторе селектор мог принять неверный ответ и записать `ok=true`. [Протокол](../../experiments/harness2/2026-11-26-final-selection-protocol.md) · [Результат](../../data/results/harness2/2026-11-26-final-selection.json) · [Исходная реализация](https://github.com/google-research/harness2/blob/6868817518876de8fd170c6a8354daca273b6191/harness2/core/selection.py)

| Сценарий | Результат |
| --- | --- |
| Корректный идентификатор | Сохраняется указанный ответ. Арифметическую правильность проверяет внешний эталон. |
| Нет блока выбора, указан неизвестный идентификатор или передана ошибка провайдера | Сохраняется первый доступный финал. Запись содержит `fallback=true`, `ok=false` и условную стоимость попытки. |
| Первый вариант не доставлен | Резервный выбор использует следующий доступный. |
| Нет доставленных вариантов | Селектор не вызывается. Запись о выбранном результате отсутствует. |
| Единственный доставленный финал в режиме k=1 | Вариант сохраняется без обращения к селектору. |

При неверном ответе или ошибке подставной модели исходный вариант с правильным ответом оставался вне пула финалов. Это соответствует устройству опубликованного метода. Для **agent-config** перед принятием результата нужна независимая проверка исходного и выбранного вариантов. Для **dsh-runtime** такой выбор имело бы смысл испытывать после определения внешнего критерия качества и бюджета всей цепочки. Условные расходы в этом тесте относятся только к селектору. Тест охватывает выбор из готовых ответов. Этапы Propose, Probe и Compose, реальные запросы и перенос в рабочие проекты остались вне прогона. [Прежний обзор](2026-11-05-full-text.md)
