## 2. Действительная схема компрессии (AUTHOR_REPORTED + статическая сверка кода)

1. Текст обратимо преобразуется в token stream (включая `preprocess.c` и vocabulary); Transformer выдаёт probability distribution следующего токена. **Предиктор один**, но конвейер не состоит из одной нейросети: препроцессор и арифметический кодер обязательны.
2. Арифметическое кодирование использует вероятности для кодирования фактического символа. После раскрытия символа обе стороны выполняют одинаковые online gradient/Adam steps и дополнительный replay. Сжатые биты не заменяются весами online-trained модели, поскольку декодер восстанавливает их последовательными обновлениями.
3. **v1:** одинаковый seed и random initialization без переноса предварительно выученных весов. 12-layer 163M decoder-only Transformer, 4K vocabulary, 192-token context, 35M-token replay и dropout 0.25. Размер payload **105 924 360 B** + decoder **54 709 B** = **105 979 069 B** (0.848 bits/byte).
4. **v2:** стартовое состояние не выводится только из seed: offline-trained 34M Cycle2 prior квантован до `weights.bin` **4 334 741 B**. Два trained blocks повторяются на 12 depth positions и становятся независимыми online layers. Payload **100 958 324 B** + decoder/vocabulary/initial weights ZIP **4 430 029 B** = **105 388 353 B** (0.8431 bits/byte). Выигрыш против v1 **590 716 B**, около **0.56%**, а не 4.97 MB чистой экономии; 4.97 MB — сокращение только payload до учёта prior.
5. Верность определяется **битовой идентичностью** predictor/state updates и quantized probabilities: одинаковый seed сам по себе недостаточен для v2 без точных weights, версии runtime, GPU и словаря. Pinned `nn.py:910–914` включает deterministic algorithms и seeds, `nn.py:515–626` проверяет prior provenance, `nn.py:1007–1010` заводит отдельные Adam optimizer states, `nn.py:1135–1199` выбирает compression/decompression и resume. Это **статическая проверка реализации**, не успешный кросс-аппаратный round-trip.

## 3. Результаты, стоимость, ограничения

| Конфигурация (авторы / leaderboard) | Payload bytes | Decoder incl. prior | Score total bytes |
| --- | ---: | ---: | ---: |
| v1 online-only | 105 924 360 | 54 709 | 105 979 069 |
| v2 pretrained Cycle2 + online | 100 958 324 | 4 430 029 | 105 388 353 |
| L6 prior (из author study) | 99.173 MB | 10.945 MB | 110.118 MB |

- **Время v2:** ~631 548 s на сжатие (7.31 суток, без отдельного offline pretraining) и ~645 748 s на декодирование (7.47 суток). Декодирование — снова обучение модели, а не дешёвый reverse dictionary pass. В official table указан расход **73 748 MiB для v1**, тогда как отдельная ячейка памяти v2 не заполнена; приписывать v2 точные 74 GB измеренной RAM некорректно.
- Авторский `README.md` требует ровно 2× NVIDIA B200 GPUs / Linux x86-64 / CUDA 13.0 / cuDNN 9.20 / Python 3.12.3 / PyTorch 2.12.0+cu130. Launcher `tufazip:44–64` валидирует точные версии и GPU, `tufazip:75–145` — SHA-256 archive, weights, vocabulary, post-decoded token stream и 1e9 bytes output. Это жёсткая граница переносимости, не оценённое поведение на иных GPU.
- Авторские ablations: увеличение replay с 15M до 35M tokens сэкономило 1.30 MB payload при ~+40% model FLOPs, 7.45e19 → 1.04e20; 4K tokenizer оказался лучше 8K/16K в выбранных настройках; больше параметров не всегда лучше. Результаты зависят от фиксированного benchmark и многоразовой настройки рецепта на enwik8/enwik9.
- **Воспроизводимость ограничена:** опубликованный `tufazip` launcher обслуживает декодирование **одного enwik9-v2.bin** с известным hash. В `nn.py` есть encoding path, но нет подтверждённого универсального CLI/публичного полного training pipeline для произвольного пользовательского набора. Сам `enwik9-v2.bin` отсутствует в tracked source repository. Не представлять это как готовый archival plugin. Код upstream и конечная проверка SHA не являются независимой воспроизведённой проверкой.
- **Security/robustness:** чужой код/зависимости не исполнялись, поэтому контейнерная безопасность, handling corrupted bitstreams, cross-device determinism, ресурсы/stop/resume под сбоем, arbitrary corpus support и стабильность optimizer на железе пользователя `UNKNOWN / NOT_RUN`. Препроцессор использует изменённый внешний исходный алгоритм — «одна нейросеть» относится к predictor stage, не к полной трансформации данных.
- Метрика enwik9 одна: хорошее lossless text bit rate **не доказывает** улучшения agent reasoning, compression of embeddings, semantic retrieval или checkpoint/storage latency; Goodhart/selection risks обсуждаются самим автором.

## 5. Условие возврата к оценке

Вернуться к TufaZip лишь если появится **конкретный проект** с неизменяемым холодным текстовым корпусом, где важнее плотность на ~0.5 MB за 1 GB, чем время/стоимость чтения; доказанный GPU-runtime, бюджет воспроизведения, независимый oracle полного восстановления и baseline `zstd`/другие современные lossless algorithms. Минимальный тест без двух B200 следует выполнять только на **самостоятельной CPU toy-реализации идеи online probability + arithmetic coding**, явно не называя его проверкой TufaZip v2. Запуск upstream `weights.bin`/GPU experiments требует отдельного owner approval и безопасной среды. Любой эффект требует сравнения end-to-end, не только сжатых байтов.
