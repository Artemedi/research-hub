## 2. Обобщённая методология, конкуренты и гипотеза

**Helmor != gnhf.** Helmor организует **параллельное интерактивное выполнение и ручную приёмку** в одном UI; gnhf ориентирован на автоматические последовательные bounded iterations с журналом. Оба используют Git, но ни один не превращает Git в security sandbox и не заменяет независимый oracle. Helmor не считать готовой реализацией всего DSH runtime или Paper2Project.

**H1:** единая операторская рабочая станция с параллельными worktree/agent sessions и отчётливой review/ship границей повышает число корректно завершённых задач на единицу операторского времени по сравнению с раздельными CLI/IDE/terminal без утраты безопасности. **H0:** дополнительное UI и сложность установки не дают выигрыша, создают ошибки выбора ветки, небезопасные права и шум review.

**Незапущенный план A/B/C:**
- **A:** штатный оператор — CLI agents + вручную создаваемые Git worktrees + отдельный diff/IDE/PR review.
- **B:** Helmor GUI на **официально поддерживаемой тестовой ОС** с отключёнными cloud companion и real credentials, fake/stub agent, синтетическими Git-repo fixtures, без `ship`.
- **C:** Helmor CLI/MCP управляет теми же рабочими задачами, но публикация/merge **заблокированы внешним независимым reviewer gate**. Для сравнения A/B/C должны работать на одном и том же поддерживаемом host/fixture; Linux/Bazzite нельзя подменять неподтверждённым портом.
- Предварительно 12–20 одинаковых задач с конфликтующими правками; immutable fixtures, независимые unit/CI oracles, пути allowlist, проверка hardlink/symlink/shared git refs, adversarial `plan` mode attempts, worktree/local confusion, malicious prompt, failed test, wrong PR target, accidental push, restart/recovery, invalid session state.
- **Метрики:** `accepted_valid_tasks/operator-hour`, успешность независимых тестов, conflict rate, reviewer time, time to PR, неверные merge/branch actions, dangerous execution count, leakage attempts, peak CPU/RAM/IO, токены/стоимость, memory usage при N параллельных agents, resumption correctness.
- **Safety constraints:** disposable isolated virtual machine/container with independent user + HOME/Git credential store, no real repos/SSH/GitHub tokens, no external model API (stub agent), network blocked, explicit branch/PR allowlist and no publishing. Worktree не использовать как основной sandbox. No production changes. Запуск третьего бинарника после audit/human gate.
- **Accept:** no unauthorized file/branch writes or remote side effects, 100% oracle correctness for accepted tasks, measurable operator overhead reduction without increased risk, A/B/C cost parity; иначе `NEEDS_EVIDENCE` либо `NOT_APPLICABLE`.

## 3. Project fit: документальная оценка

Отправная точка [`Artemedi/project-registry@7a976c353579f8da64789daf18fe1088e5ab8dbb`](https://github.com/Artemedi/project-registry/tree/7a976c353579f8da64789daf18fe1088e5ab8dbb) — 45 проектов, purpose/stack screening. Три условные цели, **ни одна не получила VERIFIED integration seam**:

- **`dsh-runtime`:** из реестра известно о собственном agent runtime, workspace/web и плагинной архитектуре. Проверять только *операторскую производительность* интерфейса и parallel task hygiene относительно штатного CLI; Helmor не считать частью DSH core. Код, тесты и внутренние пути приватного проекта в публичный research hub не копируются.
- **`agent-config`:** политика агентов и независимое ревью как источник требований к permission gate, source allowlist и защищённому запуску. Не устанавливать Claude/Codex full-access по умолчанию и не передавать конфиги с ключами.
- **`dsh-paper2agent`:** контекст для review/owner gate результатов исследовательских экспериментов; интерфейс Helmor может быть только optional developer/operator UI, но не меняет научный evidence protocol и не получает право bypass Podman.
- Остальные 42 — deferred screening, не blanket NO_FIT. На этом этапе нет доказанного потребителя Helmor MCP API, интеграционного патча и кросс-ОС воспроизводимости.

**Решение:** `DOCUMENTED_CANDIDATE / NEEDS_EVIDENCE / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED`. Linux official binary недоступен по README; рабочие исходники проектов и production **не менялись**.
