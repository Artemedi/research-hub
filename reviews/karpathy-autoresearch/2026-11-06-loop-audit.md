Различия нельзя интерпретировать как эффект метода: B преднамеренно исполняет два раунда, а A один; `n=3` для tail-latency недостаточно. CPU агрегирован по subprocesses, disk IO НЕ измерялся, GPU/VRAM не применимы, LLM calls 0, cost USD 0 в игрушечном тесте, tokens `N/A`. Включена внешняя процедура проверки с неизменным expectation, не доступная как approved test в A. **Все 6 исходных locked suites до разработки были RED** по отсутствующей функции.

**Что доказано:** при наличии пробела в oracle даже успешно отработавший реальный loop может принять неполную реализацию. Зафиксированные approved tests, restore-before-judge и внешний integration check на этом toy-case не дали фиктивному агенту ослабить сами тесты. Эти наблюдения воспроизводимы **только в указанном контуре**. Не доказаны реальное skill selection, успех автономных моделей, 10x, безопасность против агента с shell, качество переобучающего `auto-loop`, уровень ошибок на реальных проектах.

## 4. Security и методологические ограничения

- `autoloop.sh` по умолчанию содержит `AGENT_CMD='claude -p --dangerously-skip-permissions --output-format json'`. Документация Wiki_PG сама предупреждает, что *worktree не sandbox* и имеет доступ к пользовательской среде. В безопасном тесте команда была заменена фиктивным скриптом; **не запускали** дефолтного агента.
- Восстановление `tests/` не защищает внешний `PYTHON`/`venv`, который по умолчанию находится в основном checkout. Документация прямо называет возможность модифицировать interpreter/site-packages вне `tests/`. Hash Git-коммита — audit trail, не security boundary против того же OS user. Для сильной защиты требуется отдельный principal/container с read-only/host-owned frozen oracle, изоляцией окружения и секретов; эту границу **в эксперименте не доказывали**.
- Автоматическое переписывание уроков может приобрести *self-confirming bias*, overfit к видимому oracle и распространить неподтверждённый совет. Внешний frozen validation/heldout и human review для governance — обязательные до внедрения. В самом сценарии B нет моделирования получения навыка из наблюдений: второй шаг исправления заранее запрограммирован.
- «Все тесты зелёные» не означает, что новая функциональность подключена к настоящему UI/MCP/CLI пути. Каждый релевантный end-to-end и negative scenario должен быть закреплён **до** разработки. Критерий проверки должен идти от требований, а не от агентной реализации.
- `program.md` оригинала содержит предписание `NEVER STOP`; переносить без budget/stop gate нельзя. Wiki_PG ограничен `MAX_ROUNDS=5`, `AGENT_TIMEOUT=1800`, что снижает риск неограниченных расходов, но не доказывает hard resource isolation.

## 6. Решение, измерительные gates и статус

1. Для **BK-034 есть достаточно full primary engineering material и пользовательского текста**, чтобы провести адресный разбор. Оригинальное видео и исходный Claude Code setup AI LABS **остаются неподтверждёнными**, а заявленные цифры `10x` и рассказ о 700/20/19% **не считаются воспроизведёнными**.
2. **Ограниченный эксперимент проведён** над текущим, реальным, pinned `Wiki_PG/scripts/autoloop.sh` с synthetic fake agent и frozen toy-judges: два важнейших эффекта — ложное принятие при узком oracle и отклонение попытки упростить утверждённые проверки — показаны в 3× каждой ветки. Поэтому можно ставить `проверен экспериментально` **только в смысле BOUNDED_LAB_SCRIPTED_WIKIPG_LOOP**; никакой вывод о 10x/LLM agent-generalization не следует.
3. **YAGNI:** не строить новый orchestrator и не менять source проекта. Следующий самостоятельный experimental gate — реальные обезличенные функции Wiki_PG: baseline проверок vs дополненные entrypoint + hidden tests, несколько независимых задач и модельных повторов, логировать pass/false-accept, скилл-ошибки, latency, token/cost, CPU/RAM/IO. Вызов real Claude/производственный rollout — отдельное разрешение.
4. Данные происхождения/проверки содержатся в repo commit, pinned source, runner и raw JSON. Во время этого обзора не изменены `Wiki_PG`, `agent-skills`, `dsh-runtime`, работающие Hermes, PostgreSQL/MSSQL или реальные пользовательские секреты.
