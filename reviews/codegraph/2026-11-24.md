# CodeGraph — pinned bounded code audit, telemetry and benchmark interpretation

**Date:** 2026-11-24. **Pinned:** [`colbymchenry/codegraph@73c6cff66e525a92bff65675b6b0c46687e91ef1`](https://github.com/colbymchenry/codegraph/tree/73c6cff66e525a92bff65675b6b0c46687e91ef1), commit 2026-11-23, `@colbymchenry/codegraph` version 1.6.4, MIT. **Scope:** `BOUNDED_CODE_REVIEW` on pinned README, MIT license, `package.json`, `AGENTS.md`, source `src/index.ts`, extraction/graph/MCP/sync/installer/telemetry modules, Rust kernel entry and local benchmark docs. Over 900 test source files exist; **not run** and not exhaustive line-by-line code audit. No installation, compiled third-party code execution, build or independent model calls. Upstream has Rust and TypeScript, database schema and a real test suite: not a shallow README-only project.

## 1. Implementation and limits

- **VERIFIED — pre-indexed static graph.** The [`CodeGraph` API](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/index.ts) offers `indexAll`, `sync`, `watch`, `searchNodes`, callers/callees, blast-radius and context building. The pipeline is AST tree-sitter (+ Rust kernel when available) → symbol/import/call extraction → cross-file resolution and route synthesis → [SQLite with FTS5](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/db/schema.sql) → query/traversal → formatted code snippets via MCP. Structural claims are linked to code, not LLM-generated summaries. Graph quality still depends on parser coverage, alias resolution, dynamic dispatch and incomplete build information; `symbol graph` is not a sound whole-program call graph.
- **VERIFIED — supported useful languages, but DB gap.** [`src/extraction/languages/{csharp,typescript,python}.ts`](https://github.com/colbymchenry/codegraph/tree/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/extraction/languages) implement C#/TS/Python extraction. A T-SQL or PostgreSQL PL/pgSQL semantic parser, catalog/plan binding, temp-table semantics, stored procedure execution graphs or SQL Server dynamic `EXEC()` lineage were **not identified** in source's first-class language extractors. `src/extraction/index.ts` comments `.sql` may be indexed as "code-ish", but that does not establish SQL **semantic extraction**. Reflection, runtime DI and generated SQL are also outside static proof. Do not market CodeGraph as SQL Server database dependency-lineage analyzer for AKUZ. For C# calling SQL, independent expected edges/entry points are needed.
- **VERIFIED — best-effort freshness, not perfect watcher guarantee.** `src/sync/watcher.ts` and [watch policy](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/sync/watch-policy.ts) rely on a running watcher and inotify/fs.watch semantics, disabled by `CODEGRAPH_NO_WATCH=1` or WSL2 mounted Windows drive for reliability reasons. Sync may be delayed by a debounce, crash, unavailable daemon, disabled watch or cross-project worktree. [`src/mcp/answer-freshness.ts`](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/mcp/answer-freshness.ts) protects against stale source with SHA-256 hash for contributing files, but bounds it to 200 files / 8 MiB / 250 ms and lists extra paths as `unchecked`; this is fail-unknown rather than all-or-nothing proof. `src/mcp/index-freshness.ts` limits background measurements to two workers, 8s timeout; not a universal eventual-freshness SLA. Multi-branch tests must pin root+commit and verify graph matches exact tree.
- **VERIFIED — local engine and telemetry contradiction.** [`TELEMETRY.md`](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/TELEMETRY.md) and [`src/telemetry/index.ts`](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/telemetry/index.ts) show **enabled-by-default** anonymous `install/index/usage_rollup/uninstall` stats, POST to `telemetry.getcodegraph.com`, a pseudorandom machine identifier, and an independent once-a-day GitHub release check. README says "100% local" and "no data leaves your machine"; those statements do not encompass default telemetry/update egress. Upstream docs assert no source/path/symbol/query in transmitted telemetry; no independent packet-level/proxy trace or external receiver verification was conducted. Controls `DO_NOT_TRACK=1` (highest priority), `CODEGRAPH_TELEMETRY=0`, `CODEGRAPH_NO_UPDATE_CHECK=1` (only update check), `--no-telemetry` for MCP. Env `CODEGRAPH_TELEMETRY=1` overrides stored opt-out unless `DO_NOT_TRACK=1` is set. For highly sensitive corpora also deny outbound by OS/network namespace. Separate LLM agent interactions may forward returned source snippets externally; CodeGraph local indexing does not make the *coding session* confidential.
- **VERIFIED — installer modifies live agent config.** [`src/installer/targets/hermes.ts`](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/installer/targets/hermes.ts) writes top-level `mcp_servers.codegraph` into `$HERMES_HOME/config.yaml`; has a specific compatibility safeguard: avoid changing `platform_toolsets` because in prior Hermes versions and allowlist interpretation this broke other MCP services. User-defined `codegraph` entries are left untouched. [`src/installer/targets/dsh.ts`](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/installer/targets/dsh.ts) edits `$DSH_HOME/cordis.patch.yml` and `AGENTS.md`, and [Claude target](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/src/installer/targets/claude.ts) changes MCP/hook configuration. These are global/product-specific targets, **not** proof that user's customized `dsh-runtime` integrates without collision. `install.sh | sh`, `codegraph install`, `codegraph upgrade` can execute downloaded programs or mutate trusted config; none should run before isolated source and installer sandbox review.
- **VERIFIED — filesystem scope and MCP data exposure.** `src/extraction/index.ts` honors project ignore rules by default, but user `codegraph.json` `include`/`includeIgnored` can force indexing ignored or embedded repositories. Some source formats and configuration keys receive protective handling, but data indexed from private code and returned in rich MCP snippets remains sensitive. `src/mcp/tools.ts` can return verbatim source and links that are subsequently transmitted to remote LLMs. A local MCP server is not automatically a tenant isolation, nor a safe way to access production medical repos from outside a locked environment. No secrets, password manager or production AKUZ data imported during this review.
- **VERIFIED — high-scale operational footprint not known for user's repo.** One SQLite graph per project under `.codegraph/`, supporting in-memory caches and Rust/TS parse workers. Storage is schema and corpus dependent; FTS/edges/write-ahead log, index build CPU/RSS/IO and background sync can compete with other development or database tools. `src/db/wal-valve.ts` and `src/sync/worktree.ts` include explicit mitigations but are not a guarantee of no resource cost. No measured Bazzite/AKUZ workload, exact storage GB or memory peaks. Use synthetic or clean public clone before any deployment.

## 2. Benchmark audit: strong claims with counterevidence

| Evidence | Measurement | What it does **not** prove |
| --- | --- | --- |
| [README 7-repo August 2026](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/README.md) | 7 repos across seven languages, 4 runs/arm, selected architecture question; **88% fewer tool calls, 53% less wall time, 62% fewer processed tokens, 44% cheaper**; without-arm CLI contamination reported 0/28 | Independent blinded task correctness, full-cycle implementation-quality/merge success, model generality, cost after index build or across many turns. Developer-owned benchmark. |
| [37-cell S/M/L language matrix, May 2026](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/docs/benchmarks/codegraph-ab-matrix.md) | **76% fewer file reads, 189 vs 321 tool calls, 38s vs 48s mean**, yet model costs **$15.4 with vs $13.8 without**, one run per arm | Universal cost savings or significance; small repos sometimes slower; overhead and tool-definition cost may dominate |
| [Three-turn residual-context test](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/docs/benchmarks/residual-context-occupancy.md) | Graph arm left about **80% more retrieval context resident**, for VS Code 67K vs 18K tokens; repo docs distinguish processed token throughput from window occupancy | Better long-lived context-window availability or lower compaction pressure; benchmark context metadata should be separately reproduced |
| [Evaluation harness docs](https://github.com/colbymchenry/codegraph/blob/73c6cff66e525a92bff65675b6b0c46687e91ef1/docs/benchmarks/agent-eval-feedback-metrics.md) | Documents leakage control, contamination from shell, model, turn structure and known measurement traps | Independent external peer replication or measured benefit for a user-specific repo |

Benchmarks in the repo are **source-backed author claims**, not reproduced by this review. Results are workload-specific and include disclosed negative findings (cost increase, larger residual context). The relevant objective for AKUZ/DSH must be **correct, source-linked changes and verified comprehension**, not purely tokens/tools.

## 3. Portfolio screening and A/B/C

[Project-registry `91a0ca742a3225f6c4683b51031e8bbb595fdab8`](https://github.com/Artemedi/project-registry/tree/91a0ca742a3225f6c4683b51031e8bbb595fdab8): all 45 `PROJECT.md` profiles screened. Five candidates *only on documents*: `AKUZ`, `dsh-runtime`, `Harness`, `HermesAgent`, `dsh-paper2agent`; other 40 `DEFERRED_SCREENING`. The user-specific AKUZ codebase is private and mixed (C#, Python, T-SQL, PowerShell), HermesAgent is **live config**, Paper2Project is separate experimental CLI/MCP pipeline; no private code was read. See [portfolio matrix](../../portfolio/2026-11-24/codegraph.md) for per-target evidence and gates.

**H1:** graph-assisted code traversal lowers wall time, total model tokens and unnecessary file reads **without reducing grounded correctness or increasing residual context/CPU/IO materially** for complex TS/Python/C# cross-file queries. **H0:** baseline `rg/grep/Read/LSP` matches or beats it after indexing, graph misses dynamic/SQL edges, integration overhead/cost negates tool-call saving.

- **A**: existing Git/Grep/LSP/agent tools on pinned public or synthetic source fixture with prepared actual symbol/edge/change oracle, no CodeGraph; identical model/session/tool budgets and question order.
- **B**: minimal **read-only** offline static-index graph on *disposable clean clone*, pinned source and all deps in isolated rootless Podman/VM only after owner/security gate, no global `install`, no hooks, no remote telemetry, model calls under explicit approved local policy. Ideally use source API or standalone CLI, not auto-installed MCP config. `DO_NOT_TRACK=1 CODEGRAPH_TELEMETRY=0 CODEGRAPH_NO_UPDATE_CHECK=1`, network namespace deny, temp HOME, no credentials, no mounts of production code. Include exact pinned hash + corpus hash and standalone query results in artifact.
- **C**: optional CodeGraph via MCP in dummy agent home with synthetic code, *after* B measures reliability. For DSH, manually describe test-only adapter rather than mutate real `~/.dsh`; for Hermes, ensure other MCP entries survive via bytewise config diff. Check answer-freshness flags, cross-branch/worktree confusion and timeouts.
- **Fixed task set:** TypeScript module API and route chain, Python call path, C# handler→service→DB call. Include `reflection/dynamic SQL` negative controls as **known static limitations**, one-file edit then stale-index/cold rebuild, branch checkout, deleted file, concurrent N agents. Independent oracle from compiler/LSP tests, static human source-line proof, actual unit tests and an independent reviewer; don't assume graph-generated link is true.
- **Metrics:** correctness/abstention, precision/recall of edges, false-negative & hallucinated edges, required file reads and tool calls, tokens including retrieval occupancy, p50/p95 answer time and reindex/sync delay, index disk/FTS size, CPU/RSS/IO/WAL peak under concurrency, leaked egress count, per-agent config diff, answer-source freshness, reviewer time and acceptance rate. Repeated 5+ trials; different task complexity.
- **Hard gates:** zero outgoing traffic from CodeGraph under offline mode, zero sensitive source in test/LLM provider, no unintended agent-home writes, no stale results silently used, stable branch-scope, correct answer quality at least baseline, actual net gain after index/watcher costs and security review. If not met: `REFERENCE_ONLY / NO_BENEFIT`.

**Decision:** `BOUNDED_CODE_REVIEW / DOCUMENTED_CANDIDATE / NEEDS_EVIDENCE / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED`. This is a good controlled code-navigation experiment, **not** an approved production index of AKUZ or universal semantic SQL dependency map.
