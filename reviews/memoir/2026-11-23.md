## 1. Functionality verified; marketing statements bounded

- **Git-like content-versioned memory is real:** [`ProllyTreeStore`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/prolly_adapter.py) wraps `prollytree.VersionedKvStore`, [`BranchService`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/branch_service.py) implements branch/checkout/merge/ref/commit read; history and state/diff surface via CLI/SDK/MCP. This provides real lineage and prospective rollback after an incorrect write, **not automatic detection/rejection** of hallucinated facts or convergence of conflicting writers.
- **Semantic path taxonomy is not semantic vector equivalence:** exact keys like `profile.professional.skills.python`, deterministic/smart classifier, LLM path picker (single/tiered). [`IntelligentSearchEngine`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/search/intelligent.py) sends path inventory/content samples to selected LLM and can stage 2–3 LLM calls in a `tiered` search. Path mistakes cause silent false negatives even when content exists; taxonomy changes/branch context can cause wrong recall. No independent relevance guarantee.
- **«Replaces vector databases» is overbroad:** [`services/search_service.py`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/search_service.py) explicitly labels its operation vector top-k semantic search; [`services/vector_service.py`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/vector_service.py) calls `NamespacedKvStore.text_index_open/insert/search` + `MiniLmEmbedder` (first run may download ~90 MB model). It may eliminate an *external* vector database service for some workloads, **not** vector similarity/embedding itself.
- **O(log n) is not end-to-end:** [`docs/theory/search.md:502–508`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/docs/theory/search.md#L502-L508) admits `O(log n)` is a *shape claim*, `summarize` scanning k keys is O(k), not logarithmic; [`ProllyTreeStore.all_keys():524–537`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/prolly_adapter.py#L524-L537) needs full committed-snapshot replay because native `list_keys()` returns max 1024, then caches entire state (`_committed():458–505`). Consequences: snapshot first-read CPU/RAM/IO scales with total corpus/history and previous-version dependency; branch-switch and invalidated cache may reintroduce replay. Claims `0.1–1ms`, `20–30ms` and `1M memories tested` in [docs/architecture.md](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/docs/architecture.md) are **AUTHOR_CLAIMED**, without a matched raw run, hardware/branch/history, p95 and comparator reproduced here. [Search theory](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/docs/theory/search.md) itself estimates tiered LLM path selection ~1–2 seconds; distinguish KV get latency from total recall.
- **Cryptographic integrity != encryption/authenticity:** [`CryptoService.generate_proof/verify_proof`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/crypto_service.py#L29-L166) wraps ProllyTree `generate_proof(key)` and `verify_proof(proof,key,expected_bytes)`, returns value and base64 proof. `store._encode_value` [lines 568–577](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/prolly_adapter.py#L568-L577) serializes JSON/plain UTF-8; no encryption is visible on this storage code path. Even valid Merkle inclusion establishes integrity *relative to its accepted root*, not authorization, a trusted independently pinned commitment, unmodified history in face of malicious owner, or privacy. The `verify_proof` function at line 140 checks `if expected_value:`, therefore legitimate falsy expected values (`0`, `False`, `""`) are not serialized and passed as explicit expected content. This is a narrowly verified **input-validation coverage gap**, not a remotely exploited vulnerability claim.
- **Data retention/Git GC is a special correctness hazard:** [`store/git_safety.py`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/store/git_safety.py) explicitly says ProllyTree nodes can be dangling Git blobs not referenced by heads/tags; sets `gc.auto=0`, `gc.pruneExpire=never` to avoid silent loss. `git gc --prune=now` can override that protection; only file backend is claimed resilient in that code comment. Tradeoff: extra disk/history growth, explicit `memoir gc` only under verified reachability. [`MemoryService.forget()`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/memory_service.py#L545-L582) calls store.delete, which commits a logical deletion; **does not automatically purge all old commits, clones, backups, remote copies**. For personal/secret data, right-to-erasure needs a separate retention/redaction/rewrite process.
- **Branch routing is engineered, not magically isolated:** [`BranchService.routed_to():247–335`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/src/memoir/services/branch_service.py#L247-L335) takes a writer lock, checks out the target branch on disk, writes, and restores prior HEAD in `finally`. This defends against some concurrent writers, but other read/process behaviour outside the lock, process crashes, merge conflicts, Git worktrees, branch rename/rebase or cross-tenant leakage need independently exercised tests; the code logs restoration failure and may leave branch checked out. Branches are *logical lineages*, **not namespace ACLs or security isolation**.
- **Auto-capture creates an LLM/privacy boundary:** [Claude Stop hook](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/plugins/claude-code/hooks/stop.sh) consumes transcript, prompt and edited-source snippets and uses a model to summarize/capture into durable Git-backed memory, sometimes with per-turn code-change metrics; [Codex hooks](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/plugins/codex/hooks/hooks.json) run on SessionStart/UserPromptSubmit/Stop; [Hermes plugin](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/plugins/hermes/README.md) provides provider + tools. Context may be sent to model API depending on configuration. Local `get` and explicit-path `remember -p` can avoid an LLM, but the default `litellm` router and plugins mean a "local store" is not equivalent to offline/no-egress.
- **Optional cloud sync is a separate trust domain:** [`docs/cloud.md`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/docs/cloud.md) and `sync_service.py` implement remote push/pull via authenticated gateway; it is **opt-in**, not automatic core storage. The project includes remote agent-account tokens (`.git/memoir-cloud/token` mode 0600). There is no evidence here of end-to-end content encryption, protected private production data processing, audit-retention/tenant ACL appropriate to AKUZ, or cloud deletion guarantee. For high-integrity memory, pin root hash outside a writable store and verify restore/remote rollback under separate trust control.

## 2. Benchmark provenance

In pinned `benchmarks/` there is a runnable `classifier.py` benchmark and LoCoMo/LoCoMo-Plus (factual, cognitive hybrid) harness, not published independently signed per-instance benchmark results under this path. [`benchmarks/locomo/README.md`](https://github.com/zhangfengcdt/memoir/blob/7fd1b3ef704fc554596571d5b9c8b73d7f2b0c5d/benchmarks/locomo/README.md) explicitly notes `gpt-4o-mini` generation/recall, `gpt-4o` LLM-as-judge and that recall may send a **whole store** per query; this is a large input-token, privacy and scaling cost in that benchmark regime, not a guaranteed runtime pattern for every Memoir search mode. It requires the LoCoMo-Plus external dataset and API access. No A/B on same corpus vs `TencentDB-Agent-Memory`, `dsh-team-context`, native DSH context or baseline was reproduced. Do not treat benchmark scripts or reference documentation as a verified 1M-memory scaling result.

## 3. Project registry and bounded A/B/C

[Project registry pinned `91a0ca742a3225f6c4683b51031e8bbb595fdab8`](https://github.com/Artemedi/project-registry/tree/91a0ca742a3225f6c4683b51031e8bbb595fdab8): all 45 purpose/workflow descriptions screened. `TencentDB-Agent-Memory`, `dsh-team-context`, `HermesAgent`, `dsh-runtime` retained as four **documentary hypotheses only** (41 deferred). `HermesAgent` is a live gateway *configuration*, not a disposable product source. `dsh-team-context` owns knowledge/governance separate from runtime. `TencentDB-Agent-Memory` includes multi-class chat, skill, wiki, code graph; Memoir is **not** a measured drop-in replacement. `dsh-runtime` is a plugin runner with no verified mapped Memory API.

**H1:** adding branch-scope and reproducible commit lineage *without replacing current retrieval* reduces cross-branch contamination and mean-time-to-revert bad captured facts, while preserving recall correctness and incremental resource cost. **H0:** cost of snapshot replay, history/GC management, unnecessary LLM path selection, auto-capture hallucinations and secret retention outweighs benefits.

- **A — baseline:** current path/knowledge store, explicit project/branch labels, manually curated facts; freeze fixture corpus and independent expected answers; measure baseline recall accuracy/cost, history lookup, merge after code branch change.
- **B — minimal feature comparator (YAGNI):** independent **policy-only** branch-aware metadata/commit history on synthetic memory ledger without importing Memoir, no embedding calls or auto-capture. Tests for branch-aware recall, past-memory reversion, long history, concurrent writes and deletion/retention; avoid a new production engine.
- **C — Memoir official pinned source in disposable local sandbox only after owner/security gate:** synthetic documents and short conversations, empty HOME, no remote sync/credential inheritance, OS-denied outbound network, deterministic local mock model, separate UID; exercise `new`, explicit-key remember/get, branch checkout/merge/blame, cryptographic proof validation against independently recorded expected values (including falsy), crash recovery, forced Git GC and file backend (in sacrificial test copy), snapshot enumeration over 1024/10K/100K keys; compare against A and B. Never mount real AKUZ databases, real Claude/Codex/Hermes transcripts, personal preferences or authenticated project repositories.
- **Metrics:** branch-isolation leakage tests, wrong-context rate, grounded recall@k and contradictions, answer abstention when branch empty, commit/revert consistency, reproducibility across restart, Merkle proof rejection on tamper/wrong key/wrong value + trusted root, physical erase/retention behaviour, p50/p95 write/get/semantic recall, cold-cache snapshot replay peak RSS/CPU/IO, disk GB per N facts/commits, LLM token input/output and egress, reviewer time, interruptions/concurrency issues and cost per accepted fact.
- **Hard gate:** zero unauthorized cross-project/branch recall, zero sensitive network egress, tamper detection with a pinned independent root, safe GC/restore with no silent loss, measured net advantage in correct recovered context vs baseline and explicit owner-approved data lifecycle. If any fail: `REJECT_RUNTIME/REFERENCE_ONLY`.

**Decision:** `DOCUMENTED_CANDIDATE / NEEDS_EVIDENCE / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED`. Source review is not a deployment or independent benchmark.
