# Yahont CE и Wiki_PG — идентичность источников при индексации

**Результат.** В двух прогонах функция Yahont CE сопоставила 20 парам похожих путей одинаковые строки. Штатный Wiki_PG сохранил два разных идентификатора для каждой пары, хотя исходные байты совпадали. После изменения одного файла обновился только его идентификатор. После удаления второго исчез только его результат.

[Протокол](../../experiments/yahont-ce/2026-11-26-wiki-pg-source-identity-protocol.md) · [Скрипт](../../experiments/yahont-ce/wiki-pg-source-identity.py) · [Данные](../../data/results/yahont-ce/2026-11-26-wiki-pg-source-identity.json)

| Проверка | Результат |
| --- | ---: |
| Функция Yahont CE вернула одинаковые строки для пары и отличила контрольный путь | 20/20 |
| Wiki_PG сохранил два идентификатора при одинаковых байтах и правильно выбрал один путь по явному фильтру | 20/20 |
| Изменение первого файла обновило только его идентификатор | 20/20 |
| Удаление второго файла убрало только его из выдачи | 20/20 |

У Wiki_PG идентификатор записи учитывает относительный путь и хеш содержимого. В каждом поисковом ответе стенд отдельно сверял путь, хеш и текст. Со стороны Yahont проверена только исходная функция нормализации. Данные опыта не устанавливают, какие идентификаторы доходят до OpenSearch при работе реального коннектора. Полный поиск, политики доступа и эффект на пользователей здесь не проверялись.
