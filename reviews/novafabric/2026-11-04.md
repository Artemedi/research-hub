## Наш independent A/B на 20 test-run capsules

Детерминированная синтетическая Python-программа содержит две **настоящие авторские** `@novafabric.capture.record.tool` функции: `fetch_metric(name)` (чтение test JSON и запись side-effect canary) и `calculate_metric(value)` (детерминированное преобразование + canary). Перед каждым запуском подготовлено значение `700+13*i`, независимый oracle ожидает `{metric: x, doubled: 2*x, status: ok}`. `NOVA_CAPTURE_LEVEL=forensic` нужен для capture payload и строгой подстановки; **не рекомендован без проверки PII/секретов**.

Для каждого из 20 отдельных запусков:
1. Измерен **прямой**, не захваченный запуск того же toy script как контроль времени; проверен ответ и исходные два side effects.
2. `nova capture --output-dir` создал капсулу в отдельном каталоге, с `tool_call_count=2`; проведена независимая проверка текста результата.
3. `nova validate`, `nova verify` (NovaSeal) и `nova verify --ca-bundle <local CA>` завершились кодом 0.
4. Источник `x` **заменён** другим (`x+9000`), журнал побочных действий обнулён; выполнен `nova replay <capsule> --mode mocked`.
5. Проверено: replay `status=success`, **2/2** вызова поданы из записи, `tool_calls_live=0`, `tool_calls_unmatched=0`, `queues_fully_consumed=true`, `network_connections_live=0` по собственной телеметрии NovaFabric; побочных выполнений функций **0**, конечный JSON побайтно идентичен oracle. Для первого случая дополнительно выполнен `forensic` (read-only) без вызова функций.

### Negative controls через официальный `nova replay`

- **Дополнительный `@record.tool` вызов без пары в журнале:** строгое mocked replay отказало `tool_call_unmatched`, дополнительное тело функции не выполнилось. **FAIL-CLOSED на конкретном поддерживаемом hook.**
- **Обычная `Path.write_text` вне instrumented tool:** mocked replay **успешно завершился, а новая файловая запись реально произошла**. Следовательно, replay **не** является ОС-песочницей, не экранирует любой shell/file/network side effect и не даёт доказательства «ничего не было сделано».

## Подпись, manifest и нарушения целостности

Локальный `nova seal init` создал **self-asserted** ECDSA P-256 identity, локальный CA и Merkle log. Все 20 капсул прошли `nova verify` и `--ca-bundle`. **`timestamp_ok=None`** — RFC 3161 TSA не задан, trusted time отсутствует; CA pin удостоверяет доверие только к закреплённому локальному ключу, не независимую организационную идентичность.

Негативные тесты на **копиях** одной подписанной капсулы:

| Мутация после seal | `nova verify` |
| --- | --- |
| Дописать байты в `outputs/stdout.txt` | **FAIL** |
| Поменять местами два JSONL tool events (обе строки остаются JSON) | **FAIL** |
| Изменить статус в `capsule.yaml` | **FAIL** |
| Удалить `trace.jsonl` | **FAIL** |
| Переименовать пустой `model-calls.jsonl` | **FAIL** |
| Удалить подпись `.seal/` | **FAIL** |
| Добавить **новый**, не вошедший в digest inventory `rogue-added-after-seal.txt` | **PASS** |

Последнее **не означает взлом криптографии**: манифест подписывает **перечисленные** пути. Новый файл в том же каталоге не получает подпись автоматически. **Требование к DSH:** доказательства принимать только из `evidence_digests` и подписанной структуры, а для передаваемых ZIP — использовать строгую проверку *полного* состава файлов. Нельзя доверять произвольному файлу на диске лишь потому, что соседняя капсула валидна.

## Переносимый Evidence Bundle и независимый verifier

Оригинальным `nova export-evidence` создан **один тестовый** Evidence Bundle ZIP, размер **82 476 bytes**; содержит 49 regular archive members. Своим [не зависящим от NovaFabric verifier](../../experiments/2026-11-04-novafabric-independent-bundle-verify.py) на `cryptography` и стандартной библиотеке проверены:

- `manifest_hash` (канонический SHA-256), **48/48** SHA-256 и file-size records;
- **4/4 Ed25519 DSSE attestation signatures** по публичному ключу внутри ZIP, включая проверку PAE, refs, subject digest, content type;
- Merkle root v2 из capsule-relative file names и SHA-256 содержимого; подтверждено равенство `subject.capsule_hash` и подписанной run attestation;
- хеши redaction proof и lineage, members statement для всех файлов (кроме оговорённых служебных файлов), digest базового манифеста;
- проверка **закреплённого SHA-256 публичного ключа**. Закрепление проверяет key continuity только если fingerprint доверенно доставлен отдельно; не удостоверяет реальное лицо/организацию.

**Пять независимых negative controls: отказ на изменённый stdout, переставленные записи tool calls, добавленный файл ZIP, изменённый manifest, неправильный pinned key.** Все отклонены. У verifier нет импортов `novafabric`; **не утверждается**, что он годится как полнофункциональный hardened production verifier (нет верхних лимитов ZIP распаковки, resource budgets, formal policy etc).

При `nova export-evidence` выдано предупреждение: **OPA binary отсутствует, policy engine = NoopEngine**. Выходной ZIP построен, но *policy gates не были исполнены*: это не свидетельство успешной policy approval. **Нельзя включать auto-approval DSH, опираясь только на подпись архива.**

## Производительность, storage и trade-offs

Окончательный повторный прогон 20 случаев (включая два дополнительных контрольных сценария) показал медианы: прямое исполнение toy script **129,761 ms**, `nova capture` **1457,738 ms**, `validate` **1348,759 ms**, `verify` **1226,686 ms**, CA-pinned `verify` **1242,167 ms**, mocked replay **1379,459 ms**. Медианный размер одного sealed capsule **18 155 bytes** (здесь модельных сообщений нет). Первый независимый прогон на прежнем варианте скрипта показал сопоставимые медианы захвата **1513,378 ms** и mocked replay **1448,29 ms**. [Машинно-читаемые результаты окончательного прогона и независимого bundle verifier](../../data/results/novafabric/2026-11-04.json).

Время каждой операции **включает запуск отдельного CLI Python-процесса**, часть capture time — serialisation/redaction/sealing и импорт зависимостей; **не** следует считать это per-token overhead, production p95, CPU/IO потоком или линейно переносить на длинные запросы DSH. Число model SDK calls было нулевым, нет измерений latency модели, частоты disk writes, полноты user-session capture и реальной web/MCP сети.

## Отношение к проектам

- **`dsh-runtime` / агентные навыки:** явный профиль применимости к RCA и machine-verifiable provenance. Однако текущие `@record.tool` реализованы для Python, а жизненный цикл собственных DSH runtime/tool adapters и source-of-truth для результатов отдельно здесь **не проверен**. Доказан лишь тестовый capability, не интеграционная готовность.
- Исторический `dsh/docs/verifier-dependency-seam-trace.md` обсуждает optional pairwise `score-v1`: preference score и rationale **не** подтверждают, что источник reward/доказательств защищён от изменений. BenchShield и NovaFabric решают разные части: первое требует host-side capture integrity / correctness границ, второе может подтверждать подписанные **уже наблюдённые** events. Ни один механизм не гарантирует реальную полноту записанных tool/file/network activity без отдельного независимого capture oracle.
- **Предпочтительное минимальное изменение в будущем (YAGNI):** сначала узкий **evidence bundle exporter** или подпись существующего test-run manifest: pinned source revision, declared tool/model event streams, `capture_complete`, `observed_at`, `source_kind`, независимый verifier и result oracle. Проверять строгий allowlist, `ABSTAIN` при неполноте. Не переносить весь NovaFabric, distributed lineage, TSA/KMS и DB index до проверки потребности.
- **Безопасность:** не включать mocked replay в production-сеансы без sandbox, resource limits, egress policy, safe filesystem and no-secrets policy. `NOVA_CAPTURE_LEVEL=forensic` хранит полные payload, требует отдельной оценки PII. Подписанный журнал доказывает **неизменность записанного**, но не **истинность записи**, не полноту, не владельца ключа и не время события.

## Воспроизведение

Исходники [tag v0.108.0](https://github.com/MSKazemi/novafabric/tree/v0.108.0), pinned SHA указан выше; Python 3.12:

```bash
git clone --branch v0.108.0 https://github.com/MSKazemi/novafabric.git /tmp/novafabric-source
git -C /tmp/novafabric-source rev-parse HEAD # cc1d71b64b4d1b4c9aa6e4a16a804686514fe667
uv venv --python 3.12 /tmp/novafabric-venv
uv pip install --python /tmp/novafabric-venv/bin/python -e /tmp/novafabric-source pytest

/tmp/novafabric-venv/bin/python \
  experiments/2026-11-04-novafabric-real-capsule-lab.py \
  --workspace /tmp/novafabric-toy-replay \
  --nova /tmp/novafabric-venv/bin/nova \
  --python /tmp/novafabric-venv/bin/python --cases 20
# Запустить в новом, пустом --workspace. Только synthetic test, никаких real agents.

LAB=/tmp/novafabric-toy-replay
openssl genpkey -algorithm ed25519 -out "$LAB/ed25519.pem"
CAPSULE=$(find "$LAB/capsules" -mindepth 1 -maxdepth 1 -type d | head -1)
NOVAFABRIC_HOME="$LAB/novafabric-home" \
  /tmp/novafabric-venv/bin/nova export-evidence "$CAPSULE" \
  --output "$LAB/evidence.zip" --key "$LAB/ed25519.pem"
# Crypto verification; no imports from novafabric:
 /tmp/novafabric-venv/bin/python \
  experiments/2026-11-04-novafabric-independent-bundle-verify.py \
  "$LAB/evidence.zip" --self-test
```

**Методологическое ограничение:** `nova seal init` создан внутри `--workspace`, Ed25519 key используется только в disposable lab и **не публикуется**. `--self-test` создаёт/удаляет свои изменённые ZIP во временном каталоге. Полные капсулы и ключи не следует коммитить. Исследовательские метрики и проверенный код — в `research-hub`.
