## 1. Проверенные source anchors, факты и ограничения

Просмотрены pinned README, Go module, Makefile, `BENCHMARKS.md`, `.github/workflows/ci.yaml`, docs/site: архитектура, storage, single-node, Kubernetes, PPL feature-matrix, pipe mode, конфигурация, security defaults; деревья `pkg/{ppl,query,engine,colstore,ingest,database,api}` и локальный `cmd/lynxdb/query.go`. Фактические реализация/документы могут расходиться; это bounded static review. Ни Go binary, ни незнакомый сервер не запускался.

- **VERIFIED — два режима, общий query path:** [`architecture/overview.md`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/architecture/overview.md) описывает `PPL text → pkg/query compiler/IR optimizer → pkg/engine/columnar, pkg/colstore/exec → row operators`. `cmd/lynxdb/query.go:146–267` обрабатывает `--file` или stdin, создавая временную БД и записывая строки в локальные columnar parts. Это не чисто streaming grep: для локального режима нужны disk IO, индексирование и временное хранилище. Persistent mode владеет per-index local stores и query jobs через HTTP.
- **VERIFIED — форматы и ingest:** [README](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/README.md) заявляет JSON, timestamp, key=value, access/syslog; [architecture read/write paths](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/architecture/overview.md) перечисляют NDJSON/native, Elasticsearch `_bulk`, OTel logs, Splunk HEC и syslog. Общие ingestion pathways не доказывают корректного объединения multiline exception/stack trace AKUZ. Native `/api/v1/ingest` может частично принять префикс при ошибке позднего чанка, поэтому idempotence и dedup — **NEEDS_EVIDENCE**.
- **VERIFIED — single-node, НЕ distributed:** [`architecture/overview.md:8`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/architecture/overview.md) говорит `single-node`; [`deployment/kubernetes.md`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/deployment/kubernetes.md) показывает StatefulSet `replicas: 1`; [`architecture/es-stubs.md`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/architecture/es-stubs.md) называет `GET /_cluster/health` green single-node response. Не обнаружено доказательств shard replication, distributed coordinator или multi-node failover. В PPL [feature matrix](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/ppl/feature-matrix.md) cross-cluster search прямо неподдерживаем. Следовательно заявление «одним и тем же движком работает распределённый кластер» **не подтверждено в pinned revision**. Название `LynxFlow` в изученном README/architecture не найдено как отдельный public API.
- **VERIFIED — PPL не полная эквивалентность OpenSearch:** [`docs/site/docs/ppl/feature-matrix.md`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/ppl/feature-matrix.md): `join`, `stats`, `timechart`, `grok`, `search` частичны; correlated subqueries, cross-cluster search, external sources, ML и часть функций — unsupported. `join` удерживает правую сторону в RAM. `distinct_count` в columnar executor точен, но row operators после 10k используют HLL; `percentile` может использовать sketch/t-digest. **Обязателен independent exact-answer oracle** и одинаковое заранее зафиксированное query plan/semantics.
- **VERIFIED — ingestion durability граница:** [`architecture/storage.md:86–120,171–183`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/architecture/storage.md) описывает in-memory buffers, flush/manifest durable commit, no event WAL; аварийное завершение может потерять ещё не зафиксированные события. Native ingest и обычный HEC могут подтвердить buffered данные; Elasticsearch bulk и HEC indexer ack требуют sync. Database-wide Sync идёт по store независимо, **не** единой snapshot transaction. Поэтому `success HTTP` и `all events durably searchable` нельзя отождествлять.
- **VERIFIED — retention/recovery:** manifest хранит live parts per index; recovery повреждённого manifest может отказать в открытии store, а events без WAL не восстанавливаются. Retention удаляет партиции (с учётом pinned snapshots); это не доказательство резервирования, репликации, immutable evidence или true audit archive.
- **VERIFIED — локальность и доступ:** [`pkg/config/defaults.yaml`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/pkg/config/defaults.yaml) документирует default `listen: localhost:3100`, `auth.enabled: false`, `tls.enabled: false`; [`deployment/kubernetes.md`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/docs/site/docs/deployment/kubernetes.md) отдельно предупреждает, что OTLP listener не имеет auth, а `/metrics` доступен без auth. Не пробрасывать реальные пользовательские/медицинские логи в незакрытый HTTP endpoint; CLI file mode не обязан открывать порт.
- **VERIFIED — benchmark evidence:** [`BENCHMARKS.md`](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/BENCHMARKS.md) описывает микробенчмарки, JSONBench и генеративный Logs Suite с reference evaluator, но **численные результаты не зафиксированы в репозитории**, и сравнение с AKUZ corpus не выполнено. [CI](https://github.com/lynxbase/lynxdb/blob/6623322ab58f605efb35c636db8ee10b3884f6a8/.github/workflows/ci.yaml) определяет unit race/e2e/CLI/golden tests; наличие CI не подтверждает performance/operability.

## 2. Существенные эксплуатационные риски

| Риск | Конкретный механизм | Что должен показать эксперимент |
| --- | --- | --- |
| Несоответствие AKUZ event boundaries | Файл может содержать длинную multiline exception, trace continuation, текстовые даты и русскоязычные сообщения | `akuzlogparser.event_stream()` как независимая граница событий и точные raw/message/time/fingerprint parity на sanitized synthetic corpus |
| Утрата доказательств в режиме server ingest | Буфер без event WAL, native partial prefix, retention | Crash/kill-before-sync negative test, replay/dedup contract, event-count/checksum before/after restart |
| Ложная точность RCA | HLL/t-digest/percentile в отдельных планах; неполная PPL | Табличный exact oracle на count, distinct, p95, joins, missing fields, timestamps и locale |
| Memory/IO overhead при local query | Временная DB, columnar files, compaction/flush, RAM join | peak RSS, temp bytes, page cache, CPU, wall elapsed vs Python/grep/jq |
| Доступ к приватным данным | Логи могут содержать PII/PHI, GUID, SQL/stacks, hostnames; auth/TLS off по умолчанию | Только synthetic; no networking; prove no files outside temp allowlist, no export of raw evidence |
| Single-node восстановление | Отсутствуют source-backed репликация/автоматический failover | Проверка restart/manifest fault и документальная политика backup; не использовать как HA log archive |
| Семантический drift | README прямо предупреждает о смене storage/API/query между релизами | Pin commit+binary hash, golden fixtures, version skew и ability to read prior stored parts |

## 3. Фальсифицируемая H1 и A/B/C (НЕ выполнялись)

**H1:** для фиксированного корпуса синтетических application/DBA логов PPL-query над LynxDB снижает время/ресурсы повторяемого анализа *при идентичном числе и полях событий, точных результатах и без изменения evidence*. **H0:** parsing/copy/index overhead и расхождения семантики дают нулевую или отрицательную практическую выгоду.

- **A:** штатный `akuzlogparser` streaming parser + Python/SQLite/grep/jq, read-only log snapshots, frozen filters/aggregation.
- **B:** pinned `lynxdb query --file` / stdin на тех же фиктивных источниках, отдельный временный каталог, `--format csv`, без сервера и сети; независимый golden oracle и паритет покрытия событий.
- **C:** persistent single-node LynxDB на одноразовом data_dir с synthetic replay, явно сконфигурированными auth/retention, отдельным crash/durability экспериментом и метриками. **C requires separate owner approval**, не выполнять на production и не выдавать статус HA.
- Преднамеренно difficult fixtures: смешанные timestamp/encoding/Cyrillic; exception continuation, строка 1 MiB+, duplicate/out-of-order, missing/_raw fields, JSON nested/mixed types, partial ingest, crash before Sync, older partition and TTL boundary, malformed JSON, exact distinct/grouping/percentiles. Независимый oracle фиксируется **до** запуска B/C.
- **Metrics:** input events/bytes, parsed events and field parity, query answer hash, false positives/negatives, p50/p95 elapsed query and full pipeline, peak RSS, CPU, temporary disk IO+disk footprint, time-to-first-answer, compressed storage, persist/replay events lost, cost of maintenance/recovery. Режим B не равен «сервер без затрат»: local temp database также пишет на диск.
- **Acceptance:** 100% event/answer parity для принятых контрактов, no unapproved network/remote/log mutation, zero silent truncation/replay gaps in the selected durability model, measurable E2E advantage over A at equal workload, formal hard limits on resources. Отсутствие улучшения означает `NO_BENEFIT`, а неполное сохранение событий — `NO_FIT_FOR_CANONICAL_ARCHIVE`.

## 4. Применимость к конкретным проектам

Registry [`Artemedi/project-registry@7a976c353579f8da64789daf18fe1088e5ab8dbb`](https://github.com/Artemedi/project-registry/tree/7a976c353579f8da64789daf18fe1088e5ab8dbb): purpose/stack screening 45 карточек. Три условных направления, **не** VERIFIED интеграционные точки:

1. **`akuzlogparser`:** исходный [`akuz_log_parser.py:238–318`](https://github.com/Artemedi/akuzlogparser/blob/d6061aa83cdeadc22e30cfaee36aea94ac131bb2/akuz_log_parser.py#L238-L318) создаёт событие по заголовку и объединяет continuation lines; [README](https://github.com/Artemedi/akuzlogparser/blob/d6061aa83cdeadc22e30cfaee36aea94ac131bb2/README.md) — локальные/SSH/SMB .log и отчёты. Кандидат для **отдельного аналитического query слоя** на sanitized output; прямая замена парсера нарушит доказательный event contract без специальных проверок.
2. **`Wiki_PG`:** исходный [`docs/universal-system-mcp.md`](https://github.com/Artemedi/Wiki_PG/blob/d55721bb99bff25fae352341cfd630c048693d6b/docs/universal-system-mcp.md) уже обеспечивает immutable evidence/SQLite state+FTS, coverage/provenance. LynxDB мог бы быть **внешним offline benchmark comparator**, не direct MCP replacement; нужно доказать преимущество над существующим indexed read-only workload.
3. **`akuz-issue`:** [README](https://github.com/Artemedi/akuz-issue/blob/6dd20b3ff7868fa5e4f8c5804384dc3694f1bb70/README.md) описывает приватный incident RCA/evidence repository с ограничением на публикацию production identifiers. LynxDB — максимум derived query layer на искусственных снимках; не менять immutable evidence, не передавать raw incident data в публичный hub/удалённые источники.

Остальные 42 — `DEFERRED_SCREENING`, не blanket `NO_FIT`. **Измеренной пользы/интеграционного контракта нет**. Предварительный приоритет: offline B на `akuzlogparser`, затем независимый query correctness/RSS аудит, и только затем обоснование persistent C. **Вердикт:** `DOCUMENTED_CANDIDATE / NEEDS_EVIDENCE / BENEFIT_UNPROVEN / NOT_PRODUCTION_APPROVED`.
