## Метод и ограничения

Skill предлагает выбрать scope, собрать локальные истории Codex/Claude/Warp и других поддержанных инструментов, сократить сообщения и tool output, отобрать до 12 сессий за 45 дней по умолчанию, оценить их агентом по эффективности, качеству кода, соблюдению процедур и краткости, затем предложить редактирование `SKILL.md` только по неудачным сессиям. Черновики сохраняются вне исходного проекта; HTML-отчёт генерируется локально. Рубрики — инструкции субъективному оценщику, не детерминированный тест качества кода. В score четыре кривые `0.5 + 0.5 * raw`, а также coverage, с заданными весами; полученный итог нельзя считать вероятностью правильности или сравнимым benchmark без калибровки.

[Collector](https://github.com/warpdotdev/common-skills/blob/8792394ff1b655e0af451b8fabb68ef0cfcbd208/.agents/skills/skill-doctor/scripts/collect_sessions.py) обрезает сообщения (1500 символов), результаты tools (500) и длинные истории (начало/конец), поэтому проверка видит не весь контекст. Детект skill по аргументам и упоминаниям не гарантирует фактического исполнения; неудачи могут объясняться моделями или инфраструктурой, а не инструкциями. Вендорское требование «всё локально» — политика инструмента, а не гарантия того, что выбранная модель обрабатывает контекст локально: это зависит от harness и провайдера. Collector пишет сокращённые тексты в scratch; сокращение не равно удалению секретов. Приватные/медицинские данные и токены требуют отдельной политики доступа и проверки egress. Истории не запускались и не читались в этом исследовании.

## Изолированная проверка

Официальные unit tests collector/renderer: **37/37**, Python 3, `bwrap --unshare-net`, отдельный tmpfs/HOME, source read-only, без реальных пользовательских сессий. Сценарий [attribution-fixture.py](../../experiments/bk019-skill-doctor/attribution-fixture.py) вызывает настоящий `session_matches_repo` на трёх синтетических путях: `/projects/alpha/src` → True; несвязанный `/other/alpha/private` → **True**; `/other/beta/private` → False. Последнее — отрицательный контроль. Причина в [fallback по любому компоненту имени каталога](https://github.com/warpdotdev/common-skills/blob/8792394ff1b655e0af451b8fabb68ef0cfcbd208/.agents/skills/skill-doctor/scripts/collect_sessions.py#L1463-L1483); автор прямо отмечает возможность over-match. Это может включить лишнюю сессию в выборку и раскрыть её данные в локальном отчёте/контексте оценщика; доказательства реальной утечки нет. Существующие 37 тестов не устанавливают безопасность данного сценария.

## Минимальный A/B

`BLOCKED: MEASUREMENT_MISSING`. На pinned версиях взять только искусственные синтетические транскрипты 3–5 задач и независимую разметку сессий, ошибок и относящихся к ним skills. A — существующий insights без изменения; B — Skill Doctor только в изолированном offline harness с искусственными логами и исправленной/строгой атрибуцией. Контроль: два разных проекта с одним именем, git worktree, отсутствующий cwd, сессия с пропущенным началом/концом, вымышленный секрет для проверки редактирования, неверная рекомендация. Независимый blind reviewer оценивает точность атрибуции, false positives, полезность и причинность предложений, следы приватных данных, время/CPU/RAM/IO и стоимость модели; предусмотреть 3 повтора, фиксированные пороги и held-out задачи. Без подтверждения локального моделирования — оценщик `NOT_RUN`; реальные журналы и внешние модели не использовать. Откат — удаление изолированного scratch. Оценка ценности 6/10, сложности 7/10: существующий `insights` частично перекрывает задачу, privacy и субъективность шкал потребуют отдельного контроля. Не заменять его и не продвигать автоматические правки без owner gate.
