# REA — статическая проверка метаданных .NET

26 ноября 2026 года

Проверили, можно ли воспроизвести статический отчёт REA и привязать выбранные поля к конкретным записям в файле. Сравнение оригинальных функций REA со стандартным читателем .NET дало **24 из 24 успешных проверок** на Windows. Два варианта библиотеки проверили по три раза, каждый раз по четырём группам полей. Две отдельные сборки с тем же SDK дали одинаковые SHA-256 и JSON. [Протокол](../../experiments/reverse-engineer-anything/2026-11-26-managed-metadata-protocol.md) · [Результат](../../data/results/reverse-engineer-anything/2026-11-26-managed-metadata.json) · [Закреплённый исходник REA](https://github.com/morluto/rea/tree/92f332652d352e60b550567adf2399d83d8ebe78)

| Поле | Один метод | Два метода |
| --- | ---: | ---: |
| Строки MethodDef | 1 | 2 |
| Смещение записи сборки в файле | 1042 | 1072 |
| Смещение записи ссылки на System.Runtime | 1064 | 1094 |

Токен указывает на запись внутри конкретной сборки. Для воспроизводимой ссылки на свидетельство сохранены также SHA-256 файла и абсолютное смещение. Проверка подтверждает имена, версии, MVID, токены, смещения и счётчики строк у двух небольших управляемых библиотек. Поведение методов, граф вызовов, IL2CPP, работа публичного CLI и эффект на целевых проектах остались вне прогона. [Предыдущая проверка PE/CLI](2026-11-05-pe-layout.md)

В этом дереве источник управляемой сборки для переноса проверки не установлен. [Дерево psqlqa](https://github.com/Artemedi/psqlqa/tree/b2e09ff24b06f3b7a92f7cf353cd3473c2a94aea)
