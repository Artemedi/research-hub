# PGBot и Wiki_PG — диагностика блокировок на PostgreSQL 15/18

**Результат.** PGBot и Wiki_PG одинаково определили наличие блокировки во всех 16 наблюдениях на PostgreSQL 15.20 и 18.3. При одном ожидающем сеансе и двух владельцах блокировки PGBot показал один сеанс, а Wiki_PG записал две связи ожидания в поле `blocked_sessions`. Это различие воспроизвелось во всех четырёх проверках такого состояния.

[Протокол](../../experiments/pgbot/2026-11-25-wiki-pg-lock-evidence-protocol.md) · [Скрипт](../../experiments/pgbot/wiki-pg-lock-evidence.py) · [Результаты](../../data/results/pgbot/2026-11-25-wiki-pg-lock-evidence.json)

| Состояние | Сеансы / связи по SQL | PGBot `blocked_count` | Wiki_PG `blocked_sessions` | Флаг обоих инструментов |
| --- | ---: | ---: | ---: | --- |
| Исходное состояние | 0 / 0 | 0 | 0 | нет |
| Один владелец блокировки | 1 / 1 | 1 | 1 | есть |
| Два владельца блокировки | 1 / 2 | 1 | 2 | есть |
| Блокировки сняты | 0 / 0 | 0 | 0 | нет |

Запрос коллектора Wiki_PG формирует отдельную строку для каждой пары «кто ждёт, кто блокирует». Парсер считает эти строки. В стенде тот же набор пар получен проекцией двух столбцов. Штатный генератор отчёта сохранил счётчик, флаг, дату и путь искусственного deep-report. Дату задали для проверки контракта отчёта. Два прогона совпали. Полный коллектор, права эксплуатации и задержки вне прогона | Если потребуется единый показатель, проверить агрегацию уникальных ожидающих PID на снимках с несколькими ожидающими и несколькими блокирующими сеансами | `ISOLATED_INTEGRATION / OBSERVED` |

Базы временные, без внешней сети и опубликованных портов. Использован закреплённый PGBot v0.9.0. Проверка сравнивает один сигнал о блокировке. Она не измеряет качество диагностики в целом.
