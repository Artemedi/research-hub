# JetStream — проверка транзакционного контракта для AKUZ Optimizer Twin

25 ноября 2026 года два прогона дали одинаковый результат. Во всех 96 проверках за прогон обычный SQL PostgreSQL и выбранный лабораторный маршрут совпали с DuckDB. Старый снимок чтения сохранил исходный результат после коммита. После сброса состояния запросы перешли на обычный SQL. Два контрольных сравнения обнаружили устаревший ответ.

## Граница применения

Локальный `akuz-optimizer-twin@72a8b1e10ca3b199107fb2ff65ef24688a61cf29` использует `postgres/compare_plans.py:33` для получения плана. Это подтверждает назначение текущего маршрута сравнения и необходимость самостоятельного стенда с данными. Снимок исходников использован для чтения. Стенд содержит только сгенерированные записи и отдельную схему.

В статье авторы описывают отдельный слой состояния, который поддерживает корректный ответ при смене снимка, и возврат к штатному исполнению для допустимых случаев отказа. В стенде эту идею реализовали агрегатная таблица и транзакционные триггеры самого PostgreSQL. Лабораторный тест не распространяется на интерфейс опубликованного ускорителя, proof Verus или измерения авторов. [Статья v3, разделы 4 и 5](https://arxiv.org/html/2610.20527v3) · [Первичный обзор](2026-11-14.md)

## Измерение

Сравнивали восемь запросов на шести состояниях искусственной таблицы. Для каждой пары «запрос и состояние» отдельно сравнивали обычный SQL PostgreSQL и результат маршрута стенда с DuckDB. Из 48 вызовов маршрута 35 использовали агрегаты, 13 исполнили исходный SQL. После `TRUNCATE` и добавления новых строк штатный SQL обработал все восемь запросов. Принудительное чтение старых агрегатов в этот момент расходилось с эталоном. При коммите старый снимок и новый сеанс видели каждый свою версию. Подстановка числа строк из старого снимка в новый дала расхождение.

Для повтора нужны локальный образ PostgreSQL по digest из результата, Python 3.11 с `duckdb==1.5.4` и Docker. Сценарий запускается командой `python -B experiments/jetstream/twin-maintenance.py`. Контейнер и его анонимный том удаляются после прогона.
