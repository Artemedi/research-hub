# Anthropic Agent Automations — отметки после сбоя источника

26 ноября 2026 года

Отдельные отметки источников и десятиминутное перекрытие восстановили **7 из 8** синтетических изменений. Общая отметка без перекрытия восстановила 4, отдельные отметки без перекрытия — 5. Сохранились как поздняя запись внутри окна, так и запись на его границе. Ещё одна запись появилась после выхода за границу окна. [Протокол](../../experiments/anthropic-agent-automations/2026-11-26-source-bookmarks-protocol.md) · [Результат](../../data/results/anthropic-agent-automations/2026-11-26-source-bookmarks.json) · [Прежний обзор](2026-11-04.md)

| Способ чтения | Опубликовано из 8 | Прочитано записей с повторами | Повторных публикаций |
| --- | ---: | ---: | ---: |
| Общая отметка без перекрытия | 4 | 6 | 0 |
| Отдельные отметки без перекрытия | 5 | 8 | 0 |
| Отдельные отметки с перекрытием 10 минут | 7 | 16 | 0 |

При сбое чтения отдельная отметка сохранилась на прежнем значении. Ответ `ok=true` без идентификатора, отказ и сухой прогон сохранили файл отметок и реестра публикаций побайтно. Повторное чтение не опубликовало неизменившиеся записи, а возврат одной записи к прежнему состоянию был опубликован как новое изменение. Издержка в этом опыте — больше прочитанных записей. Задержка и стоимость внешних API не измерялись. [Инструкция Anthropic daily-brief](https://github.com/anthropics/claude-quickstarts/blob/8ef47d719eba5379ff8f38133f5defcc499e856f/managed-agents/daily-brief/agents/daily-brief/agent.md#L47-L63)

Для **wiki-tasks** результат даёт сценарий проверки восстановления отметок из журнала при частичных сбоях. Оптимальное окно для реальных источников пока неизвестно. Для **TelegramBot** управление отметками и подтверждение внешней доставки нужно проверять как разные условия. Стенд моделирует правила чтения и фиксации, а штатный workflow Anthropic, Slack, Telegram и код целевых проектов в тесте не исполнялись.
