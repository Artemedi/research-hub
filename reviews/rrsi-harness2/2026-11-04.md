## Задача и первоисточники

Проверить, можно ли на фиксированных сценариях обнаружить риск выбора переобученной конфигурации и ограничить его **до** просмотра отложенного теста. Это исследовательский эксперимент с детерминированными компонентами реальных исходников, не воспроизведение заявленного авторами прироста качества LLM.

- [RRSI: Regularized Recursive Self-Improvement of Agent Harnesses, **полный HTML v3**](https://arxiv.org/html/2609.24972v3) и [код google-research/rrsi@be50316e](https://github.com/google-research/rrsi/tree/be50316e1db05914068a973f322770ef08ed7ba1). Применены оригинальные `rrsi.selection.select_round`, `rrsi.evaluate.aggregate` и `rrsi.schedule.budget_table`.
- [Harness²: Recursive Agent Harnessing for an Open World, **полный HTML v1**](https://arxiv.org/html/2610.14224v1) и [код google-research/harness2@68688175](https://github.com/google-research/harness2/tree/6868817518876de8fd170c6a8354daca273b6191). Применены оригинальные `harness2.core.selection.selection_pool` и `assign_ids`. Процедуры Propose–Probe–Compose, модельный выбор, Codex/OpenCode и накопление опыта **не запускались**.
- Контрольный source: [Artemedi/agent-config@489e074](https://github.com/Artemedi/agent-config/tree/489e074ab0daaadb732673c193047172a3744862), реальная `tools/review.py:check_findings` без модификаций.
- Тестовая среда: Bazzite, Python 3.14.8, чистые независимые checkout. Harness² объявляет поддержку Python `>=3.12,<3.14`, поэтому его локальный unit-прогон на 3.14 **вне поддерживаемого интервала**; для репликации полной системы потребуется 3.12/3.13.

## Наш фиксированный эксперимент

[**Полный воспроизводимый скрипт**](../../experiments/2026-11-04-rrsi-harness2-selector-smoke.py) создаёт **105** искусственных Python-файлов с однотипной функцией `gate(value)`, затем генерирует утверждения о них (корректная цитата, корректная соседняя строка, удалённая строка, выдуманная цитата, неверное утверждение о поведении). Проверка поведения выполняется через `runpy` исключительно для собственного сгенерированного кода. Seed `20261104`.

Разделение датасета: **train 40**, **validation 25**, **holdout 40**. На train и validation доля пяти классов одинаковая; на **holdout намеренно сдвинута** доля дефектных классов. Между наборами нет общих идентификаторов; итог отложенного набора не участвует в `select_round` и не входит в пользовательский `guard_fn`. Это контролируемый synthetic distribution shift, а не естественные out-of-distribution агентные задания.

Четыре варианта (это **наши** зафиксированные проверяемые механизмы, RRSI их **не генерировал**):

1. **baseline** — результат текущей `agent-config.review.check_findings`: существующая строка и наличие цитаты где угодно в файле;
2. **memorizer** — намеренно непереносимая конфигурация: таблица правильных ответов только для train, на новых заданиях использует baseline. Это **конструируемый negative control**, а не реальный предложенный LLM-патч;
3. **locality** — исходный baseline плюс требование реального вхождения цитаты в указанную или соседнюю строку;
4. **oracle** — locality плюс запуск самостоятельного детерминированного `gate` с известным ожидаемым ответом; универсальный исполняемый oracle для естественных агентных задач отсутствует.

**Метрика:** binary decision accuracy (принять подтверждённое утверждение и отклонить неподтверждённое), а **не** end-to-end качество agent work и **не** скорость/стоимость inference.

| Вариант | Train (40) | Validation (25) | Holdout (40, shift) |
| --- | ---: | ---: | ---: |
| baseline | 24/40 = **60%** | 15/25 = **60%** | 18/40 = **45%** |
| memorizer | 40/40 = **100%** | 15/25 = **60%** | 18/40 = **45%** |
| locality | 32/40 = **80%** | 20/25 = **80%** | 28/40 = **70%** |
| oracle (предоставленный извне) | 40/40 = **100%** | 25/25 = **100%** | 40/40 = **100%** |

### Выбор кандидата реальным RRSI selector

`RRSIConfig()`, `delta=0.02`, `incumbent=baseline`, три candidate. Все получают результат `EvalResult` через настоящую `rrsi.evaluate.aggregate`; **policy-token telemetry отсутствует** (`C=None`), поэтому cost gate этого опыта не проверен. Формула `relative_cost_change` возвращает 0 при отсутствии данных; объявлять такой выбор оптимальным по токенам нельзя.

- **Без пользовательских domain guards:** `rrsi.selection.select_round` выбрал `memorizer` (100% на train, первый при ничьей с oracle). Holdout = 45%, **ниже или на уровне baseline**, несмотря на 100% train.
- **С заранее определённой проверкой validation + deployability:** `guard_fn` отклоняет вариант, если он не добавляет минимум 10 п.п. к baseline на validation, и отдельно отклоняет `oracle`, поскольку такой всеобщий oracle недоступен. Выбран `locality`. Holdout = 70%, против baseline 45%, то есть **+25 процентных пунктов на искусственном наборе**.
- **Важно:** этот `guard_fn` написан нами. Его нельзя приписывать стандартным защитам RRSI. RRSI содержит собственные critic, regularization, cost rules и history; полный recursive-agent цикл не запускался.
- Применён оригинальный `rrsi.schedule.budget_table(T=8,b_min=1,b_max=4)`: `[4,4,4,4,3,2,2,2]`. Это тест формулы лимита количества правок, не измерение результата LLM.

### Контракт Harness²

Оригинальный `harness2.core.selection.selection_pool(mode='agg', k=2)` содержит `agg1,agg2`, последовательный `mode='sequential'` содержит `c1,c2`. Reference `base1` **отсутствует в обоих наборах по дизайну метода**, а `assign_ids` даёт повторяемую анонимизацию для одинакового seed. Это не баг: для наших production-решений требуется **отдельный, внешний** baseline/OOD gate, поскольку эта функция строит набор для выбора улучшенных rollouts, а не проверяет деградацию относительно baseline. Полноценную `Probe/Compose`-процедуру мы не запускали.

## Измеренные trade-offs и пределы

**Результат подтверждает риски selection overfit, но не прирост моделей.** Мы искусственно задали memorizer и пять классов; их частоты формируют результат. Это illustration с истинным независимым oracle и отдельным контрольным split. **Inference calls: 0.** Policy tokens, стоимость LLM, p95 latency, реальная нагрузка CPU/IO и execution traces не измерялись. `oracle` не является универсальным deployable решением. `locality` — минимальная узкая правка, предложенная в предыдущем эксперименте VeriHarness; этот прогон проверяет её устойчивость к одному синтетическому shift, а не даёт разрешение на изменение production-кода.

**Вердикт:** `ADOPT_SELECTION_DISCIPLINE_NOT_AUTO_EVOLUTION`. Для `agent-config` — отдельно и хирургически исправить проверку местоположения цитаты после регрессионных тестов. Для `dsh-runtime` — не добавлять RRSI/Harness² engine поверх существующего verifier, пока нет воспроизводимого offline-replay набора реальных traces и immutable holdout. В production-контур не направлять агента, который меняет собственные prompts/tools без независимого oracle и отдельного approval.

## Повторение

```bash
# В чистом временном каталоге клонировать репозитории на pinned SHA выше.
python3 experiments/2026-11-04-rrsi-harness2-selector-smoke.py \
  --rrsi /tmp/rrsi --harness2 /tmp/harness2 --agent-config /tmp/agent-config
```

Скрипт автоматически проверяет разделение наборов, контрольные значения, выбранные варианты и внешние механизмы обоих репозиториев. Для реальной репликации провести минимум 30–50 независимых агентных кейсов с сохранёнными rollout traces, source-grounding, oracle, бюджетом; model/seed/runtime и rollout pool должны быть зафиксированы. Реальные изменения runtime не выполнялись.
