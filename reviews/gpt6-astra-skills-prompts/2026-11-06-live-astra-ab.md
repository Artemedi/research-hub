# BK-009 — GPT-6 Astra: влияние инструкций AGENTS.md и skills на стоимость задачи

**Дата:** 2026-11-06. **Решение:** `BOUNDED_LIVE_ASTRA_A_B / SYNTHETIC_FIVE_PAIRS / NO_PRODUCTION_APPROVAL`. Наблюдения — наше независимое испытание, не эксперимент, заявленный OpenAI.

Это официальный практический совет, **не peer-reviewed и не публикация с численными A/B-результатами**.

Автор рекомендует сократить и уточнить trigger descriptions навыков; использовать progressive disclosure (корень skill как короткий router к references); заменить безусловное чтение architecture/database/deployment документов на точечную навигацию; переоценить прежние ограничения, заставляющие агента спрашивать разрешение на явно безопасные действия; явно формулировать критерии завершения. **Сохранять необходимые ограничения безопасности и тестирования**, а не удалять их автоматически.

## Эксперимент и оригинальная модель

Тестовая модель закреплена **`gpt-6-astra`** через `codex exec -m gpt-6-astra`, Codex CLI **0.164.0**, `model_reasoning_effort=medium`. Контрольный запрос к модели успешно выполнен, в JSONL журналах десяти рабочих сессий есть usage/token counters. Codex запускался с `--ignore-user-config --ignore-rules --ephemeral --sandbox workspace-write`. Все 10 Git-копий находятся во временном лабораторном каталоге. Ни один реальный проект, домашняя папка с агентными правилами или production environment не изменялся; авторизация Codex применялась штатно без переноса секретов.

**A:** преднамеренно переусложнённый «старый» `AGENTS.md`: перед *любой* правкой обязательны три документа, просмотр дерева, все навыки и запуск всей тестовой батареи до и после; 8 skills с расплывчатыми trigger descriptions и длинными root-файлами. **B:** контекстные указания, чёткие триггеры, маленькие roots со ссылками на references, только релевантные локальные тесты, разрешение завершать безопасные исправления. A и B стартуют с **одинакового остального source tree и одинакового task prompt** в каждой паре. Объём восьми корневых SKILL.md: A **20 100 bytes** против B **1 858 bytes**; AGENTS.md — A 515 символов, B 611. Это **комбинированное изменение сразу нескольких инструкций**, не факторный тест отдельных приёмов.

Задачи: исправление одного слова (`typo`), Python unit regression (`unit`), новая безопасная PostgreSQL migration (`migration`), один YAML флаг (`config`), индексно-дружественный SQL UUID predicate (`query`). Независимый oracle проверяет изменённые файлы, синтаксические требования, сохранность настроек и **2/2 unit-теста**. Запуски по одному на вариант, порядок A/B менялся между задачами. Данных пользователя, модельного fine-tuning и доступа к базе не было.

На typo A запускал нерелевантные тесты до/после и зафиксировал существовавшее падение `test_ok`, тогда как B проверил дифф; оба исправили один и тот же текст.

Это **не фактически выставленные Codex-счета**, которые в данном исследовании недоступны.

**Разделены функциональность и чистота:** обе ветки завершили по 5/5 задач, но строгий gate по отсутствию любых посторонних файлов — **4/5 в каждой**: во время обоих Python-тестов возникли по три `src/__pycache__/*.pyc` и `tests/__pycache__/*.pyc`. Они не относятся к смысловой правке, но не скрыты из подсчёта. Нет разницы между вариантами по этому критерию.

## Оговорки для переноса

- **5 пар, одна итерация каждой задачи**: нет повторов и confidence interval, порядок и серверное состояние/префиксный кеш могут искажать latency и usage. Только описательная локальная статистика.
- A **намеренно искусственно перегружен** и не является измерением конкретного существующего AGENTS.md пользователя; эффект обусловлен сравнением с этим слабым baseline.
- Менялись `AGENTS.md`, skill metadata, root/body **вместе**. Эксперимент **не показывает**, что именно дало 46,72% экономии.
- Тесты короткие, с предельно простой предметной областью. Не измерялись долгие multi-file задачи, persistence/approval границы, баги production, реальные database migrations, качество других моделей, человеческий review.
- Характеристики модели получены из явно закреплённого параметра Codex CLI и успешного probe. Server-side immutable model snapshot не был отдельно аттестован.
- `--ignore-user-config` отключил пользовательский config Codex, но сам клиент всё ещё использует штатную авторизацию; стенд не копировал `CODEX_HOME` и ничего не изменял в нём.
