## Метод статьи, опубликованные результаты и ограничения

В Sections 3.1–3.3 авторы предлагают **две формы** опыта: `single-artifact` (описание задачи, summary вклада и snippets) и `artifact-pair` (связь двух артефактов). При поиске применяется retrieval семантических представлений описаний, затем **LLM-classifier релевантности** к каждому кандидату и соседнему артефакту. Опыт добавляется к initial prompt и результатам search-tool. Метод требует проверять старые сведения по текущему документу: при конфликте приоритет у **текущего источника**. Appendix A.2 описывает получение записей из предыдущих reasoning traces, Qwen3-8B-Embedding и DuckDB для хранения. Это существенно шире простой связи Markdown между карточкой и обзором.

В Section 4 и Appendix D: многокорпусная оценка (файлы, техническая документация, code tasks, SQL и QA), преимущественно ReAct baseline, порядка 100 оценочных задач на набор, по умолчанию 80% задач для статического experience-store и остальные для оценки. Часть quality scores установлена **LLM-as-judge**, стоимость вычислена по token usage/API pricing, а не по наблюдаемому production счёту или wall-clock SLA. Авторы приводят до **+11,0 пунктов качества** и до **−50,5% online cost** в **различных конфигурациях**; усреднённо описаны +3,9% относительного score и −20,8% online cost против указанных baselines. Эти цифры относятся **только к их экспериментам**, не к проектам владельца.

**Ограничения:** статическое обучение/проверка на связанном корпусе, возможная leakage корреляций между задачами, стоимость offline indexing/embedding/LLM relevance, устаревшие или неверно извлечённые summaries, privacy/ACL при соединении отдельных артефактов. В публикации нет отдельной исчерпывающей секции Limitations, поэтому ограничения реконструированы из setup/analysis и свойств метода; отсутствие production-долговременного online evolution не следует считать доказанным решением.

## Независимый офлайн-тест навигации по связям

[Исполняемый тест](../../experiments/experienceindex/2026-11-07-link-retrieval.py) / [JSON со всеми 33 случаями и отрицательными контролями](../../data/results/experienceindex/2026-11-07-link-retrieval.json).

Зафиксированный corpus: **155 публичных Markdown-файлов** из `studies/` и `reviews/`; 33 отдельных карточки со ссылкой на датированный обзор в собственном source namespace. В качестве query выбраны заголовки H1 карточек. Внешний **детерминированный navigation oracle** — существование **последнего явно указанного** обзора, подтверждённое exact href, путем `reviews/<source>/...` и SHA-256 обеих сторон. Это не слепая человеческая разметка topical relevance, не новый gold answer к научной работе.

**A:** стандартный словарный BM25 по полному Markdown, Top-5. **B:** тот же BM25 Top-5, затем до одного доверенного hop от первого source card в Top-3 к самому позднему **явно связанному** обзору с актуальными хешами. Отдельного LLM relevance classifier, embeddings и learning from previous traces **нет**.

| Проверяемый показатель | BM25 (A) | BM25 + проверенный link-hop (B) |
| --- | ---: | ---: |
| Целевой обзор в Top-5 | **32/33** | **33/33** |
| Дополнительно найдено | — | **1/33** |
| Потерянных попаданий | — | **0/33** |
| Подтверждённое улучшение научного ответа агента | **не измерялось** | **не измерялось** |

Валидация источников содержит **4/4** отрицательных контроля: `stale_source_hash`, `stale_target_hash`, `missing_target`, `wrong_namespace` — все отказали без вставки связи. Дополнительный **адверсариальный контрпример**: другая ссылка на более старый обзор **того же** источника с корректным SHA и namespace проходит структурный gate, хотя **не соответствует** целевому «последнему обзору». Следовательно, корректность SHA и ссылки не гарантирует актуальную или смысловую релевантность; требуется независимое relevance/recency решение.

Наблюдаемая прибавка к recall очень мала: BM25 уже имел **97,0%** navigation-hit на данном искусственном наборе. Эталон задаётся самими ссылками в карточках, H1-запросы тесно связаны с индексируемым содержимым, так что тест склонен завышать baseline и успех расширения; нельзя использовать 33/33 как оценку качества агента. Затраты/время — локальный CPU/память Python на небольшом публичном корпусе, **без** offline-индексации дорогой модели, эмбеддингов, LLM evaluator, production DB/IO. Никакая денежная/latency выгода не доказана.

### Независимая контрпроверка

Оракулы вычисляются **без ZCode**: отдельная буквальная валидация href/path и SHA, обязательный pinned Git tree, четыре инъекции нарушения целостности, один контрпример свежести. [Второй независимый Node.js oracle](../../experiments/experienceindex/2026-11-07-link-oracle.mjs) из **отдельного исходного кода** перечитал все 33 пары через `git show <pin>:<path>`, сверил ссылки и SHA и отклонил подменённый SHA: **33/33 provenance checks PASS + mutation rejected** ([машинные результаты](../../data/results/experienceindex/2026-11-07-link-oracle.json)). Он подтверждает структуру и членство target в записанной выдаче, но **не** пересчитывает BM25 независимо и **не** судит о семантической релевантности.

Два последовательных advisory критика ZCode (роли `methodology`, `adversarial`) были вызваны отдельно с публичными отрывками Sections 3–5. **0/2 COMPLETE, 2/2 BLOCKED_PROVIDER**: первая роль `TIMEOUT` (~45 с), вторая `NONZERO_EXIT` (~14 с). Более ранний запуск с расширенным контекстом также не завершился, поэтому слепое повторение прекращено. [Протокол](../../data/results/experienceindex/2026-11-07-council.json) / [скрипт](../../experiments/experienceindex/2026-11-07-council.py). **Ни согласия моделей, ни внешнего модельного вердикта не получено**; научный статус работы не повышается. Независимая от моделей проверка ограничена кодом, Git и хешами.

## Итог, инженерные trade-offs и следующий gate

**Вердикт:** `FULL_SOURCE_RECHECKED`; `ACCEPT_BOUNDED_EXPLICIT_LINK_NAVIGATION` для собственных 33 navigation-oracles, `REWORK_RELEVANCE_AND_RECENCY`, `DEFER_EXPERIENCEINDEX_INTEGRATION`, `NO_PRODUCTION_APPROVAL`.

- **Плюс:** проверенный ссылочный граф при пропуске карточки/обзора может увеличить полноту без дополнительных LLM calls; единичный новый hit подтверждён.
- **Минус:** offline-index и перезапись связей добавляют CPU/RAM/FS IO и сложности; близкий к потолку baseline снижает потенциальный выигрыш. Semantic relevance и stale/ACL gate не являются бесплатными.
- **Следующее проверяемое решение:** 50–100 **независимо размеченных** вопросов реальных пользователей к разрешённому корпусу, gold `repo@SHA:doc`, BM25 против BM25+link и BM25+semantic relevance, no-match/negative controls, изменения версий и разграничение доступа. Отдельно считать полноту ответа, false insertion, token cost, полный indexing cost, p50/p95, CPU/RAM/IO. Только если выигрыш устойчив и стоимость приемлема — предметное решение по Wiki_PG/dsh-team-context; иначе **NO_IMPLEMENTATION**.
