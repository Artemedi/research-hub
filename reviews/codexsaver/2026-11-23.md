## 1. Перевод и верифицированный механизм

Текст `win first on readonly specialists / win second on bounded verifiable patch work / keep risky judgment and final review in Codex` означает: *сначала получать экономию на дешёвых read-only объяснениях/поиске/ревью; затем на коротких, проверяемых патчах; сложные/опасные архитектурные, security и deployment-решения и финальное принятие оставлять Codex*. Это **product thesis**, не доказательство безопасности/экономии для любого workflow.

Изучены pinned `README.md`, `SPEC.md`, `AGENTS.md`, `pyproject.toml`, benchmarks 2026-05-12..31, `codexsaver/{router,policy,agent_registry,agent_router,pi_agent,orchestrator,work_packet,verifier,engine,config,installer}.py`, `codexsaver_mcp.py`, `cli.py`, дерево tests. В репозитории **нет** `.github/workflows` — нельзя утверждать CI gate для этой ревизии по наличию Python tests.

- **VERIFIED — разделение ролей и частичный fallback:** v1 [`router.py:27–79`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/router.py#L27-L79) классифицирует по `str substring` (`find`, `test`, `docs`, `refactor`, high-risk слова), возвращает `deepseek` либо `codex`. V3 [`orchestrator.py:158–251`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/orchestrator.py#L158-L251) последовательно выполняет work-graph, параллелит readonly/patch batches, изолирует изменения в копии workspace и возвращает `aggregate_patch` и `needs_codex` при отказе. Финальная проверка Codex — **следующий шаг в тексте результата**, не автоматическое доказательство независимого рецензирования.
- **VERIFIED — keyword risk ≠ authoritative sandbox:** [`policy.py:7–113`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/policy.py#L7-L113) сначала ищет доменные слова (`auth/schema/database/infra/secrets`), затем слова действий; это эвристика, которая не строит AST/semantic call graph и может пропустить опасную операцию, описанную иначе. Наоборот, безопасные задачи с keywords могут дать ложное блокирование. `AGENTS.md` содержит policy как текстовое поведение, не ACL.
- **HIGH — v1 executes worker-proposed shell:** [`verifier.py:44–100`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/verifier.py#L44-L100) берёт `commands_to_run` из JSON результата дешёвого worker и запускает каждый через `subprocess.run(command, shell=True, cwd=workspace)` без allowlist или sandbox, в этом кодовом пути нет даже `timeout`. Наличие допустимого task risk не ограничивает побочные действия shell. Это **source-confirmed high-impact trust-boundary concern**; не тестировали exploitation и не утверждаем RCE по сети без предпосылок, но модель уже является потенциально недоверенным источником shell commands.
- **HIGH — v2 «sandbox» = copytree/tmpdir, not OS isolation:** [`work_packet.py:290–424`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/work_packet.py#L290-L424) копирует рабочие файлы в `tempfile.mkdtemp`, применяет patch через `git apply`, затем запускает `packet.allowed_commands` с `shell=True`, `timeout=120`, но *на том же хосте* с правами пользователя, сетью, HOME/credentials. Это механическая изоляция файлов патча, не process/filesystem/network isolation. Команда с абсолютным путём или сетевым вызовом технически может выходить за скопированный каталог. Даже пользовательская allowlist — это список разрешённых command strings, а не запрет действий внутри процесса.
- **HIGH — v3 "readonly" is a prompt constraint:** [`orchestrator.py:597–612,875–892`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/orchestrator.py#L875-L892) передаёт в Pi/worker prompt `Do not propose patches`; [`pi_agent.py:25–56`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/pi_agent.py#L25-L56) выполняет команду Agent Card как subprocess без container, Linux namespaces или удалённого read-only mount. Названия полей `filesystem_policy`/`network_policy` [`agent_registry.py:75–99`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/agent_registry.py#L75-L99) записываются в задачу, **не** гарантируют применение политик на уровне kernel. Формулировка `readonly` подтверждает intended output discipline, не невозможность side effects.
- **SECURITY — discovered agent cards are executable code configuration:** [`agent_registry.py:45–99`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/agent_registry.py#L45-L99) загружает `*.agent-card.json` из workspace и HOME, включая поле произвольной команды; [`pi_agent.py:69–93`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/pi_agent.py#L69-L93) использует эту команду. Поэтому сторонний/скопированный агент-каталог сам становится executable trust input. Нельзя загружать недоверенный проект как `workspace` и исполнять карточки без строгого allowlist и отдельного UID/изоляции.
- **VERIFIED — global config credential changes:** README рекомендует `codexsaver install`, который меняет `~/.codex/config.toml`, и `auth set`, который пишет API key в `~/.codexsaver/config.json` и `~/.pi/agent/auth.json` с правами 0600. 0600 защищает от других локальных UID, **не** от агента/скрипта под тем же UID. `setup/install` не исполнять в текущей Codex/DSH среде.
- **VERIFIED — patch policy is limited:** [`work_packet.py:447–491`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/work_packet.py#L447-L491) проверяет changed filenames по `+++ b/`, filename fnmatch и размерам diff, keywords secret/protected. Не объявлять проверку патчей полноценным validation of symlinks, git mode changes, rename, unsafe effects, verification scripts или semantic correctness. [`orchestrator.py:723–758`](https://github.com/fendouai/CodexSaver/blob/fe44dc105070c1f40eef29d9be76438edeab9987/codexsaver/orchestrator.py#L723-L758) агрегирует в выделенном временном рабочем дереве, не переписывая original root при обычном v3 successful result; однако запуск worker/commands по прежнему не сдерживается только cwd.
- **VERIFIED — test evidence:** tests представлены в `tests/test_*.py`, но git repository не содержит `.github/workflows` для этого snapshot. Ни `pytest` автора, ни собственные эмуляции безопасности нами не запускались. Статус тестов заявляется **AUTHOR_CLAIMED**, до запуска нельзя выдавать PASS.

## 3. Проверяемая гипотеза и A/B/C — не запускались

**H1:** на безопасных read-only операциях fixed synthetic repo дешёвый specialist/parallel graph + дорогой независимый reviewer сократит total dollar/token cost **при неизменной точности ответов, полном audit trail и отсутствии неразрешённых действий**. **H0:** стоимость review, пересылки контекста и повторений компенсирует экономию дешёвых токенов; prompt-only readonly и provider routing расширяют attack surface.

- **A:** штатный single Codex для одинаковых изолированных объяснений, анализа плана, поиска и source review на *фиктивном* коде, с независимым gold/ground-truth oracle.
- **B:** отдельно написанная **policy-only** эмуляция staged delegation на том же наборе: trusted host запускает cheap read-only model без direct shell/filesystem, получает текст+citations, Codex reviewer выполняет финальное сравнение. Никакого копирования CodexSaver code/license.
- **C:** CodexSaver pinned source только после license/security owner gate, отдельный UID + isolated rootless Podman network policy + empty HOME, synthetic repo, mock/fake provider. Проверка, что `readonly` действительно не может write/exec/exfiltrate, malformed Agent Card, untrusted `commands_to_run`, path traversal/symlinks, timeout/process tree cleanup, strict command IDs and patch allowlists, fail-closed secrets, adversarial keywords на русском/английском. Не утверждать, что C можно безопасно запускать без исправления найденных trust-boundary issues.
- **Metrics:** end-to-end `cost_usd` measured all providers/route/fallback/approval, input/output tokens by model, latency p50/p95, independent answer correctness/citation-grounding, accepted correct tasks/hour, reviewer minutes and rejected patches, near-miss unsafe actions, unauthorized file and network attempts, CPU/RAM/sandbox cost. Один benchmark для A/B/C с frozen snapshots, random paired order, 20+ tasks and 5+ repetitions.
- **Hard gate:** `0` unauthorized side-effects/commands, no private input egress, 100% accurate ground-truth on accepted outputs within benchmark, controlled human review, no unsafe shell or unverified licensing, measurable **total** savings not just hypothetical per-token price. Otherwise `REJECT_RUNTIME / REFERENCE_ONLY`.
