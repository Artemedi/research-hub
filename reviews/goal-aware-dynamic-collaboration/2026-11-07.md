## Что утверждают авторы

В [Section 4.1](https://arxiv.org/html/2610.39193v1) GAD описывает динамически разрастающийся execution graph. Каждый узел фиксирует исходную цель `g`, условия приёмки `K`, статус и зависимости; worker может предложить decomposition, но решение проверяется контроллером. [Section 4.2](https://arxiv.org/html/2610.39193v1) формирует контекст узла из исходной инструкции, локальной цели, acceptance, собственной истории и **верифицированных** результатов зависимостей; unrelated global history не копируется бездумно. Публикация результата child требует отдельной проверки; **лишь проверка исходной корневой цели** разрешает завершение всего задания (Appendix B, Algorithm 1).

Авторы сообщают для Terminal-Bench 2.1 Sonnet 4.6 **71,9%** против **65,2%** у сильнейшего MAS baseline, для Qwen3.7-Plus **64,0%** против **57,3%**. На SWE-bench Pro Hard-51 эффект иной; нельзя переносить эти проценты на наши задачи. Испытаны 89 Terminal-Bench задач и 51 Hard-51; до 3 workers одновременно, до 1 000 tool calls и 2 000 model calls на задачу, без агрегированного ограничения токенов. Семантический verifier применяет базовую модель, **не независимый test oracle**. Изменения в topology, расход токенов, model family и evaluation budget мешают причинно приписать прирост только DAG/acceptance; для наших проектов нужны отдельные измерения.

## Реальный кодовой шов и независимый испытательный стенд

**Пин:** `Artemedi/dsh-runtime@3feed5d0d9a8a0f8e75c0a63f37b530d6eebc5dc`. Реальный файл [`packages/experimental/agent-team/src/task-graph.ts:26-68`](https://github.com/Artemedi/dsh-runtime/blob/3feed5d0d9a8a0f8e75c0a63f37b530d6eebc5dc/packages/experimental/agent-team/src/task-graph.ts#L26-L68) (SHA-256 `a726081289a2f7a848f69109a750db3ead0d95b88ab0adfdae0477f749b8f490`) содержит **уже существующий** `assertTaskGraphCandidate`: проверка missing/duplicate/cycle/self ссылок. Мы **не предлагаем писать второй валидатор**. Выполнен оригинальный TypeScript через Node 22 `--experimental-transform-types` (требуется из-за parameter properties TS) без изменения файла/репозитория.

Воспроизводимый [JS-стенд](../../experiments/goal-aware-dynamic-collaboration/2026-11-07-dag-guard.mjs) использовал 5 наборов ID × 7 типов графа: линейный DAG, diamond, duplicate dependency, self-dependency, absent/deleted blocker, cycle. Отдельная матрица 5 × 7 намеренно упрощённых сценариев evidence/root проверяла `VERIFIED`, hash, scope, declared dependencies и root acceptance. В каждой из 35 synthetic scenarios «слабый контрпример» **намеренно принимает любой заявленный worker DONE**; это не реальный existing MAS implementation.

| Показатель | Наблюдение | Что действительно доказано |
| --- | ---: | --- |
| Реальный validator `dsh-runtime` | **35/35** совпали с oracle | Проверяемые пять вариантов каждого из семи типов graph relation |
| Внешний guarded gate | **35/35** совпали с oracle | Пять валидных сценариев приняты, 30 инъекций контракта/корня отклонены |
| Наивный baseline «self-report DONE = accept» | **30/30 ложных принятий** в негативных классах | Демонстрация специально некорректной политики, не prevalence в реальных агентах |
| Guarded acceptance | **5/5 валидных**, **0/30 ложных** | В этом наборе fake receipts; не security attestation |
| Передача глобального списка vs только VERIFIED dependencies | **210 vs 55** synthetic context items | Число передаваемых элементов, **не** измеренные токены / latency / RAM |
| Независимый Python oracle | **70/70** записанных результатов + mutation rejected | Отдельная декларативная таблица сверяет каждый записанный исход и контрольную мутацию |

[Machine evidence](../../data/results/goal-aware-dynamic-collaboration/2026-11-07-dag-guard.json) с 70 cases, pinned code/file SHA и состояниями / [декларативный независимый verifier](../../experiments/goal-aware-dynamic-collaboration/2026-11-07-dag-oracle.py) / [его JSON](../../data/results/goal-aware-dynamic-collaboration/2026-11-07-dag-oracle.json). Оракул независим от модели и имеет отдельную реализацию, однако сам проверяет *записанные исходы* и pinned hash, не переписывает полный алгоритм исходного `assertTaskGraphCandidate`. Хеш/статус могут быть сфальсифицированы процессом с теми же правами; модельные tool calls не выполнялись. Ограничения не замаскированы названиями `PASS`.

## Совет роя

Две последовательные роли ZCode (`methods`, `falsifier`) получили только короткие **публичные** excerpts из HTML и агрегаты эксперимента, без приватных проектов и без инструментов. [Скрипт](../../experiments/goal-aware-dynamic-collaboration/2026-11-07-council.py) / [модельные receipts](../../data/results/goal-aware-dynamic-collaboration/2026-11-07-council.json). **Результат: 0/2 COMPLETE, 2/2 BLOCKED_PROVIDER** (`methods=TIMEOUT`, `falsifier=NONZERO_EXIT`). Следовательно, **независимого модельного совета не получено**; научный статус не повышается. Оба отказа сохранены с хешами запросов и временем, повторение без нового протокола не требуется. Детерминированная проверка и отдельный Python oracle остаются единственным подтверждённым независимым измерением на данном этапе.

## Диспозиция

**`ACCEPT_BOUNDED_GRAPH_AND_ROOT_GATE_LAB`** — ограниченная независимая проверка Git-pinned graph-contract / dependency evidence / root-acceptance. **`DEFER_RUNTIME_CHANGE`**, **`NO_NEW_PROJECT_FIT`**, **`NO_PRODUCTION_APPROVAL`**, `BLOCKED_MEASURED_END_TO_END_BENEFIT`. Авторы не воспроизведены на Terminal-Bench/SWE, а наш intentionally weak naive baseline **не доказывает** прирост успешности от GAD. Нужен отдельный end-to-end controlled experiment на реальных задачах с одинаковыми бюджетами и test/build oracle; до этого не переписывать `dsh-runtime` и не создавать глобальных абстракций.
