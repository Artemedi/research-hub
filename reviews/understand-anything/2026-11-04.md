## Устройство и исправление первичного screening

Проект комбинирует статическое извлечение с LLM-анализом для графа кода и отдельного графа wiki. [SQL config](https://github.com/Egonex-AI/Understand-Anything/blob/4e6d3299017a7432da15957874992837a315c5b4/understand-anything-plugin/packages/core/src/languages/configs/sql.ts) распознаёт расширение `.sql`, есть SQL prompt snippet и отдельный [SQLParser](https://github.com/Egonex-AI/Understand-Anything/blob/4e6d3299017a7432da15957874992837a315c5b4/understand-anything-plugin/packages/core/src/plugins/parsers/sql-parser.ts). Поэтому предварительный вывод по одному README нуждается в уточнении: **SQL-обработка в исходниках есть**, но реализация не подтверждает полный SQL/T-SQL dependency graph. Сам parser описывает ограничения: не обрабатывает procedures, triggers и schema-qualified names; возвращает определения таблиц, представлений и индексов, а не полные edges зависимостей. Prompt-указания на возможные связи не являются доказательством их фактической точности.

## Изолированные проверки

Оригинальные 9 тестов knowledge parser `tests/skill/knowledge/test_parse_knowledge_base.py` прошли с копиями трёх pinned source/test файлов в сети-изолированном bwrap и временном HOME/TMP. Они проверяют малые synthetic Markdown fixtures, не существующую вики пользователя.

[Наш fixture](../../experiments/bk048-understand-anything/sql-fixture.mjs) непосредственно импортирует исходный `sql-parser.ts` через Node 22 type stripping, без сети, SQL Server, реальных схем и модификации исходника. Результаты:

| Synthetic SQL | Реальные имена, возвращённые parser | Независимое ожидаемое значение |
| --- | --- | --- |
| `CREATE TABLE dbo.users (id INT);` | `dbo` | `dbo.users` |
| `CREATE TABLE [dbo].[users] (id INT);` | нет определения | `dbo.users` |
| комментарий с `CREATE TABLE fake`, затем реальный `CREATE TABLE real` | `fake`, `real` | только `real` |
| `CREATE TABLE users (id INT);` | `users` | `users` |

Fixture проверяет воспроизводимость фактического поведения, а колонка oracle показывает расхождение; он не тестирует весь graph builder или LLM postprocessing. Воспроизведение после получения pinned SQLParser как `/path/to/sql-parser.ts`, Node v22.23.2:

```sh
mkdir -p /tmp/ua-source
cp /path/to/sql-parser.ts /tmp/ua-source/sql-parser.ts
bwrap --unshare-all --die-with-parent --ro-bind /usr /usr --ro-bind /lib /lib --ro-bind /lib64 /lib64 --ro-bind /path/to/node /node --ro-bind /tmp/ua-source /source --ro-bind "$PWD/experiments/bk048-understand-anything/sql-fixture.mjs" /fixture.mjs --tmpfs /tmp --proc /proc --dev /dev --setenv HOME /tmp --chdir /source /node --experimental-strip-types /fixture.mjs
```

`LAB_VERIFIED` относится только к четырём synthetic parser cases и девяти wiki unit tests; качество настоящего графа, точность вызовов/impact, LLM и приватные данные `NOT_RUN`.
