# Google Antigravity CLI 1.5.11 — bounded lifecycle probe

Дата: 2026-11-26. Источники: [headless](https://antigravity.google/docs/cli/headless/), [hooks](https://antigravity.google/docs/hooks), [rules](https://antigravity.google/docs/rules/). Документация описывает проектные hooks и Stop decision continue; эксперимент проверяет наблюдаемое поведение установленного CLI. Полный обзор всех capabilities не выполнен (PARTIAL_SOURCE_REVIEW).

## Метод

Одноразовый git workspace, синтетический AGENTS.md с маркером RULE-7B9C. Agent prompt запрещает читать файлы и вызывать инструменты. Hook пишет только имя события и наличие conversationId; первый Stop просит добавить GATE-4D2E, второй разрешает завершение. Sandbox включён; разрешения не отключены. JSON/NDJSON результаты и журнал событий — oracle, а не самоотчёт агента. Глобальные настройки не изменялись. Модель не закреплена; это smoke, не сравнительный benchmark.

## Результаты

- plan + relative hook path + JSON: exit 0, SUCCESS, RULE-7B9C, hook journal отсутствует; 10938 total tokens.
- auto + absolute hook path + stream-json: exit 0, SUCCESS, RULE-7B9C затем RULE-7B9C GATE-4D2E, последовательность SessionStart, PreInvocation, PostInvocation, Stop, PreInvocation, PostInvocation, Stop; 13195 total tokens (8628 cache read).
- plan + absolute hook path + JSON: exit 0, SUCCESS, оба маркера, те же семь событий; 14167 total tokens (9415 cache read). Plan mode сам по себе не исключает hooks. Первый опыт также отличался способом выбора пути журнала; причина отсутствия событий не изолирована.
- Наблюдаемый повторный invocation после Stop подтверждает bounded continuation. Срабатывание hooks зависит от конфигурации; первая пара опытов меняет несколько факторов. Нельзя приписывать отсутствие хуков только режиму либо только пути.
- Накладные расходы нельзя вывести из сравнения этих двух запусков: режим, формат, путь, история и cache различаются. Нет проверки отказоустойчивости, security boundary, hard deny, subagents или реальной сборки. Exit 0 не является доказательством выполнения quality gate; headless permissions могут soft-deny действие.

## Следующий этап

1. Разделить mode/path/output и повторить 5 раз на вариант; закрепить версию и model slug. Проверять отсутствие tool calls по stream events.
2. Проверить PreToolUse deny на безопасной синтетической операции с независимым filesystem oracle, PostToolUse и scoped permissions; hard-stop/timeout при сбое hook, ограниченный retry.
3. Проверить glob/model_decision rules, subagent isolation, структурированный stream contract и cancellation.
4. После pinned source audit DSH выполнить парный A/B на 10 одинаковых задачах в одноразовых worktrees. Измерять completion, scope violations, gate bypass, p50/p95 latency, tokens; pass: ноль обходов gate/неразрешённых изменений, завершение не хуже baseline. Бюджет: не более 2 retries на задачу, 60s smoke timeout; отдельное согласование нагрузки.
5. Интеграция запрещена до подтверждения seam и решения владельца. Риски: proprietary runtime, auth/quota, schema drift, стоимость повторных invocation, hook execution privileges и утечка контекста. Лицензия/условия распространения не проверены.

Практическая ценность гипотезы 8/10 (машинный контроль жизненного цикла); сложность 6/10 (неизвестный seam, стабильность контрактов и permissions). Это качественная оценка, не измеренный выигрыш.
