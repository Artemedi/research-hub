# MCCL — удержание и обновление наблюдений в Wiki_PG

**Результат.** В двух одинаковых прогонах новая сессия Wiki_PG совпала с полной сборкой в 30 из 36 сравнений. Во всех шести расхождениях байты снимка изменились при сохранении размера и времени изменения файла. Штатная сборка пропустила обновление, и новая сессия продолжила отдавать предыдущее значение и его хеш. Следующее видимое изменение запустило пересборку и устранило расхождение.

[Протокол](../../experiments/memory-centric-continual-learning/2026-11-25-wiki-pg-catalogue-retention-protocol.md) · [Скрипт](../../experiments/memory-centric-continual-learning/wiki-pg-catalogue-retention.py) · [Данные](../../data/results/memory-centric-continual-learning/2026-11-25-wiki-pg-catalogue-retention.json)

MCCL предлагает измерять сохранение прежних знаний и адаптацию к изменившимся фактам. На локальном Wiki_PG мы перевели эти свойства в проверяемый контракт чтения снимков. Сравнивались фактические ответы штатного SQL-каталога с полным пересозданием индекса и эталоном из файлов. [Первоисточник MCCL, arXiv v1](https://arxiv.org/html/2610.29357v1)

| Изменение | Наблюдение |
| --- | --- |
| Снимок другого хоста с той же датой | Значение исходного хоста и его история сохранились |
| Исправление с видимым изменением метаданных | Новый читатель вернул исправленное значение с новым SHA‑256 |
| Исправление с прежним размером и временем изменения | Новые читатели штатного индекса вернули прежний снимок, а полная сборка показала исправление |
| Следующее видимое обновление | Штатный индекс снова совпал с полной сборкой |
| Удаление позднего снимка | Штатный индекс и полная сборка вернули ранний снимок. Открытый читатель сохранил исходное поколение |

Один и тот же псевдоним разрешался в нужный хост на всех этапах. Время наблюдения и путь сверялись отдельно от числа. Пропуск при одинаковых метаданных следует из оптимизации для предполагаемого добавления записей без перезаписи. Сценарий с искусственной заменой проверяет границу этого предположения. Он не устанавливает, что рабочий процесс Wiki_PG выполняет такую замену.
