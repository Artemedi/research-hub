## Как устроено

MCP-сервер создаёт state manager и worker manager для каталога проекта; задачи, изменения состояния и checkpoints хранятся в файлах проекта. Запуск создаёт рабочий Git worktree, готовит prompt и запускает Claude CLI в tmux; предусмотрены проверки результата, retry, plan-review и восстановление. Протоколы регистрируются отдельно. Декларации README о надёжном принудительном исполнении ограничений, изоляции и восстановлении не являются сами по себе доказательством работы и требуют проверок границ.

В дереве `src/` вызов setter найден только внутри фабрики `createEnforcementIntegration`; вызова самой фабрики штатным сервером не найдено. Проверка перед запуском условна: [`manager.ts:596–621`](https://github.com/cj-vana/claude-swarm/blob/31f19199bf3557cda4860231186a06b72c8edb94/src/workers/manager.ts#L596-L621). Вывод — **статический, для штатного пути данного commit**; интерактивное воспроизведение не проводилось, и нельзя исключать внешнее подключение через иной embedding-код.
2. **Разрешения и изоляция:** [`manager.ts:55–80`](https://github.com/cj-vana/claude-swarm/blob/31f19199bf3557cda4860231186a06b72c8edb94/src/workers/manager.ts#L55-L80) выбирает `bypassPermissions` по умолчанию и разрешает Bash/Write/Edit, если окружение явно не переопределяет значения. Git worktree отделяет рабочие деревья, но не является границей безопасности ОС и общих Git-объектов.

Это потенциальная потеря незакоммиченных данных при повторном использовании ID. [`killWorker`](https://github.com/cj-vana/claude-swarm/blob/31f19199bf3557cda4860231186a06b72c8edb94/src/workers/manager.ts#L2174-L2187) отправляет tmux kill и подавляет ошибку: завершение всего дерева процессов независимо не проверено.

Код мониторинга читает вывод workers при проверках; это не доказательство синхронной блокировки каждого опасного действия.

## Следующий A/B и решение

`BLOCKED: MEASUREMENT_MISSING`. Frozen SHA проектов и инструмента; disposable Git без секретов, network denied, заглушки CLI и tmux, фиксированные расписания событий. A — существующая orchestration/recovery, B — локальная модель соответствующих механизмов Swarm без внешних LLM и без неконтролируемого удаления. В одинаковом порядке: два worker с конфликтом, отказ worktree, потеря lock, повреждённый checkpoint, прерванный worker, двойной replay и остановка процесса. Независимый oracle сравнивает сохранённые файлы, идентичность задач, append-only историю, живые PID и фактические разрешения; mutation control принудительно отключает enforcement и должен быть обнаружен. Метрики: ошибки state, потерянные изменения, повторные действия, время восстановления, CPU/RAM/IO, latency и цена (offline = 0). Задать критерии до запуска, rollback — удалить отдельную среду. Реальные Claude calls, общий рабочий Git и production требуют отдельного owner gate; в этом обзоре их не запускали.

Ценность 6/10, сложность 8/10 — предварительные оценки: идеи повторного запуска и независимой проверки сопоставимы с существующей архитектурой, но безопасность worker-пути и конфликты данных блокируют непосредственное использование. Production integration не разрешена.
