## Метод и результаты авторов

SIMURG вычисляет признаки на символах, регулярные правила, n-граммы, повторения, SimHash и ансамбль с порогом; `Simurg.feed` удерживает стартовые 350 символов, затем периодически анализирует поток и сообщает `clean/suspect/corrupt`. При обнаружении после выдачи части потока уже выданный текст нельзя отозвать без поддержки клиента. API guard добавляет retry/heal/fallback. Это защита от некоторых паттернов деградации вывода; она не устанавливает истинность нормального, но неверного ответа.

**PDF, table 2 (авторские данные):** 359 потоков, 119 test: 77/77 synthetic corrupt и 0/42 clean flags; median delay примерно 535 символов, 121 исторический production text, включая две обнаруженные деградации. Предположения: положительные примеры синтетические, выходы в основном один макроэкономический домен, независимость и переносимость на другие потоки не доказаны. Figure 5 в том же PDF содержит другие размерности классов (21+19+23+11=74, а не 77) и median 617, в то время как table указывает около 535: это не устранено. Репрезентативность при смене seed отдельно не проверена.

**Более поздний README v1.0.4:** 243 потока, test 81, TPR 78/80, только 1 clean тестовый поток, AUROC 0.55 и median 590. Это другие числа, а не повторение PDF; однопоточный clean test не даёт надёжной оценки false positives. Авторы сами указывают на доменные ограничения и необходимость калибровки.

## Проверка кода и наблюдаемые риски

1. **AUROC на связках с одинаковой оценкой некорректен.** [`evaluate.py:72–82`](https://github.com/doofzoff/SIMURG/blob/2831a92359cdaf1b38cc14f55e74251e09a91e0b/src/simurg/data/evaluate.py#L72-L82) сортирует пары score/label, не усредняя ранги ties. Для одинаковых оценок двух positive и двух negative выдал 1.0; независимый попарный oracle с половиной веса связки равен 0.5. Это опровергает корректность данной функции в таком случае, но не позволяет пересчитать отсутствующие исходные оценки PDF. Результаты AUROC надо воспроизводить исправленным внешним oracle.
2. **Заявленный гарантированный уровень false alarms не следует из реализации для всех входов.** [`fusion.py:75–86`](https://github.com/doofzoff/SIMURG/blob/2831a92359cdaf1b38cc14f55e74251e09a91e0b/src/simurg/detection/fusion.py#L75-L86) обрезает порог сверху 0.95. При 50 идентичных clean scores 0.99 и alpha 0.02 порог = 0.95, и такой же clean score получает `corrupt`: 100% на этом контрпримере. Также hard rule может обходить порог ([sentinel.py:100–106](https://github.com/doofzoff/SIMURG/blob/2831a92359cdaf1b38cc14f55e74251e09a91e0b/src/simurg/detection/sentinel.py#L100-L106)). Корректность калибровки нужно устанавливать для всей политики и нужной выборки, а не только предполагать exchangeability.
3. **Zero-leak ограничен буфером и успешным обнаружением.** [`sentinel.py:119–142`](https://github.com/doofzoff/SIMURG/blob/2831a92359cdaf1b38cc14f55e74251e09a91e0b/src/simurg/detection/sentinel.py#L119-L142) передаёт выпущенные chunks до следующего checkpoint; guard вызывает `on_token` до последующей проверки stitched-ответа ([openai_guard.py:146–157](https://github.com/doofzoff/SIMURG/blob/2831a92359cdaf1b38cc14f55e74251e09a91e0b/src/simurg/integrations/openai_guard.py#L146-L157)). Замена в UI — обязанность host; прошлый вывод нельзя считать никогда не показанным. Крупные chunks меняют фактические границы задержки.
4. **Fallback корпус:** [`dataset.py`](https://github.com/doofzoff/SIMURG/blob/2831a92359cdaf1b38cc14f55e74251e09a91e0b/src/simurg/data/dataset.py) при отсутствии внешнего корпуса использует три длинных seed-текста и может повторно использовать их как основу corruption, затем делит экземпляры случайно. Это не независимая проверка на новых авторах/шаблонах. [`evaluate.py:94–101`](https://github.com/doofzoff/SIMURG/blob/2831a92359cdaf1b38cc14f55e74251e09a91e0b/src/simurg/data/evaluate.py#L94-L101) собирает calibration scores из train streams после обучения модели на train, что также не доказывает независимую split-conformal калибровку.
5. **Безопасность/стоимость:** отдельный `websearch` отправляет поисковые запросы внешним провайдерам и включает встроенную конфигурацию доступа; retry/heal/fallback вызывают повторные запросы и могут передавать фрагменты ответа другому провайдеру. Секреты, медицинские данные, рабочие логи и реальные endpoint не использовались. Автообучение по результату повторной генерации само по себе не доказывает корректность метки.

## Наш ограниченный offline test

Linux, Python 3.14 / NumPy 2.3.5, `bwrap --unshare-net`, read-only source и пустой tmpfs/HOME; никаких API/моделей/сервисов. Пять upstream `tests/test_sentinel.py` выполнены как обычные Python-функции: **5/5**; это не полный pytest suite (pytest не установлен). [Эксперимент](../experiments/bk011-simurg/check-fixture.py) содержит независимый попарный oracle AUROC и конкретный calibration counterexample выше. Искусственный повторяющийся русский текст и повторяющийся SQL были отмечены `corrupt`, JSON fixture — `clean`, заведомый repetition loop — `corrupt`. Стресс-примеры нарочито повторяются: это не оценка доли ложных тревог на реальном русскоязычном или SQL-трафике. После релиза буфера на этих примерах уже было выпущено 1092 и 1120 символов соответственно. `LAB_VERIFIED` ограничен этими воспроизводимыми фактами, качество на проектах `NOT_MEASURED`.

Воспроизведение в отдельной среде, где `/path/python` — каталог Python runtime с NumPy, а `/path/SIMURG` — checkout указанного commit:

```sh
bwrap --unshare-net --ro-bind /usr /usr --symlink usr/bin /bin --symlink usr/lib64 /lib64 --proc /proc --dev /dev --tmpfs /tmp --ro-bind /path/SIMURG /source --ro-bind /path/python /runtime --ro-bind "$PWD/experiments/bk011-simurg/check-fixture.py" /fixture.py --setenv HOME /tmp/home --setenv PYTHONPATH /source/src --setenv PYTHONDONTWRITEBYTECODE 1 /runtime/bin/python3 /fixture.py
```

Перед запуском отдельно проверить точный SHA checkout и NumPy; зависимости не устанавливать автоматически. ОС/пути библиотек могут отличаться. Полный benchmark и реальные агенты не запускались.

## Минимальный A/B и решение

`BLOCKED: MEASUREMENT_MISSING`. Зафиксировать target SHA, версию источника и параметры; baseline A = без guard, B = guard в отдельном replay только для text deltas, без tool-call arguments. Размеченные синтетические train/calibration/test разделить **по источнику и шаблону**, включить чистые RU/EN, SQL, JSON, код, медицинские форматы без реальных данных, а также повтор, смену языка и мусор с известным onset. Повторить одинаковые потоки при chunk sizes 1/40/400 и разных границах; oracle независимо проверяет byte-exact SSE/JSON, tool calls, полные отозванные/показанные данные и детекторные исходы. Негативный контроль: равные scores AUROC и all-high clean calibration; отдельно test cancellation, connection end, retry budget и отказов. Измерять false aborts, precision/recall с интервалами, задержку/утечки символов, p50/p95, CPU/RAM/IO и стоимость повторов; до запуска задать пороги и обеспечить нулевой egress. Никаких production, платных LLM и пациентских данных. Откат — удалить временную replay-среду. Значимость 6/10, сложность 8/10 — предположение из-за двойного языкового стека и необходимости не ломать streaming contract. Не интегрировать и не воспринимать текущую калибровку как гарантию до исправления и независимого подтверждения.
