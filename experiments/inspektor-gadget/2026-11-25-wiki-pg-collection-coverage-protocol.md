# Inspektor Gadget — статусы сбора в Wiki_PG

1. Закрепить Wiki_PG на `d55721bb99bff25fae352341cfd630c048693d6b`. Взять за ориентир [исторический опыт с 40 контрольными событиями](../../reviews/inspektor-gadget/2026-11-06-privileged-podman-trace.md). Вместо запуска трассировщика использовать искусственные счётчики.
2. Проверить один отчёт без явного статуса секции. В секции оставить сообщение о запуске и искусственную метку аргумента. Через штатный SQLite проверить статус диагностической записи, покрытие и возможность найти метку лексическим поиском.
3. Проверить девять вариантов отчёта с явным статусом. Из опытного преобразования передавать только статус, код выхода, область и время. Успех ожидается только при завершённом сборе с ненулевым ожидаемым числом событий, совпадением счётчиков и отсутствием посторонних событий. При отказе в доступе и таймауте ожидать `degraded`, в остальных непроверенных случаях — `unknown`. Искусственная метка должна отсутствовать во всех девяти индексах.
4. Повторить тест с новыми временными каталогами и потребовать точного совпадения результатов. Остальные четыре обязательных инструмента в искусственном отчёте всегда имеют явный статус `ok`.

[Скрипт прогона](wiki-pg-collection-coverage.py) принимает путь к закреплённому checkout. Используются Python, PyYAML и SQLite FTS5. Секция `execsnoop` служит моделью существующего диагностического контракта Wiki_PG. Сбор eBPF, Podman и сеть для теста не нужны.
