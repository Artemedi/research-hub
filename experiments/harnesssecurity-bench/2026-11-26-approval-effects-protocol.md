# HarnessSecurity-Bench × DSH Runtime — решение о допуске и эффект

1. Взять чистый checkout DSH Runtime на `b6a1635b1200071754e2871b9d9453368e6daf23` и Node.js 24.

   ```text
   node --experimental-transform-types experiments/harnesssecurity-bench/approval-effects.mjs <pinned-dsh-checkout>
   ```

2. Запустить штатный метод запроса подтверждения. Журнал сессии, диспетчер ответов и исполнитель подставные. Для допустимого действия исполнитель увеличивает числовой счётчик. Отдельно сверять значение счётчика и записи запроса и решения, включая ID запроса и ID вызова.
3. Проверить девять сценариев по десять случаев. Разрешение должно давать один эффект после записи решения, остальные сценарии должны оставлять счётчик неизменным. В сценарии отмены дождаться начала запроса к отвечающему, отменить запрос и лишь после этого вернуть разрешение. В сценарии ошибки записи разрешение уже получено от отвечающего, но запись решения должна завершиться ошибкой до изменения счётчика.
4. Повторить матрицу трижды. Сравнить итоговые счётчики. Случайные ID подтверждений сверяются внутри каждой пары записей и не входят в итоговый JSON.

Действия ограничены памятью одного процесса. Подстановки не проверяют доставку решения через интерфейс, запись журнала на диск или вызов инструмента. Затраты на полноценное выполнение задачи и задержка ответа пользователя не измеряются.
