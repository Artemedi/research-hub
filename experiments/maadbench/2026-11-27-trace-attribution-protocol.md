# MAADBench × DSH Runtime — проверка синтетического журнала команды

1. Подготовить чистый checkout DSH Runtime на ревизии `b6a1635b1200071754e2871b9d9453368e6daf23`, Node.js 24.11.1 и установленный вне checkout пакет `zod@4.4.3`. Скрипт проверяет ревизию и хеши двух файлов проектора.

   ```text
   node --experimental-transform-types experiments/maadbench/trace-attribution.mjs <pinned-dsh-checkout> <zod-package-directory>
   ```

2. Воспроизвести по 12 журналов каждого из пяти сценариев. Граф содержит две исходные задачи, их сумму и удвоение суммы. Независимые эталонные значения для входа `s` равны `s + 2`, `3s`, `4s + 2` и `8s + 4`. Каждый вычисленный результат размещается в текстовом сообщении.
3. Сначала проверить, где штатный проектор отклоняет последовательность. При пропуске ревизии 2 эталон указывает на первое наблюдаемое нарушение, ревизию 3 задачи `left` на позиции 6. После отказа проектора расчёты не оцениваются.
4. Для принятых журналов использовать только доставленные сообщения. Если результат расходится с расчётом по наблюдаемым входам, считать его источником ошибки. Если совпадает с этим расчётом и расходится с независимым эталоном, считать ошибку унаследованной. Если результата или прямого входа нет среди доставленных сообщений, фиксировать отсутствие наблюдения. Сверить идентификаторы задач с заранее заданной разметкой для каждого сценария.
5. Повторить прогон трижды с разными входами. Счётчики должны совпасть. Все события и разметка созданы стендом.
