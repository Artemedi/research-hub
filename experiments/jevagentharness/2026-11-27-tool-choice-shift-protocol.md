# JevAgentHarness × DSH Runtime — перенос порога делегирования

1. Подготовить чистый checkout DSH Runtime `b6a1635b1200071754e2871b9d9453368e6daf23` и Node.js 24.

   ```text
   node --experimental-transform-types experiments/jevagentharness/tool-choice-shift.mjs <pinned-dsh-checkout>
   ```

2. Построить 48 калибровочных задач и три непересекающихся тестовых набора по 48 задач. Каждая задача содержит выбор арифметической операции, её масштабирование и форматирование итога. Сравнить итог с отдельно рассчитанным эталоном.
3. Использовать штатную проверку аргументов DSH. Названия инструментов проверять по лабораторному списку. Подобрать порог, который принимает максимум предложений без ошибок целой задачи на калибровочной выборке. Сравнить эталон, делегирование без порога и замороженный порог.
4. На двух наборах со сдвигом подставить высокую уверенность для неверных, но допустимых по схеме предложений. В одном наборе также изменить версию профиля. Повторить с дополнительным правилом, которое при новой версии возвращает выбор эталону. Считать делегированные решения, возвраты, отклонения схемы и решённые задачи.
5. Повторить на других входных числах с теми же классами предложений. Счётчики трёх повторов должны совпасть.

Лабораторный порог использует принцип делегирования выше заданной уверенности из статьи. Оценки уверенности, ответы и инструменты заданы стендом. Валидация схемы исполняется штатным кодом DSH. Время вызова модели, цена, GPU, память и ввод-вывод вне измерения. [Скрипт](tool-choice-shift.mjs) · [Данные](../../data/results/jevagentharness/2026-11-27-tool-choice-shift.json)
