# LIMBO × HermesAgent — проверка видимости созданной задачи

1. Зафиксировать ревизию HermesAgent `668689dded92affb16b6a3b3f63d4be43d3d80cd`. В локальном JSON указать `entry_path` и `publisher_path` для двух файлов этой ревизии. Имена функций задать в полях `entry`, `lookup`, `publish`, `generate`, `videos`, `fallback` и `context`. Они обозначают точку входа, поиск обработанных видео, публикацию, генерацию текста, два способа получения видео и загрузку контекста. Исходники и привязки из приватного проекта хранятся у владельца.
2. Запустить `python experiments/exactly-once-limbo/issue-readback.py <local-bindings.json>`. Скрипт проверяет SHA-256 обоих файлов, извлекает три определения функций и исполняет их с подставными зависимостями. Импорт приватных модулей, запуск внешней команды и обращение к сети отсутствуют.
3. Дважды вызвать точку входа для каждого видео. Подставной сервис различает подтверждённое создание, ошибку до создания, потерю подтверждения при видимой задаче с URL, видимой задаче без URL и скрытой от повторной сверки задаче. В ветке сравнения подставной генератор гарантирует URL в тексте. Это моделирует принудительное добавление URL в будущей реализации.
4. Сверить число вызовов и созданных задач с отдельными ожиданиями по каждому сценарию. Контроль до создания должен допустить повтор и оставить одну задачу. Скрытая задача должна выявить предел сверки по URL даже в ветке сравнения. Выполнить три последовательности по 20 случаев каждого типа на ветку.

Стенд держит только состояние текущего видео в памяти. Файловый ввод ограничен двумя закреплёнными исходниками и локальными привязками. Задержка видимости задана сценарием, а затраты реального сервиса и модели не измеряются.
