# Matoi × DSH Runtime — повторная проверка последствий и разрешений

1. Использовать чистый checkout DSH Runtime на ревизии `b6a1635b1200071754e2871b9d9453368e6daf23` и Node.js 24.11.1. Загрузить штатный `ApprovalService` и его компоненты диспетчеризации из этого checkout. Подставить локальный сеанс с журналом в памяти и вымышленного ответчика.

   ```text
   node --experimental-transform-types experiments/matoi/effect-revalidation.mjs <pinned-dsh-checkout>
   ```

2. В каждой из двух веток проверять текущее разрешение штатным сервисом перед каждым новым исполнением. В первой ветке пересчитывать последствия действия каждый раз. Во второй использовать предыдущий результат анализа, если вход, от которого зависит вычисление, совпадает. Считать все запуски анализа, включая заполнение кеша.
3. Прогнать шесть сценариев по четырём независимым входам. Проверить стабильное состояние, изменение посторонних данных, изменение значимых данных, отзыв разрешения, отсутствие ответчика и повтор операции с неизвестным исходом.
4. В случае неизвестного исхода сохранить запись о попытке и блокировать повтор с тем же идентификатором до сверки. Это правило стенда. Пара событий одобрения из DSH подтверждает решение по запросу. Свидетельством результата служит отдельная запись стенда.
5. Сверить исход каждого случая, пары событий запроса и ответа, число вызовов анализа, число живых проверок и число вызовов вымышленного инструмента. Повторить с другими входами. Время работы и свойства восстановления после перезапуска в этом прогоне не измеряются.
