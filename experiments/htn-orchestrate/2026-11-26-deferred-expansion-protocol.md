# HTN-Orchestrate — сравнение момента планирования зависимой ветки

1. Подготовить чистый checkout авторского HTN-Orchestrate на `0bccf18d813298e5c2a33961dbf56b907bd8b133` и изолированное окружение Python 3.12 с `pydantic==2.12.5`.

   ```text
   python experiments/htn-orchestrate/deferred-expansion.py <pinned-htn-checkout>
   ```

2. Использовать штатное дерево и модель узлов. Корень содержит подзадачу определения операции и зависящую от неё вычислительную ветку. Проверить четыре сценария по 12 входов. Ранняя догадка совпадает с распознанной операцией либо расходится с ней. Два контрольных сценария моделируют ошибку предшественника и завершение с нерешённым результатом.
3. На каждом входе сравнить три варианта. Ранняя догадка заранее планирует сложение и меняет план при расхождении. Фиксированный вариант заранее планирует сложение и вычитание. Отложенный вариант планирует только после получения результата. Во всех трёх случаях стенд проверяет готовность по дереву и наличие решённого результата перед добавлением дочерних узлов.
4. Сверить итог корня с заранее заданным арифметическим эталоном. Для каждого варианта отдельно считать планы, отброшенные планы, перепланирования и выполненные вычислительные узлы. Повторить весь прогон трижды и сравнить JSON.

Скрипт загружает два модуля дерева. Планировщик, агенты и авторские бенчмарки в стенде не запускаются. Предшественник один и тот же во всех вариантах, поэтому его запуск не входит в число вычислительных узлов. Измеряются счётчики работы. Время ожидания, CPU, память и ввод-вывод реальной задачи остаются за пределами стенда.
