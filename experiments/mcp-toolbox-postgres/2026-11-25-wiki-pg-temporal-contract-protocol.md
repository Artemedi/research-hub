# MCP Toolbox и Wiki_PG — время наблюдения настройки PostgreSQL

1. Использовать PostgreSQL 15.20 и 18.3 из образов с закреплёнными идентификаторами, Wiki_PG `d55721bb99bff25fae352341cfd630c048693d6b` и [официальный Toolbox v1.15.0](https://storage.googleapis.com/mcp-toolbox-for-databases/v1.15.0/linux/amd64/toolbox). Перед запуском сверить SHA‑256 бинарника с хешем прежнего лабораторного прогона.
2. Для каждой версии создать одноразовую базу без внешней сети и публикации порта. Разрешить Toolbox ровно один инструмент из [прежней лабораторной конфигурации](../2026-11-04-mcp-toolbox-wikipg-tools.yaml). Независимые искусственные снимки Wiki_PG имеют 4096 и 8192 kB в две заданные даты.
3. Последовательно установить три значения `work_mem` для лабораторной роли: 4096, 8192 и 16384 kB. На каждом этапе открыть новую сессию Toolbox, сравнить её ответ с прямым чтением PostgreSQL под той же ролью, проверить обе фиксированные даты, последний снимок и дату без снимка через Wiki_PG MCP.
4. Требовать совпадения значения и единицы с эталоном, точной даты захвата и идентификатора файла для существующих снимков, явного `no_snapshot` для отсутствующей даты. Повторить со свежими базами и сверить итоговый JSON.

[Скрипт](wiki-pg-temporal-contract.py) принимает пути к закреплённому checkout Wiki_PG и бинарнику. Для запуска нужны Python с MCP SDK, Docker и два указанных локальных образа. Учитываются только значения `work_mem`. Нагрузка, задержка и эксплуатационные права вне этого прогона.
