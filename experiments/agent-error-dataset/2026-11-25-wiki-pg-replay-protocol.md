# Agent Error Dataset — парное воспроизведение запроса Wiki_PG

Порядок зафиксирован до серии прогонов.

1. Использовать чистый Wiki_PG на `d55721bb99bff25fae352341cfd630c048693d6b`. Штатный сборщик SQLite строит отдельный временный каталог из искусственных JSON. В нём один хост с двумя портами и другой хост с одинаковым именем в двух регионах. Отдельные версии в каждой группе позволяют обнаружить неверный выбор.
2. Зарегистрировать 24 сценария, по четыре варианта каждого семейства. Два семейства допускают одну коррекцию: ошибка требует порт, явно указанный в задаче, или ошибка требует регион, явно указанный в задаче. Четыре контрольных семейства оставляют выбор открытым: порта нет в задаче, регион отсутствует, два порта противоречат друг другу, подсказка относится к другому действию.
3. Зафиксировать первоначальный запрос, точный текст ошибки и ID действия. Из одной публикации SQLite выполнить исходный запрос ещё раз. Для второй ветки изменить только отсутствующий селектор, если его единственное значение явно записано для этого действия и совпадает с типом ошибки. На остальных случаях воздержаться. Все вызовы выполняются через штатный `SystemQueries.state` на чтение. Хеш базы сверяется до и после.
4. Сверить исправленный ответ с исходным JSON по хосту, региону, порту, наблюдаемой версии и SHA-256. На каждом из восьми исправляемых случаев прогнать отрицательный контроль с другим существующим портом или регионом. Он обязан вернуть ответ, который отвергает независимый оракул.
5. Сохранить число восстановлений, число воздержаний и результаты контролей. Критерий — исходный повтор не восстанавливает ни одного вызова, восемь одношаговых коррекций совпадают с оракулом, остальные 16 не исполняются, восемь неверных селекторов обнаруживаются. Повтор полной серии должен дать одинаковую сводку.

После серии на Python API добавлен транспортный контроль на том же контракте. Повторить все вызовы через штатный инструмент `query_system_state` в отдельном read-only MCP stdio. Для ошибок зафиксировать общий код `invalid_request`, тот же конкретный текст и совпадение ID ответа с вызовом. Для успехов проверить те же поля и источник. Обе серии читают одну публикацию SQLite.

Это перенос парного метода из [Agent Error Dataset v2, §3.2](https://arxiv.org/html/2609.40111v2#S3.SS2) в конкретный API проекта. Лаборатория не измеряет естественную частоту ошибок или поиск сбоя агентом. Один небольшой файл SQLite на прогон и три искусственных JSON хранятся временно.
