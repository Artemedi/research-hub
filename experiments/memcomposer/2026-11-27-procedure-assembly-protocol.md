# MemComposer × DSH Runtime — отбор и порядок примеров

1. Подготовить чистый checkout DSH Runtime на ревизии `b6a1635b1200071754e2871b9d9453368e6daf23` и Node.js 24.11.1. Скрипт сверяет хеш исходника сборки контекста.

   ```text
   node --experimental-transform-types experiments/memcomposer/procedure-assembly.mjs <pinned-dsh-checkout>
   ```

2. В каждом повторе сформировать 48 задач. Для 36 задать процедуры из одного, двух или трёх шагов. Для 12 оставить только чужие или устаревшие примеры. Добавить к каждому списку кандидатов такие отвлекающие примеры. У половины многошаговых задач кандидаты с нужными шагами идут в обратном порядке.
3. Подать один и тот же список кандидатов в четыре ветки. Контроль передаёт пустой список. Фиксированный отбор берёт первые три записи. Третья ветка оставляет примеры нужного семейства и версии в исходном порядке. Четвёртая передаёт тот же состав в порядке зависимостей.
4. Передавать выбранные записи через штатную сборку динамического контекста DSH. Проверить состав и порядок по именованным секциям, побайтный размер снимка в UTF-8, неизменность статического системного текста и очистку секций после опыта.
5. Для каждой ветки пропустить полученные примеры через один детерминированный исполнитель. Он проходит список один раз и принимает следующий шаг, когда выполнен предыдущий. Сверить итоговое состояние с эталоном. Отдельно считать пустой контекст при отсутствии подходящего примера. Повторить трижды с новыми входами.
