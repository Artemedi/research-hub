# Yahont CE и Wiki_PG — различимость путей источников

1. Использовать Wiki_PG `d55721bb99bff25fae352341cfd630c048693d6b` и [функцию нормализации Yahont CE из закреплённого коммита](https://github.com/pipedude/yahont-ce/blob/367b48da9de2d296f905aca4bf0eb384043bf643/backend/onyx/document_index/opensearch/string_filtering.py). Скачать исходник функции в отдельный файл и сверить SHA‑256 перед локальным запуском.
2. Создать десять пар похожих относительных путей. Добавить отдельный путь для проверки, что функция различает входы, сохраняемые её правилами. В Wiki_PG обе записи каждой пары начинают с одинакового содержимого.
3. Проверить общий и ограниченный путём поиск. Сопоставить выданные пути, SHA‑256 и текст с фактическими временными файлами. Затем изменить первый файл и удалить второй. Ожидать новый идентификатор только у изменённого файла и отсутствие удалённого файла в выдаче.
4. Повторить весь тест с новыми временными каталогами и сравнить результаты.

[Скрипт](wiki-pg-source-identity.py) принимает путь к чистому checkout Wiki_PG и отдельному проверенному файлу Python Yahont CE. Нужны Python, PyYAML и SQLite FTS5. Полный сервис Yahont, OpenSearch, права доступа и реальные документы не участвуют.
