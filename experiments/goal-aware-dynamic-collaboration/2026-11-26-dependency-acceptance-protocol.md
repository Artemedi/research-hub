# GAD × DSH Runtime — проверка результата перед запуском зависимой задачи

1. Использовать чистый checkout DSH Runtime на `b6a1635b1200071754e2871b9d9453368e6daf23`. Запустить в Node.js 24:

   ```text
   node --experimental-transform-types experiments/goal-aware-dynamic-collaboration/dependency-acceptance.mjs <pinned-dsh-checkout>
   ```

2. Для каждого из восьми наборов чисел создать две родительские задачи, одну зависимую и одну постороннюю. Использовать штатные операции создания, взятия в работу, завершения и повторного открытия. Хранить записи в подставном журнале в памяти и проверять последовательность версий. Поиск участника для переназначения исключён из стенда.
3. Прогнать шесть сценариев с одинаковыми входами для обеих веток. Штатная ветка пытается взять задачу по готовности доски. Ветка проверки дополнительно пересчитывает результат каждого родителя и сверяет ID задачи и версию записи. Для устаревшего результата переоткрыть и повторно завершить родителя, оставив старую версию результата.
4. Проверить, что валидные результаты допускают запуск. Отдельно проверить отсутствующий результат, неверное значение, верный итог от чужой задачи, старую версию и незавершённого родителя. В каждом заблокированном случае предоставить исправленный результат и убедиться, что дочернюю задачу теперь можно взять. Повторить всю матрицу трижды и сверить счётчики.

Стенд проверяет последовательные переходы через публичные методы модуля доски. Состояние задачи, вычисление суммы и журнал используют память одного процесса. Цена хранения, задержка записи на диск, поведение при параллельных запусках и стоимость модельной проверки вне этого прогона.
