## Протокол v0 (2026-11-14, решения совета и владельца)

Источник: три советника (Opus 5.5, Fable 5.2, Gemini 4 Carbon), ответы получены по одному запросу; цифры ниже — **рекомендации советников, не измерения**. Владелец утвердил запись протокола, шаг A′ и потолок стоимости экстрактора **$20** (весь корпус). Gemini ответил вне API, по тексту, который передал владелец. Порядок шагов изменён против таблицы выше.

### Порядок
1. **A′** — перезапуск UMAP+HDBSCAN с 3–5 сидами; нестабильные кластеры — ранний no-go. Статус и блокер — см. ниже.
2. **B1** — заморозить корпус, запросы DBA (≥30) и пороги go/no-go до любой разметки; убедиться, что в test ≥50 релевантных статей (иначе расширить cs.DB до оплаты извлечения).
3. Извлечь ACC на dev, подобрать τ на dev (5 сидов, отчёт о разбросе), заморозить.
4. **B2** — слепой пул top-K test от четырёх систем (BM25, текущий shortlist, SPECTER2 k-NN по целым аннотациям без ACC, ACC+τ) плюс небольшая случайная выборка вне пула для оценки recall; разметка вслепую.
5. **C** — один прогон на test.

### Решения
- **Корпус:** OpenAlex (CC0), 2021–2025, 2–3 тыс. записей: ~40% базы данных, ~30% смежные системы, ~30% дальний контроль; отбор по рубрике, не по ключевым словам. Split по `sha256(id)` на fit/dev/test; UMAP/HDBSCAN обучать только на fit. Манифест (ID, дата снимка, SHA-256) коммитится до извлечения.
- **Разметка:** владелец размечает вслепую (без вывода системы и вердиктов LLM) + судья другого семейства, чем экстрактор + повтор 30% через ≥7 дней. Отчитываемся только об intra-rater κ и κ «человек–модель»; термин «inter-rater» не используем (второго человека нет).
- **Экстрактор:** эталон — модель и промпт авторов, temperature 0, версия закреплена, выводы кэшируются. Потолок стоимости — $20 на корпус. Дешёвая модель допустима, если на dev: recall человеческих ACC ≥ 0,85, число ACC на статью в пределах ±15%, пересечение top-20 ≥ 0,7.
- **Порог τ:** один скаляр — косинус до ближайшего центроида в пространстве `assign.py` (сверить по коду); новый алгоритм не вводится. Способ подбора (перцентиль сходства членов кластеров на dev либо сетка по F0.5) выбрать и записать до запуска, затем не менять. Ниже τ — `UNASSIGNED`: в тренды не входит, идёт в видимую очередь outliers. τ=0 — контроль авторского поведения.
- **Go/no-go (все условия сразу, иначе остаётся BM25):** recall@20 ≥ BM25 + 10 п.п. с нижней границей парного bootstrap-CI > 0; precision@10 ≥ BM25 − 5 п.п.; forced assignment на контролях ≤ 10%; outlier rescue ≥ 30% релевантных noise-статей; Спирмен трендов между сидами ≥ 0,8; стоимость ≤ $20 на корпус; intra-rater κ ≥ 0,6, иначе пилот не засчитывается. Пороги фиксируются на B1.
- **Недействительно, если:** τ или промпт подобраны на test; разметка со знанием источника системы; судья из семейства экстрактора; qrels из пула одной системы; корпус отобран ключевыми словами; аннотации, вероятно, входили в обучающие данные экстрактора и это не учтено.
- **Слабое место:** релевантность держится на одном человеке, релевантных статей по PostgreSQL в test мало; при <50 позитивов или <30 запросов доверительные интервалы шире эффекта.

### Шаг A′: статус
Опубликованный репозиторий автора (`6c643d6`) не содержит текстов ACC и эмбеддингов: `acc_clusters_emnlp.csv` хранит только `claim_id, paper_id, year, cluster, cluster_name`; тексты есть лишь в листах человеческой валидации. Поэтому перезапуск UMAP+HDBSCAN «на данных авторов» требует заново получить аннотации EMNLP (ACL Anthology) и извлечь ACC, то есть это уже шаг B-класса, а не дешёвая проверка. **Решение (по поручению владельца «решает совет»): вариант б.** Рассуждение: A′ требовался Fable как ранний фильтр, но он стоил бы нового извлечения ACC и скачивания SPECTER2; Opus и Gemini его не требовали. A′ объединён с B1: стабильность кластеров (3–5 сидов, Спирмен трендов ≥ 0,8) проверяется на нашем fit-сплите перед платным извлечением на dev/test. Нестабильность остаётся основанием для no-go. Скачивания (SPECTER2, пакеты) — только после отдельного разрешения владельца.

## Метрики шага C

precision@K и recall@K проектного shortlist, missed relevant studies, forced assignment, outlier rescue, inter-rater reliability, latency, токены и стоимость, CPU/RAM/IO, стабильность трендов.

Порог `min_similarity` — доработка к авторскому `src/acc/assign.py` (там argmax cosine без abstention). Значение порога и формула не заданы исследованием: подбирать на отдельном dev-split, не на test; ниже порога — `UNASSIGNED` / `NEEDS_REVIEW`. Не выдумывать алгоритм там, где автор его не дал.

## Критерии решения

- **Go:** измеренный прирост recall при заранее заявленном допустимом precision и стоимости. Пороги фиксировать до запуска шага C.
- **No-go:** неверные назначения, неприемлемый рост false positives либо отсутствие положительного эффекта.
