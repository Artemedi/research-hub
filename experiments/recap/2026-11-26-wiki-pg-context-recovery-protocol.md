# ReCAP — восстановление раннего контекста Wiki_PG

1. Использовать чистый Wiki_PG `d55721bb99bff25fae352341cfd630c048693d6b`. Для шести наборов создать ранний и поздний отчёты одного инстанса и отчёт другого порта. Штатный лексический поиск предоставляет пути, хеши и диапазоны строк.
2. Сравнить три способа собрать контекст. Первый сохраняет только свежий фрагмент. Второй использует лексический поиск. Третий дополнительно читает ранний фрагмент по связи от найденного свежего фрагмента. Для всех действует одинаковый лимит 960 байт сериализованного результата.
3. Проверить пять вариантов. Это восстановление по связи, прямой запрос с ранним маркером, отсутствие связи, связь на другой порт и изменение байтов раннего источника. Для возвращённого фрагмента требуется совпадение с эталоном. Связь хранит координаты и SHA‑256, а текст читается из исходного файла.
4. После каждого случая повторить штатный поиск и сверить хеши источников. Два прогона по 30 случаев должны совпасть.

[Скрипт](wiki-pg-context-recovery.py) принимает путь к закреплённому checkout. Нужны Python, PyYAML и SQLite FTS5. Связи заданы вручную. Лимит измеряется в байтах, токенизатор не используется.
