# BIRD-RL — сравнение изоляции в PostgreSQL

Используйте Docker в Linux с cgroups v2 и Python 3.11+. Нужен локальный образ PostgreSQL 18.7, закреплённый по SHA-256 в скрипте. Стенд не загружает образ. Контейнеры используют отдельный временный файловый раздел в памяти, локальный сокет PostgreSQL, 2 CPU и 512 МиБ памяти. Сеть и общие каталоги отсутствуют.

```text
python3 -I -B experiments/bird-rl/postgres-isolation.py
```

1. Сравнить новый экземпляр на каждый прогон, клон чистой базы через `CREATE DATABASE … TEMPLATE … STRATEGY WAL_LOG` и откат в одной повторно используемой базе. Каждый вариант выполняет три последовательности с одной и той же схемой, 20 000 строк и последовательностью.
2. В каждой последовательности получить значение `nextval`, изменить 10, 20 или 30 строк, создать и заполнить тестовую таблицу. Перед началом, перед завершением транзакции и из нового соединения сверить количество и хеш строк, состояние последовательности и наличие таблицы. Эталон вычисляется независимо в Python.
3. Записать длительность подготовки и работы, разницу позиций WAL и счётчиков `pg_stat_io`, размер базы, занятые блоки каталога данных и потребление памяти контейнером в момент измерения. Время подготовки нового экземпляра включает инициализацию. Его счётчики WAL начинаются после готовности сервера. Время клона измерено после подготовки общего шаблона. У уже открытой базы отката отдельного шага подготовки нет.
4. Повторить стенд с новыми контейнерами. Сравнить состояния и значения последовательности. Замеры времени и ресурсов хранить отдельно для обоих запусков.

Оба запуска использовали файловый раздел в памяти. Счётчики относятся к операциям PostgreSQL. Физические IOPS, пик памяти, конкуренция и подключение внешних клиентов не измерялись. Контейнеры удаляются после прогона.
