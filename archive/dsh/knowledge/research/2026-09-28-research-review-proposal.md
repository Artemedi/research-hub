## Accepted research sequencing (not implementation authorization)

1. **P1 reliability and security inventory:** exactly-once external-effects audit and self-replicating prompt-injection threat/fixture design. These are distinct: one concerns side-effect concurrency and idempotency; the other concerns untrusted text flow and authorization.
2. **P2 measurement-first efficiency:** baseline tokens/caching/tool discoverability; evaluate guarded history compaction with immutable evidence; no plugin until DSH-native metrics justify it.
3. **P2 KVSET:** keep using the already qualified local isolated paper-backed tool, not DSH production. Acquire known tokenizer/trace/cache-policy information before any usefulness claim.

## Scope, known blockers and non-promotion rule

- Full original paper text is available for LIMBO, StateComp and KVSET and was inspected for methods/results/limitations; Cursor is a complete engineering blog and OpenAI a complete public disclosure, **not peer-reviewed papers**. No full reproduction of the authors' original research results was undertaken here.
- The control-plane status at original review was E000874; at operator acceptance it is E000875, with **general AF-003 CLOSED within the F1-defined scope; production HOLD**. This file is not current gate authority; always consult `docs/iq-f1-orchestration/STATE.md`.
- For exactly-once, exact current DSH code paths and which tool providers already implement idempotency have **not yet been audited**. Candidate tests, not confirmed defects.
- For StateComp, a successful task-level token saving does not make automatic source-history replacement safe. DSH must preserve durable event provenance and maintain protected information boundaries.
- For Cursor, no production DSH prompt-caching usage/cost baseline or eligible capability discovery dataset has been measured. Tool presentation and tool authorization are distinct.
- For OpenAI, no real-world worm outbreak or DSH-specific vulnerability has been observed by the study.
- For KVSET, local source-bound scientific-tool qualification demonstrates a tool works, **not** an ROI or memory provision estimate for DSH or remote APIs.
