**Verified:** ProllyTree VersionedKvStore with actual branch/commit/merge/diff/get/blame, semantic path taxonomy and LLM-driven retrieval, code assistants and Hermes plugins. Cryptographic proof supports integrity relative to a Merkle commitment, **not encryption, RBAC or an externally trusted immutable root**. `_encode_value` persists plain JSON/UTF8; `forget` logically removes latest item but Git history/remote replicas may preserve old secrets. A second ProllyTree vector search/embedding path is present, so the broad marketing assertion that it replaces vector search is false. In one verification path `if expected_value:` omits explicit checking for `0`/`False`/`""`.

**Performance / operations:** Source `all_keys()` replays committed snapshot because native `list_keys()` is capped at 1024; full snapshot cache has memory/IO implications, and `gc.auto=0; gc.pruneExpire=never` mitigates deletion of dangling ProllyTree Git objects but leaves explicit prune hazards and retention costs. Docs themselves say `O(log n)` is a shape claim and `summarize` scans O(k); LLM-tiered search is ~1–2 seconds. Claims `0.1–1ms` and `1M memories` are **AUTHOR_CLAIMED / NOT_REPRODUCED**; LoCoMo harness uses model calls and a judge, not a verified source-included paired result. Default auto-capture/LLM route creates external data exposure possibility; cloud sync optional but must remain off for a local pilot.
